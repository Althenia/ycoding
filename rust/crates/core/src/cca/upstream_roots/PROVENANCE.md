# Node 26.4.0 packaging-reference roots

## Applicability and material

The bundled material is the 120 PEM string values, in source order, from official Node 26.4.0 `src/node_root_certs.h`. The source archive SHA-256 is `9eceb3621024069d91035b5471d2ebe86aa04d22dbeba72a782eaf36ff9183ac`; the header SHA-256 is `d4ed10ddcd8cb9e65a3a2c70154f9e55640cd2ec56bbe6053bb9192e32e69e8e`. The official archive is `https://nodejs.org/dist/v26.4.0/node-v26.4.0.tar.xz`. Authentication is inherited from the validated official release signature and SHA-256 manifest, not inferred from the certificate contents.

`packages/cli/script/build-node.ts` at locally available commit `ff1e006225fe461c627b90cd2bf6c36cc4594186` selects Node 26.4.0. This material applies to that packaging reference. It does not establish the root snapshot used by Bun, development executions, shared-OpenSSL builds, or another Node release. Cached webpki-root-certs 1.0.9 is not this snapshot: 121 versus 120 certificates, 116 shared DER values, four Node-only and five cached-only values; neither order nor set matches. This leaf has no webpki/native-certs/default-client-root constructor.

`transform.py <authenticated-header> rust` emits `bundled.rs`; `transform.py <authenticated-header> digests` emits `tests/digests.rs`. The transformation validates the header digest, concatenates C string literals with Python literal decoding, and preserves each PEM value and array order. DER digest derivation only decodes static public base64 data. It does not parse trust, issue certificates, create keys, or emit standalone certificate artifacts. There are 120 unique full-DER SHA-256 values. The digest oracle was separately compared with the authenticated-source audit's ordered digest list.

## Explicit-root API and lifetime

Keep one `RequiredRootProvider` for the process system-root cache. `load` requires a system collection closure; it cannot silently instantiate native, OpenSSL-default, mutable default-client, or webpki roots. The closure can call `platform::collect_current_system` with an explicit `SystemPlan`. A missing or wrong-target source is an error, not a successful empty root policy. Native store/query failures that Node treats as an empty collection remain empty observations; unsupported Rust certificate representations are errors.

Capture `StartupCaSnapshot` from the owner-supplied startup environment map, before child trust mutation. It retains only the eleven canonical CCA keys, in canonical key order. Its first `load` reads each distinct nonempty raw path once, excluding paths identified by the authority owner's managed-path predicate. `read_startup_ca_file` follows stat semantics, requires a regular file of at most 1 MiB, and returns no additions on file/stat/read errors. Snapshot values and first-load certificate additions are retained independently of subsequent child environment changes. Node's separately captured `NODE_EXTRA_CA_CERTS` default-client layer is not added a second time.

The ordered union is system, this bundled snapshot, then startup-file additions. Deduplication uses the canonical normalized PEM text: ECMAScript trim, CRLF-to-LF and one trailing LF. It does not change certificate line wrapping or substitute DER-based deduplication. The normalized generated authority PEM is excluded. `UpstreamRoots::into_parts()` returns `(rustls::RootCertStore, Vec<String>)`, with both built from that upstream union. The child authority is not inserted into either result. The authority owner can append its CA to a separate child bundle. Pass the returned ordered PEM list to `mitm_ca::upstream_openssl_connector`; do not introduce another verifier or default-store path.

Every selected PEM must decode and its X509 fields must be extractable. A single raw DER field path constructs the existing public rustls `TrustAnchor` from subject, SPKI and NameConstraints contents and inserts it into the same explicit `RootCertStore`. It does not add a verifier, drop name constraints, or use a high-level parser as a fallback. Conversion errors retain the union index and prevent a successful reduced-root result. `RootError::RequiredSystemSource`, `RequiredOpenSslDefaults`, `NativeCertificate`, `InvalidCertificate`, `Pem`, `PemLabel` and `RootStore` distinguish required inputs, malformed X509 and unsupported representations. Windows/macOS skip structurally malformed native certificates; Unix PEM loading retains its prefix before a malformed certificate, as Node does. Unsupported representations return errors, not an incomplete success. A source collection error is retained by the system cache. The authority owner retains final authority/bundle caching and managed-path resolution; this leaf performs no file writes.

## Platform source algorithms

Node `src/crypto/crypto_context.cc:340–927` and `lib/tls.js:121–206` define the explicit system selector and first-load cache. macOS and Windows do not consume OpenSSL path overrides on this selector.

Windows uses ROOT at local-machine, local-machine-group-policy, local-machine-enterprise, current-user and current-user-group-policy; CA at the same five; TrustedPeople at the three machine locations. Each open is existing-only and read-only. `CertGetEnhancedKeyUsage` performs the native property/extension intersection. Both property reads must succeed. Zero OIDs allow all purposes only with `CRYPT_E_NOT_FOUND`; otherwise zero OIDs reject. Nonempty OIDs require server-auth or any-EKU. Missing stores and rejected properties do not contribute roots. Contexts and stores have explicit cleanup, including early errors. Location bit values come from approved cached windows-sys 0.61.2 constants and its location-ID/shift definitions.

macOS constructs the same SecItemCopyMatching certificate/all/ref query, not an aggregate-anchor helper. The collector reads certificate data, evaluates user then admin settings, skips application- and policy-string-scoped entries, matches policy identity to Apple SSL, defaults an absent result to TrustRoot, and retains the first decisive setting. An empty settings array differs from no array. Self-issued certificates accept TrustRoot or TrustAsRoot; other certificates accept only TrustAsRoot. A missing settings array triggers one native SSL-client/no-hostname trust evaluation; a successful evaluation returns before admin settings, matching Node's control flow. Duplicates and expired entries are excluded after trust selection. Expiration uses whole-second `notAfter <= now`, matching OpenSSL's comparison convention. Native settings read errors skip that domain.

Unix resolves the compiled file-environment name and directory-environment name independently; each absent value retains its own compiled default, and explicit empty values suppress only that input. It loads the file before one directory, does not split a colon-delimited directory into guessed search paths, follows regular-file stat semantics, and sorts directory names by raw byte comparison as libuv does. PEM reading retains the successfully decoded prefix on malformed PEM and accepts the historical X509 CERTIFICATE label.

`CompiledOpenSslDefaults::node_26_4_bundled_linux_build` is sourced from the authenticated archive: `deps/openssl/openssl_common.gypi:62–69` defines `OPENSSLDIR="/etc/ssl"` for the Linux/other bundled build branch; `include/internal/common.h:83–98` derives `cert.pem`, `certs`, `SSL_CERT_FILE`, and `SSL_CERT_DIR`; `crypto/x509/x509_def.c` returns those macros. These are not guessed host paths. The archive lacks `config.gypi`; it does not prove the configuration of an independently supplied binary or shared OpenSSL library. For those builds require their exact compiled defaults rather than selecting this constructor automatically.

## Native ABI and ownership evidence

The macOS target source uses the separately proposed exact cached edges core-foundation-sys 0.8.7 (`default-features=false`, `link`) and security-framework-sys 2.17.0 (`default-features=false`), with existing libc 0.2.190. Manifest/lock integration belongs to its separate owner. Cached archive SHA-256 values are respectively `773648b94d0e5d620f64f280777445740e61fe701025087ec8b57f45c791888b`, `6ce2691df843ecc5d231c0b14ece2acc3efb62c0a398c7e1d875f3983ce020e3`, and `ce5d3ddc6d3fa000eb1536d85e147bfe31aacaba692ed6a876f95cb7c855be78`.

Installed public macOS 26.5 SDK `Security.framework/Headers/SecPolicy.h` declares nullable `CFDictionaryRef SecPolicyCopyProperties(SecPolicyRef)` and exported `const CFStringRef kSecPolicyOid`, available since macOS 10.7. The local C-ABI bridge uses the cached opaque-pointer aliases and Security framework linkage. A Copy result has +1 ownership and is released once after the borrowed OID comparison; NULL is unspecified policy. `SecTrustSettings.h:181–186` defines setting keys as exact CFSTR macros, so the source creates the corresponding CF strings instead of guessing exported symbols.

Each native Create/Copy result is wrapped in one `OwnedCf`; its Drop releases exactly once. Query arrays/dictionaries retain CF entries through kCFType callbacks. Values returned by GetValue/GetValueAtIndex are borrowed only while their owners remain alive. Certificate data is read while its Copy owner remains alive. Trust-policy creation, settings arrays, evaluated trusts and policy dictionaries are cleaned on every return. Type checks guard the policy/result/settings casts. Windows usage buffers have pointer alignment through usize storage; successful property output remains alive through OID reads. Enumeration consumes its previous certificate context, and the cursor guard frees an outstanding context on early exit.

## Representation and verification boundary

No Rust, Cargo, Node, formatter, compiler, test, build, lint, certificate generation, trust evaluation, environment read, keychain query, Windows store access, or trust-setting mutation was executed for this source slice. All executable cases are unrun, including all target-specific source and linkage checks. Static source/material comparisons are not executable correctness or platform parity evidence.

The cached x509-cert 0.2.5 Raw profile disables serial-number checks, not typed field decoding. Its der 0.7.10 dependency has a 1970 DateTime lower bound and rejects UniversalString tag 0x1c. Those are reachable restrictions: OpenSSL's X509 field template accepts ASN1_TIME and X509_NAME; its time algorithm supports the 1950–2049 UTCTime pivot and four-digit GeneralizedTime, and its name canonicalization explicitly includes UniversalString. Native macOS certificate data is DER, with no 1970-only or narrower DirectoryString contract. An old notBefore date must not remove an otherwise trusted unexpired certificate.

The leaf therefore does not use x509-cert Raw for root collection. Its raw DER path retains time octets and all seven OpenSSL-canonicalized string types. It applies the authenticated UTF-8 conversion, ASCII-only case/whitespace canonicalization and SET ordering for self-issued comparison, not structural name equality. Signed chrono calendar values cover pre-1970 dates; invalid comparison-time syntax means not expired, matching X509_cmp_time's error result. It accepts explicit versions and unique-ID fields from the authenticated X509_CINF template. Direct standard TrustAnchor construction also avoids rustls-webpki's v3/v1-only certificate parser, unique-ID rejection, and inner/outer signature-algorithm equality check when extracting an already trusted anchor. NameConstraints are retained as the sequence contents expected by the same rustls verifier. Synthetic unrun substructure examples cover these boundaries, and an unrun bundled-root case compares all extracted components against the existing rustls anchor extractor.

These source restrictions are distinct from unrun verification. OpenSSL additionally accepts noncanonical BER indefinite/overlong lengths, constructed string encodings and normalized bit-string padding; those forms are not implemented by the DER reader and cause explicit NativeCertificate errors. Duplicate or unrepresentable NameConstraints also require unresolved OpenSSL policy handling rather than discarded constraints. Complete malformed-certificate acceptance and skip behavior is not established equivalent to Node. These are known source compatibility gaps, not merely missing platform test evidence, and prevent a complete arbitrary-system-root collector claim. Separately, every Rust test and all target ABI/linkage/native behavior verification remain unrun. Do not silently replace a failed system collection with a smaller root policy.
