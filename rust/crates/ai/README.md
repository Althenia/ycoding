# ycoding-ai

---

Provider-native request lowering and incremental response settlement. This crate depends on `ycoding-schema` and the approved HTTP, WebSocket, Tokio, JSON, error, and tracing libraries. It does not own Sessions, permissions, provider discovery, configuration, credential storage, quota refresh, or durable events.

## Prerequisites

Use Rust 1.98 or newer and Cargo from the repository's Rust workspace. The crate is unpublished and consumed as a workspace dependency; no separate package installation is required. The workspace license is AGPL-3.0-only.

<a id="inputs-and-execution"></a>

## Inputs and execution

Supply a resolved `llm::Model`, `Request`, and `auth::Credential` from the upstream model/provider owner. Model and provider identifiers use Schema domain types. Credential identifiers remain upstream handles; secrets have redacted `Debug` implementations. No route reads ambient configuration or environment variables.

Construct an Anthropic route with `Route::anthropic_provider` or `Route::anthropic_compatible`. Select API-key, bearer-token, or explicit composed authentication through `ProviderAuth`. Override the endpoint, route defaults, model defaults, and request options directly. Resolution applies route defaults, model defaults, then request overrides. Protocol metadata remains in the `anthropic` namespace for both direct and compatible providers.

`Route::prepare` applies cache policy and lowers the protocol body. Its `body` is the protocol-only body; `wire_body` and `encoded_body` include permitted transport overlays. Protocol-owned body fields cannot be overlaid. Endpoint query overrides preserve unrelated query parameters; authentication runs after headers and body assembly. JSON content type is authoritative.

Inject a configured `reqwest::Client` into `Executor`. The optional `Executor::http_client` constructor disables ambient proxies and automatic redirects. HTTP requests use fresh connections. `Executor::stream` returns an owned `EventStream`; pull events with `next`, or use `generate` to assemble the ordered assistant message. Drop the stream to interrupt its transport. `generate_object` forces a named tool and returns the JSON input; the caller validates a dynamic output schema.

The route executor reports attempt `1`. Muse's OAuth transport remints a rejected inference key once on HTTP 401; other routes perform exactly one physical attempt. The executor never reconnects after an SSE `retry:` directive or converts a WebSocket continuation rejection into an HTTP request. The Session runner owns bounded retries, backoff, interruption during backoff, and exactly one durable terminal settlement per started logical Step. Use the typed provider-error reason, context-overflow classification, retry-after value, and rate-limit scopes to apply that policy upstream.

## Muse (Meta) subscription adapter

`muse::route(Connection)` uses OpenAI Responses lowering and the `openai` metadata namespace. Direct keys bypass minting. OAuth connections bind lazy key minting to stored credential ID and generation, coalesce concurrent mints, and retry inference once after a 401 with a newly minted key. Expired or rejected account tokens require `/connect`; no refresh grant is sent. Mint and discovery requests have a ten-second deadline and disable redirects and automatic retries. A Runtime owns the process-session UUID and redacted key cache.

Requests use the minted base URL's `/responses` endpoint, `x-client-id: tbh:exec`, and equal `x-tbh-session-id` and `x-meta-ai-gateway-session-id` headers. Defaults use `store: false` and encrypted reasoning inclusion. Reasoning remains reasoning, and encrypted state replays in the complete input rather than through `previous_response_id`.

The stream drains trailing `response.subscription_usage` events after response completion, including an unterminated final data line. Invalid quota events are ignored with a payload-free warning. Only normalized Schema observations are retained, keyed by the Core-supplied account identity; credentials, emails, subscription tiers and raw quota payloads are excluded. `normalize_usage` preserves absent metrics and reported zero. Core owns usage reads and profile presentation; quota reads never mint or fetch.

<a id="openai-family"></a>

## OpenAI family

<a id="usage"></a>

### Usage

Construct requests with a credential already resolved by the upstream owner:

```rust
use ycoding_ai::{
    auth::{Auth, Credential},
    llm::{Message, Request},
    providers::{self, Config, OpenAIConfig, Transport},
};

fn request(credential: Credential) -> Request {
    let model = providers::openai("gpt-5.6", OpenAIConfig {
        common: Config::new(Auth::bearer(credential)),
        organization: None,
        project: None,
        transport: Transport::Http,
    });
    let mut request = Request::new(model);
    request.messages.push(Message::user("Hello."));
    request
}
```

Use `Transport::WebSocket` for the native Responses WebSocket protocol. `Executor::generate` consumes completion without requiring the server to close the retained connection. HTTP overlays reach the WebSocket `response.create` message; canonical replay and delta lowering use the Responses protocol's representation.

## Hosted provider adapters

These constructors produce native Rust `llm::Model` values. They do not admit catalog packages, select accounts, execute JavaScript, load npm, or resolve Core integration snapshots. Core supplies the selected API model ID, resolved credentials, and typed settings; credential metadata is not an HTTP body overlay.

<a id="hosted-usage"></a>

### Usage

`providers::Config` supplies `auth`, optional `base_url`, query parameters, and `llm::Defaults`. Use `Auth::bearer(Credential)` for API-key vendors. Put per-model/call provider options in their named namespace under `Defaults.provider_options` or `Request.provider_options`, not in `http.body`. HTTP request headers retain request-over-default precedence. Shared transport owns HTTP error classification, credential redaction, cancellation, and SSE framing.

Pass environment values through the constructors' explicit environment maps or resolve credentials upstream. Constructors do not read or mutate the process environment. GitLab and SAP async constructors exchange credentials before creating a model; returned models hold the access token. Core owns refresh, shared account-generation caches, reconstruction at the credential lifetime boundary, and request retry policy. Exchange failures expose status and a generic message, never credential-bearing response bodies.

<a id="hosted-supported-paths"></a>

### Supported and rejected paths

- Alibaba uses DashScope-compatible Chat with thinking fields, cache-controlled blocks, assistant reasoning-as-text replay, and cache-creation usage normalization. Mistral uses its random-seed/options names, thinking arrays, complete tool-call chunks, and document URLs. Perplexity retains citations and normalized search usage/image/cost fields in finish metadata. Venice retains known cost and web-search citation fields. Vercel uses the v0 endpoint, distinct from Gateway.
- Cohere uses `/v2/chat`, its `p`/`k` fields, uppercase tool choices, typed message/content/tool stream events, and `usage.tokens` rather than billed units. Truncated streams and incomplete tool calls fail. Cohere source/citation events are accepted but do not produce a dedicated source event.
- Gateway sends the v3 language-model prompt/options body to `/language-model`, with protocol/model/specification/streaming headers. It forwards part provider metadata and Anthropic/Alibaba cache hints, and maps text, reasoning, tool-input/call, final provider-executed tool results, finish, usage, and source metadata. Preliminary result replacement, approval requests, file-output events, and unknown v3 event families are rejected.
- Cloudflare unified POSTs an array of `{provider, endpoint, headers, query}` to the account/gateway URL, distinct from the low-level `/compat` route. The selected key appears in the protocol-required nested Authorization field and the outer sensitive gateway auth header. Do not log prepared or encoded provider bodies.
- GitLab maps supported Duo agentic IDs to native Anthropic/OpenAI proxy model IDs and exchanges `/api/v4/ai/third_party_agents/direct_access` before inference. Duo Workflow Service models are rejected rather than sent to an agentic proxy. Static returned models do not reexchange tokens or retry token errors.
- SAP accepts client-secret service keys and explicit-deployment orchestration v2 requests. Certificate-bound service keys, BTP bound-service discovery, deployment auto-selection, Foundation Models transport, and prompt-template references are unsupported.
- `snowflake_cortex::conversation_complete(status, body)` recognizes the JSON message/error-string 400 stop condition. HTTP transport converts this condition to an empty assistant stop only for the Cortex protocol and a complete, untruncated JSON diagnostic body. Bodies exceeding the 16,384 UTF-16-unit diagnostic limit, other routes/statuses, malformed JSON, and unrelated errors remain failures. Empty SSE role values parse through the Chat parser.
- Bedrock credentials/signers and Vertex ADC refresh remain Core-owned. Constructors do not perform Core package admission, catalog transformations, or runtime credential-lifecycle management.

## GitHub Copilot bundled adapter

`github_copilot::model` and `providers::github_copilot_sdk` construct the bundled Core Copilot Chat/Responses adapter. Supply `github_copilot::Config` with the shared provider `common` configuration, an optional `api` override, and the caller's release `user_agent`. Supply the endpoint and already-resolved bearer authentication; credential discovery and token exchange remain upstream. The existing `providers::github_copilot` function owns the native `packages/ai` facade, with its dedicated native route IDs and `openai` metadata contract.

The bundled adapter selects Responses for lowercase `gpt-<major>` model IDs with major at least five, excluding `gpt-5-mini` prefixes. An explicit `Api` overrides family selection. The route uses `ai-sdk:@ai-sdk/github-copilot` cache identity and the `copilot` replay namespace. GPT model IDs omit maximum-output-token settings. Responses reasoning families use developer instructions and omit unsupported sampling settings.

Every inference request sets the supplied user agent, `Openai-Intent: conversation-edits`, and `X-GitHub-Api-Version: 2026-06-01`. The final encoded request determines `x-initiator` and image-driven `Copilot-Vision-Request`. Resolved authentication replaces an existing bearer header and removes `x-api-key`. Integration and editor headers remain caller-supplied; the TypeScript model-discovery operation owns its `Copilot-Integration-Id` default. Headers, query, and body overlays use the shared route assembly and credential-redaction rules.

Chat preserves separate user text blocks, concatenates assistant text without separators, and echoes visible reasoning only with its opaque signature. Opaque signatures survive text/tool output and replay. Reasoning closes before text or tools begin. Claude cache hints lift to message-level `copilot_cache_control`, omit TTL, and share the TypeScript four-marker bound. Chat omits `stream_options` and leaves unreported usage absent. Responses preserves item IDs, stateless encrypted reasoning, generic continuation/cache options, and the latest opaque compaction boundary. Summary identity stays canonical when a final item ID rotates; final encrypted content survives replay. Unreported cache writes remain absent.

The adapter uses the native streaming executor and typed event vocabulary. SDK-only per-file `copilot.imageDetail`, raw-chunk, warning, response-metadata, direct non-streaming generation, and JSON response-format hooks are outside that contract. Native request-level OpenAI image detail belongs to the native OpenAI Responses route.

Copilot Responses accepts the native OpenAI `image_generation` and `web_search` hosted-tool definitions, including image action/quality/size, search domain filters, location, external-web-access, and token-budget fields. Tool choice follows the selected definition's native type, not its function name. Invalid hosted image/search options fail locally. `file_search`, `local_shell`, `web_search_preview`, and `code_interpreter` have no native hosted request lowering; those names remain ordinary function names without an image/search native definition. HTTP failures use the shared native typed classification and retain the Copilot error object's string-or-number code, nullable type, and arbitrary parameter fields in redacted HTTP context; they fail before stream parsing.

`tests/github_copilot.rs` ports bundled conversion, cache, reasoning, routing, and Responses regression vectors. `tests/github_copilot_transport.rs` verifies actual loopback HTTP request bytes, fragmented SSE, and a stateless tool-result continuation. The two Copilot SSE fixtures preserve the basic-text and reasoning-with-tools recordings embedded in `packages/core/test/github-copilot/copilot-chat-model.test.ts`. All checks are offline.

## Amazon Bedrock

`bedrock::amazon_bedrock` constructs the `amazon-bedrock` provider; `Route::bedrock` exposes the Converse protocol directly under the `bedrock` provider identity. Both require an explicit endpoint and resolved authentication. Supply `bedrock::Config` with `endpoint`, `auth`, and `defaults`; route/model/request defaults use the shared resolution order. The endpoint path percent-encodes the validated model ID as `/model/<modelId>/converse-stream`.

Select `Auth::bearer(Credential::value(...))` for a resolved Bedrock bearer token or `bedrock_auth::sigv4(Some(credentials), clock)` for AWS signing. `bedrock_auth::Credentials` contains `region`, redacted access-key/secret fields, and an optional redacted session token. The injected clock returns UTC `YYYYMMDDTHHMMSSZ` at each preparation. Credential discovery, expiration, and refresh belong to the upstream owner; no Bedrock code reads the ambient environment, discovers credentials, or retries provider requests. Missing SigV4 credentials fail preparation. Authentication signs the final encoded transport body and query, including overlays, with the TypeScript `aws4fetch` header exclusions, sorted canonical headers/query, double-encoded path, SHA-256, and HMAC-SHA256 derivation. Signed authentication/session-token headers retain sensitive-header markers.

Converse lowers system prompts, chronological wrapped system updates, user/assistant/tool histories, tool schemas and choices, inline base64 images/documents, signed reasoning, and inference settings. Adjacent nonvolatile user/tool/system content merges into the user wire role without reordering blocks. Cache points share four slots allocated in tools → system → messages order; one-hour hints emit `ttl: "1h"`. Unsupported or malformed media becomes the shared visible omission notice. `topK` lowers to `additionalModelRequestFields.top_k`. Model-specific thinking fields are supplied through `http.body.additionalModelRequestFields`; Bedrock provider options do not invent Anthropic thinking defaults or transform those fields.

The existing `framing::AwsEventStream` owns binary decoding and CRC validation. Converse uses the shared lifecycle, partial-tool accumulation, tool-schema projection, and exclusive-input usage normalization. Stream settlement waits for EOF so `messageStop` and `metadata` produce one final event in either order; cache reads/writes join the non-cached input count, and the normalized total includes that input plus output rather than the provider's cache-exclusive total. Absent counters remain absent and reported zero remains zero. Reasoning signatures survive replay, and signature-only reasoning marks output as potentially containing unreported reasoning without manufacturing visible text. Malformed local tool JSON emits a non-executable input error. Event-wrapped exceptions use shared error classification; binary frames whose `:message-type` is `exception` or `error` are ignored exactly as in the TypeScript decoder. Missing terminal settlement fails visibly.

`tests/bedrock.rs`, `tests/bedrock_transport.rs`, and `bedrock_auth` unit tests cover the TypeScript contracts and all three checked-in Converse recordings, including exact HTTP request bytes and the two-request tool-result continuation. The recordings are included directly from `packages/ai/test/fixtures/recordings/bedrock-converse`. Signing tests include the AWS `aws-c-auth` published `get-vanilla` and `get-vanilla-query-order-encoded` canonical/string-to-sign/signature vectors and fixed-clock `aws4fetch` output. All transport tests use loopback sockets; no live AWS traffic is required.

## Cursor wire boundary

`cursor` owns the Cursor Connect protobuf wire boundary. `cursor::request::RunRequest` accepts explicit conversation, group, message and model identities, selected variant parameters, resolved tool descriptors, encoded request context, inline selected images, and an optional opaque checkpoint. The encoder preserves protobuf field order, explicit zero settings, live request-context placement, seed-system/history JSON, and byte-identical checkpoint replay. Resume submits an empty resume action without another user message. Identity generation, model discovery, workspace/context discovery, authentication refresh, and durable conversation storage belong upstream.

`cursor::protobuf` implements strict uint32 tag/length and uint64 scalar parsing plus the hand-encoded `google.protobuf.Value` tool-schema format. Struct keys sort by JavaScript UTF-16 order. Value strings use TextEncoder replacement semantics; protobuf message strings preserve protobufjs encoding, including unpaired surrogate input. The Connect decoder retains split headers and payloads, preserves end-stream flags, and validates gzip members. Incomplete framing and EOF without `turn_ended` fail rather than inventing completion.

`cursor::headers::run` composes Cursor CLI identity/checksum, Connect and Run headers, and caller headers before applying an already-resolved `auth::Auth`. Request IDs are caller-supplied and replace case-insensitive prior values. Credentials retain the shared sensitive-header and redacted-debug behavior; the module does not read configuration, environment variables, credential stores, or device files. `agent_origin` accepts only HTTPS Cursor subdomain origins without URL credentials.

`cursor::stream::State` consumes wire bytes and returns common text/reasoning/finish events, correlated KV replies, and explicit control messages. Text closes a prior reasoning span, and terminal settlement closes open spans exactly once. Corrupt gzip and malformed non-request protobuf frames return diagnostics, block replay, and allow subsequent valid frames; malformed reply-requiring requests fail. Empty checkpoint updates retain the authoritative checkpoint. Exec, display-tool, step and interaction controls remain explicit caller-owned work; the state does not execute tools or guess native variant replies. `cursor::wire::Exec` decodes MCP argument maps and encodes successful/error results with elapsed time plus the required separate stream-close reply. Both replies belong on the originating Run. Blob maps can be restored by their upstream conversation owner; unknown binary 32-byte hash IDs return empty data, while inline content IDs echo their bytes, including 32-byte printable ASCII/control-whitespace payloads.

Replay analysis preserves the checked-in client's strict frame classification and sticky first barrier. Visible text/reasoning, display-tool lifecycle, non-control execution and malformed/unknown frames suppress replay; an upstream unsafe failure never becomes safe. Counter normalization uses inclusive input/output totals, clamps reported cache/reasoning partitions, and leaves absent counters absent. Checkpoint token details are inspected without re-encoding opaque state, with at most 128 breakdown categories. Raw Run counters and checkpoint occupancy remain distinct; the common usage boundary does not manufacture zero counts or a one-token output solely for UI occupancy display.

`cursor::transport::Client` owns raw bidirectional Run connections over h2. Construct it with explicit timeout and optional resolved proxy settings; compose authenticated headers through `headers::run`, then call `open` with a validated `Endpoint::agent`. TLS uses reqwest's default crypto-provider selection and rustls-platform-verifier system roots, validates the server name and certificate, and requires h2 ALPN. Cleartext endpoints are restricted to explicit loopback socket addresses. Each Client owns its per-origin connection cache, validates reuse by PING, and replaces connections at fifteen minutes or after a remote failure. `shutdown` cancels and joins owned connection drivers.

The returned Run has an independently usable reader and cloneable serialized writer. Writes preserve Connect frame bytes and await HTTP/2 flow-control capacity; write-drain timeout is non-transient and non-replayable. Reader deadlines apply while consuming the response. Local close/cancel unblocks reading without fabricating remote failure or provider completion. Remote terminal errors retain sticky settlement: raw stream failures take precedence, HTTP status wins over gRPC status, and trailers override response headers. gRPC message credentials are redacted. Cursor origin/transient/replay-safety diagnostics and gRPC/RST status remain in `provider_metadata.cursor`; replay analysis must still apply the visible-output and execution barriers before any upstream retry.

`cursor::proxy` resolves HTTP CONNECT proxies from a caller-supplied environment snapshot, honors uppercase/lowercase HTTPS_PROXY and NO_PROXY precedence, supports domain/port/IPv6 bypass rules and percent-encoded proxy userinfo, and preserves prefetched tunnel bytes before TLS. HTTPS-scheme proxies are ignored by environment resolution, matching the maintained JavaScript resolver. No transport reads ambient environment variables or credential stores.

`cursor::provider::model` constructs a native `llm::Model` for the shared `Executor::stream` and `generate` operations. Supply a resolved credential, CLI identity, validated encoded `RequestContext`, and shared `provider::Runtime` through `provider::Config`. JSON providers retain their existing protocol path. Cursor rejects JSON body/query overlays. Session headers select process-local conversation state; the Runtime serializes each Session's active stream and retains the originating Run across MCP tool-call/result steps. Trailing tool results are delivered as correlated exec-result and close messages on that Run, without resending the user prompt. Missing pending results fail locally. Absent usage stays absent.

`provider::Runtime::snapshot` and `restore` expose typed conversation identity, opaque checkpoint, blobs, last user input, and epoch-held tool descriptors. Core/Store own durable persistence; this crate writes no conversation files. Restoration rejects an active stream or held Run. `Config.persistence` is the typed `persistence::Store` boundary: the first Run of a Session keyed by the Session header calls `load` once and adopts a `Loaded::Restored` snapshot (missing, expired and invalid records start a fresh conversation; a prior `Runtime::restore` also counts as hydration), and each Run's `TurnEnded` calls `save` with the current snapshot before the finish is delivered. Store methods are infallible by contract; the Core implementation reports its own faults, which never fail a Run. Blob reachability compaction, host-agent/system-prompt identity and compaction-rebase markers are not part of the snapshot. While a Run is held or streaming, the Runtime writes a client heartbeat every `Config.continuation.heartbeat_ms` (default 5000); a failed heartbeat write cancels the Run so the next read fails visibly, and releasing the Run stops the heartbeat. `provider::model` validates `Config.continuation` with the committed messages: every value is a positive integer no greater than 2147483647, `heartbeat_ms` is below `semantic_idle_ms`, and `semantic_idle_ms` is at most `hard_cap_ms`. While no tool result is pending, a stream with no semantic progress (non-empty text or thinking, turn end, tool lifecycle, exec, KV, exec control, interaction query or checkpoint frames) for `semantic_idle_ms` (default 120000) fails with the transient, replay-safe `CURSOR_SEMANTIC_IDLE_TIMEOUT` error; each progress frame renews the deadline. A held Run whose tool result is still pending after `hard_cap_ms` (default 600000) is cancelled, and the next request with trailing tool results starts a fresh resuming Run from the stored checkpoint. OpenCode-activity lease renewal of the hard cap is not implemented. RequestContext materialization preserves caller-supplied base fields and replaces flat and existing filesystem/meta-tool catalogs with the epoch-held advertisement. MCP-state exec #36 reports full tool definitions from that context and filters requested servers. Configured MCP server IDs are sanitized and matched longest-first; equal provider/tool identities retain frozen descriptors. Advertisement remains stable while `ToolChoice::None` and absent current-step tools deny execution.

<a id="framing-and-lifetime"></a>

## Framing and lifetime

- SSE retains byte fragments until complete lines, supports LF/CRLF/CR separators, preserves UTF-8 splits, joins multiline data, and ignores empty data, comments, retry directives, and `[DONE]`. Neither a retry directive nor `[DONE]` certifies provider completion.
- AWS event-stream validates prelude and message CRC32, lengths, typed headers, and JSON payloads. Event payloads are rewrapped under `:event-type`; padding field `p` is omitted. Incomplete final frames do not manufacture events or provider completion.
- WebSocket JSON transport converts HTTP(S) endpoints to WS(S), sends the encoded transport message, reads text/binary frames, and owns a bounded socket actor. Abnormal close and delayed lifecycle heartbeat fail visibly. The actor pings every 25 seconds; a heartbeat delayed beyond 50 seconds closes the connection.
- Continuation serializes requests per supplied key, validates canonical replay before using `previous_response_id`, retains normalized output, and clears replay on fingerprint changes or explicit full replay. Idle retention is 60 seconds. Capacity is 64 inactive/active entries; all-active overflow is temporary and trims when an entry settles. Active requests cannot be evicted. Dropped sockets abort their owned tasks; idle and fingerprint eviction perform graceful close.

Protocol parsers emit typed text, reasoning, signed/redacted thinking, partial tool input, tool-call/result, usage, and terminal events. Missing terminal settlement and output after terminal settlement are errors. Local malformed tool arguments produce a non-executable input-error event; malformed provider-executed arguments fail the stream. Refusal becomes `ContentFilter`. Unknown token telemetry remains `None`; reported zero remains `Some(0.0)`. Anthropic input totals include non-cached input plus cache reads/writes; hidden reasoning is not independently reported. Cache-write TTL breakdowns survive incremental usage merging.

Provider strings and JSON values use Schema's lossless UTF-16 strings and JavaScript-ordered JSON objects, including tool-argument fragments containing lone surrogate units. Request bytes preserve provider field order and stable model-visible prefixes. Auth and prepared-request diagnostics exclude secrets; HTTP diagnostics redact sensitive fields, headers, query values, and echoed request credentials.

<a id="cache-and-tool-boundaries"></a>

## Cache and tool boundaries

Automatic Anthropic caching coordinates four shared marker slots in tools → system → messages order. Known Anthropic prefixes use the one-hour bucket; rolling message anchors use the default five-minute bucket. Manual hints retain precedence and consume the shared budget. Volatile messages are never auto-marked. Model-family gates control adaptive/manual thinking, effort, chronological system roles, and sampling. GPT-5.6+ cache selection retains its bounded stable-prefix/read-window policy for consuming protocols.

`tool::dispatch` executes one supplied handler without provider IO or continuation. Typed consumers supply decode/encode callbacks; dynamic JSON tools retain handler-owned validation. Expected tool failures become error/results; defects propagate. Structured outputs and text/file content remain distinct.
