# Revision 5 descriptor generation

Declare one protobuf service per Protocol group and one RPC per application operation in `protocol/ycoding/v5/*.proto`. These declarations describe binary WebSocket operations; they do not enable gRPC. Import `operations.proto`, declare the file's `(ycoding.v5.operation_range)` with inclusive `first` and `last`, and annotate every method with `(ycoding.v5.operation)`. Set an explicit ID, diagnostic name, fully qualified typed error names, roles, scope, mutation, settlement, paging, streaming and sensitivity. RPC request/result types supply the corresponding descriptor fields. Generation rejects duplicate IDs/names, missing annotations/ranges/roles, out-of-range IDs, unknown message types and gRPC streaming.

The TypeScript owner is `bun run --cwd packages/protocol generate:v5`. Cargo's protocol build owner generates the Rust table from the same descriptor set, preserving custom option bytes. TypeScript exports `operations`; Rust exports `OPERATIONS`. Both contain canonical `OperationDescriptor` values sorted by explicit ID. Rust also exports `DOMAIN_OBLIGATIONS` keyed by fully qualified message name and field tag; TypeScript's generated contract retains obligations alongside each field's structural rules. Neither table grants permission or implements dispatch.

`ProviderUsage_Source` assigns `provider_api=1`, `local_client_rpc=2`, `response_headers=3`, `provider_internal_api=4`, `local_session=5`, and Muse's `response_stream=6`. Append source ordinals without renumbering existing values; Effect literal declaration order does not determine persisted wire ordinals.

Annotate fields with `(ycoding.v5.constraints)`. `integer_min` and `integer_max` are canonical decimal strings within signed int64 through unsigned uint64 bounds. `utf16_min/max`, `codepoints_min/max`, `utf8_bytes_min/max` and `count_min/max` are inclusive bounds, capped at the JavaScript safe-integer maximum. Integer constraints apply to int32/int64/uint32/uint64; text constraints apply to protobuf strings or `LosslessString`; count constraints apply to repeated fields. Generation rejects incompatible field types and inverted bounds. Both strict validators enforce structural bounds. UTF-8 length counts the replacement character's three bytes for each lone UTF-16 code unit, matching JavaScript TextEncoder. Count minima apply to absent repeated fields as zero.

`domain_obligations` lists source schema identities such as `packages/schema/src/browser.ts#Browser.Tab` or `packages/protocol/src/groups/pty.ts#OwnedLocationQuery`. Record all source patterns, filters and refinements here; no regex dialect or regex engine exists in this wire layer. Obligations are metadata, not enforced wire constraints. Source coverage checks must call `requireConstraintCoverage` for each checked source field: it conservatively requires the exact source obligation for every Effect check, including checks with structural-looking annotations, because custom filters can reuse those annotations. Structural metadata alone must never certify a custom filter. Traverse source fields and union branches in the operation's coverage owner; an uncovered live Effect check fails coverage.

At wire-to-domain conversion, `ycoding-schema` must enforce every obligation before a handler runs. Schema-port lanes own those domain validators and real-Effect accept/reject goldens. Map conversion rejection to the same validation-error class as structural rejection. Neither table generation nor a successful structural decode proves domain obligations satisfied.

Check generation rejection with `bun test --cwd packages/protocol test/operation-generation.test.ts test/field-constraints.test.ts` and `cargo test -p ycoding-protocol` from `rust`. Use `--check-operations <fixture.proto>` on the TypeScript generator for read-only fixture validation; it writes only to a temporary directory. Adding canonical proto files changes the contract digest; regenerate digest-bearing foundation vectors through their owning generator, never by editing binary goldens.

## Sans-IO connection API

`connection::Connection` owns one authenticated revision-5 connection. Construct it with `Config`, an explicit operation descriptor table (production passes `OPERATIONS.clone()`), the required `Config.event_types` set, and monotonic caller-supplied milliseconds. There is no generated public-event catalog or default event allowlist; a payload type outside the supplied set is a protocol failure. Supply fresh connection and process source epochs on the Ready producer. It contains no sockets, executor, clock reads, sleeps, Frame codecs, or replay path. Generated payload validators enforce endpoint structural contracts; handlers enforce domain obligations.

Call `admit_incoming(byte_length)` before decoding, copying or asynchronously retaining the existing native buffer. It enforces the absolute directional cap and reserves its complete byte length. Refusal returns no token; drain `take_decisions()` and do not decode. Run `decode_strict::<v5::Frame>` on the original bytes, then call `accept_incoming(&token, frame, now_ms)`. Call `reject_incoming(&token)` on decode failure. Tokens are connection-owned and single-use; foreign or used tokens are caller errors. Acceptance transfers the charge into the receiving ledger or handshake owner; rejection and teardown release only that connection's charges.

Inject `Config.reservation: Some(SharedReservation)` to share a concrete `Rc<RefCell<ReservationBudget>>` across serialized connection/binding owners. `ReservationBudget::new(limit)`, `reserve(bytes)`, `release(bytes)`, `used()` and `limit()` expose the bounded pool. An omitted pool uses the connection's enforced windows, queues, handshake and endpoint reassembly limits, not a shared-relay limit. Reserve each independent backing allocation or delivery responsibility in its owning adapter; charge a shared backing store once and each actual copy separately. The relay adapter owns its cross-peer/HTTP aggregate policy. The 128 KiB/1 MiB application caps do not bound native receipt, platform send buffers, decoded-object heap size, allocator overhead or whole-process memory. Cloudflare can buffer a 32 MiB native message before the callback.

Call `start(now_ms)` to queue Hello. Valid Hello queues Ready; valid Ready queues the initiator's one receipt-confirming Ping. `request(operation_id, scope, encoded_payload, reserve_bytes, now_ms)`, `respond(result, reserve_bytes, now_ms)` and `enqueue(body, reserve_bytes, now_ms)` take binding-measured conservative complete-Frame reservations, including maximum uint64 ordinal/receipt widths. Transfer ownership of bodies and backing bytes; do not mutate them while queued, prepared, handed or buffered. Tiny controls are generated by live-work and consumption entry points.

`prepare_handoff(now_ms)` selects one eligible record without advancing a ledger or marking a request transmitted. Its opaque `Prepared` exposes `frame()` and `reserved_bytes()`. Encode that final Frame in the binding, then call `handoff(prepared, exact_encoded_bytes, now_ms)` at the synchronous native handoff boundary. Transmit only an accepted `Decision::Send`, without yielding after the transition. A size above the reservation or stale authority fence is terminal. A newly queued scoped resync returns a prepared StreamEnd to its queue instead of handing it early. `abort_prepared(prepared)` returns ownership to the queue and reuses the ordinal. Keep at most one prepared record outstanding. Native delivery is not consumption; disconnect on native handoff failure and never replay transmitted work. `advance(now_ms)` generates warranted credits/heartbeats and enforces deadlines. Drain `take_decisions()` after reservation/preparation calls.

The frame, handshake and typed-payload caps are fixed generated `limits` values. `Budgets` holds connection receive windows and queue, credit, rate and scheduling limits. Hello proposes bounded windows; Ready fixes the responder's effective windows without granting authority from a proposal. Pass authenticated roles and fresh opaque connection/source epochs in `Config`; the machine does not authenticate credentials or discover process identity. Application handlers must resolve Session placement and enforce domain obligations, pending form/review rules and managed-child restrictions before execution.

`request` validates an operation's role, scope and endpoint typed body and allocates a monotonic decimal connection-local ID. Relays validate header association and bounds while retaining opaque domain bytes for endpoint validation. `respond` checks the current incoming request and descriptor settlement. Cancellation distinguishes queued-unsent from transmitted-unknown, removes queued delivery and emits request-scoped cancellation decisions without claiming rollback or Session interruption. Close/restart settles unresolved transmitted requests as unknown and unsent requests as unsent; a replacement connection starts fresh. Concurrent incoming ID reuse fails; lifetime uniqueness is the peer allocator's obligation. Late results for previously allocated local IDs are dropped; future/unallocated IDs fail.

Request/Forward and request-scoped Cancel decisions retain exact input arrival order. The bounded incoming-request owner rejects overflow explicitly without silently dropping or reordering admitted requests. Relay/domain adapters own authorization, fresh-authority checks and admission lanes: reads remain independent, mutations preserve per-Session (or sessionless per-connection) arrival order, and notices share their per-connection lane. Admission completion is not Result settlement or consumption credit. The machine does not inspect opaque relay bodies to derive lane policy.

`consume` is an explicit receiver boundary: call it only after applying a frame or transferring it into a specifically bounded application owner. Forwarding, scheduling a callback, native socket handoff or HTTP enqueue is not consumption. Normal/event/bulk Credit releases exactly the known sender prefix; tiny receipts are piggybacked only on independently warranted traffic. Handed bytes remain accounted until receipt or teardown. Each class has independent ordinals, fixed windows and oldest-unconsumed deadline. Queue admission reserves complete encoded frames; tiny flow precedes normal, followed by Session/transfer rotation and two event batches per bulk piece when both wait.

`stats` reports owned/admitted/prepared byte charges, conservative queue reservations, exact handed/received charges, hydration/reassembly ownership, bounded request/subscription counts and oversized invalidations. Handoff refunds reservation slack and retains the exact encoded charge until receipt. Consumption releases receiver backing ownership, while the receiving window retains its grant fence until Credit handoff. These counters are not allocator or native-buffer measurements. `update_authority(version, authorized, now_ms, code)` fences admission/preparation across awaited binding work; an old fence cannot dispatch or transmit. `replace_authority` cancels work outside refreshed remote inventory; `revoke(4401 | 4403)` tears down revoked authentication. `disconnect(true)` reconstructs with 1012; create a new connection after close. Pre-Ready failures use 1008; use `Close::reason()` as the fixed ASCII reason, never payload or exception text. On non-request queue admission failure, disconnect/reconcile that recipient rather than building a retry queue. Local request preflight rejection is unsent and does not disturb previously admitted work.

`consume(class, ordinal, now_ms)` marks exactly one received frame consumed. Out-of-order consumption emits no grant until all earlier ordinals are consumed; its return value is the newly releasable contiguous byte prefix. The machine marks tiny receipt processing, accepted bounded hydration batches and endpoint bulk assembly as their own consumption boundaries. An earlier unapplied live event or pending normal frame cannot be credited by a later hydration/reassembly transfer. A relay forward is never automatically consumed.

After successful EVENTS settlement, decode the generated operation-specific Result and call `accept_subscription(request_id, subscription_id, authorized_scope, now_ms, Direction::Receive)`. The producer uses `Direction::Send` after Result handoff. Supply the decoded, authorized Session/global target explicitly: `event.subscribe` has a global outer RPC scope but carries its target in its typed request; Session-scoped EVENTS operations such as `session.log` require equality with their outer RPC scope. Reject other targets and remote global subscriptions. Invalid registration closes with the generated failure category. `release_subscription(subscription_id, direction)` releases interest and buffered ownership; producer release removes queued batches and queued/prepared StreamEnd.

Call `begin_hydration(subscription_id)` before the canonical snapshot read. Keep incoming EventBatches in the existing bounded event budget without selecting or validating their source epoch during that read. After the snapshot returns, call `complete_hydration(subscription_id, canonical_source_epoch, now_ms)` with its required nonempty source epoch. Completion installs only that argument, never Ready's epoch or an epoch inferred from EventBatch, and folds buffered batches in input order: matching epochs yield Events; other epochs yield ResyncRequired. Later mismatched epochs require resync again. Empty canonical input fails with EPOCH without discarding buffered ownership; an unknown subscription returns the caller error UNKNOWN without closing other work. Reserve caller projection storage before accepting returned objects. Buffer overflow and typed ResyncRequired invalidate buffers and retain a resync fence; failure of bounded native admission closes with LIMIT. Start fresh canonical hydration to recover. Successful canonical reconciliation clears the fence. The application owns subscribe-before-snapshot ordering, watermark discard, aggregate checks, gap reload, live-text merging and newest-100/paging/compaction projection; hydration does not resume provider execution.

`enqueue_event(event_record, EventMetadata, now_ms)` accepts one event with already encoded typed payload bytes, accepted Session/subscription identity, source epoch, optional message identity and interactive/background priority. Formed EventBatch admission through `enqueue` is a protocol failure. The connection owns one ordered open batch per Session/subscription and computes exact protobuf sizes arithmetically from UTF-8/payload lengths, scalar varint widths and field/length-prefix overhead; it never encodes a Frame. `event_frame_bytes` exposes the exact size for specified ordinal/receipt values; `event_reservation_bytes` reserves maximum uint64 widths. Flush at the 40 ms/750 ms expiry, 64 events, 256 KiB complete reserved bytes, source/interest identity changes or StreamEnd. A later interactive event shortens its open background batch's wait. A batch that cannot contain another whole event flushes before a new batch starts. An individual event above the cap is rejected from event delivery and produces a bounded normal-ledger ResyncRequired from metadata, never split. Flush earlier accepted events and wait for their scoped event-ticket consumption before handing the invalidation. Failure to admit the marker closes that recipient with LIMIT.

Canonical `v5::StreamEnd` completes an active finite subscription on the event ledger. Flush prior coalesced batches and do not hand it ahead of a queued or handed-unconsumed scoped ResyncRequired. Reject unknown, ended or wrong-direction terminals. Hydration, invalidation and unresolved resync block finite success. Only the canonical terminal yields `Decision::StreamComplete`; close without it is incomplete, never success. Tests use generated operation descriptors/codecs and an explicit test-only event payload type list. The relay hydration state fixture changes only the generated event.subscribe descriptor's requester role in memory; it does not verify production catalog authorization, which has no relay EVENTS operation.

Typed bulk success requires contiguous piece indexes/offsets, exact announced bytes/pieces and successful BulkEnd, then validates the complete typed message before settlement. Endpoints reserve announced storage before allocation and expose completed bytes through a shared `Rc<Vec<u8>>`, retaining the charge until `release_bulk(transfer_id)` or teardown. Reserve destination ownership before releasing that lease. Asset bytes retain the raw content contract without a typed decode. Relay mode routes bounded pieces without full-message assembly; forwarding never automatically consumes them. Cancellation immediately releases reserved assembly ownership and the transfer slot, independently of tiny-flow capacity. Unknown-transfer pieces/end are consumed as late delivery, increment `stats().dropped_transfers`, and follow exact byte/ordinal/credit accounting on their canonical ledgers (BulkPiece on BULK, BulkEnd on NORMAL), without allocation, resurrection or success. BulkStart still requires its live transmitted request, unique live transfer identity, matching operation/type/content kind, bounded announced bytes/pieces and the two-transfer cap. Native HTTP readers, asset target/MIME/digest validation, attachment admission/TTL, multi-peer reservations and authentication freshness remain adapter-owned.
