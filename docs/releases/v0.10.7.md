# YCoding v0.10.7

## Changed

- Chrome control keeps working in the background with real input: clicks and scrolls on a background tab or in an unfocused or minimized window are trusted mouse input that carry user activation, so popups, clipboard access, and file pickers work without bringing the tab forward. While YCoding controls a tab, the page reports itself visible and is not background-throttled; detaching ends this.
- Browser action results no longer include the `input` field.
- macOS computer use runs one persistent YCoding Computer Use helper per YCoding process over a private local socket instead of launching the helper for every operation.
- When a background app brings itself to the front in response to a computer-use click or key press, YCoding puts your original app and window back in front within the same action.

## Upgrade

- Select **Reload** on the YCoding extension card in `chrome://extensions` after updating so Chrome runs the new extension worker.
