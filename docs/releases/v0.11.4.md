# YCoding v0.11.4

## Added

- Authenticated Dots OAuth principals can create, read and revoke a durable device-wide grant (`session.dots.delegation.device.create`, `.read`, `.revoke`) for an existing Dots binding. Selecting `task`, `decision` or both, it covers every nonarchived Session the device owns, including existing native work and future Dots tasks. Core derives expiry from OAuth authorization; the grant has no one-hour cap and survives runtime restart and MCP reconnect until you revoke it, unbind, or authorization expires. The existing human-activated one-hour task delegation remains a separate path.
- `session.dots.decisions.list` lists typed pending decision candidates across those Sessions, and a listed candidate settles through the existing Dots exchange create and read operations without a preceding task exchange.
- MCP progress and blocker notifications are captured immediately, deduplicated and reconciled. The TUI and web conversation views identify client-originated decisions.

## Changed

- **Breaking Change:** an authenticated Dots principal with a device grant can settle any decision class through its exact typed candidate, including sensitive permissions, hard and custom-rule guardrail reviews, Forms, Questions, managed-child questions, deferred review items and recovery waits. Permissions and guardrails accept only a one-shot once or reject reply; room and prompt text never settles a decision. Settlement records the principal, grant, epoch and exchange as the source, and explicit denies, permission ceilings, ownership, archive state and revocation are rechecked at admission and settlement. Create a device grant only for a Dots client you trust with these decisions, and revoke or unbind to end it. Stored decision provenance migrates automatically on upgrade.
- **Breaking Change:** the `human-input` built-in instruction selector is renamed `decision-input`. Configuration that still uses `human-input` in `builtin_instructions` is invalid and is not rewritten; replace it with `decision-input`.
- macOS Keep machine awake holds display sleep as well as idle system sleep and declares native user activity immediately and every second, independently of shared lid-control ownership. The TUI Status dialog and web Settings → Machine report display and activity separately, including errors and unsupported parts. Activity confirms that the native assertion succeeded; it does not report an unlocked screen or guarantee that automatic lock is prevented, and deliberate locks and managed security policy remain effective.
- Session and subagent speed show estimated received-output throughput. The first output chunk is excluded, and a rate appears only after at least one second of observed output. Live rates use a trailing five-second window and restart for each provider attempt. Usage reports keep provider-counted output and their existing timing rules.
- Built-in reply guidance calls for plain Markdown without HTML `details` or `summary` wrappers, leaves the full list of changed paths to the native Captured changes (TUI) and Edited files (web) summaries, and cites a repository-relative path only where it explains a finding, behavior, action or handoff.

## Fixed

- Antigravity requests no longer send client cache resources or cache breakpoints, so the Cloud Code gateway chooses the implicit Gemini prefix.

## Limits

- Local synthetic-transport checks do not establish host-side Dots or MCP client behavior.
- Automatic-lock prevention under Keep machine awake depends on the Mac's idle screensaver and lock settings and was not established by assertion success.
