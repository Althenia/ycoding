# YCoding v0.11.4

## Added

+ Servers started with `YCODING_LOG_LEVEL=DEBUG` record aggregate memory diagnostics in the existing private log: separate current and lifetime-peak RSS, plus heap size, capacity and external memory on Node. Sampling starts immediately, repeats every 30 seconds and stops after 120 records or when the server scope closes. Normal Info-level operation does not sample memory. Unsupported, unavailable and failed measurements have explicit statuses instead of substitute numbers.
+ `ycoding decision watch --family --follow` accepts `--max-readers` to bound live Session subscriptions independently of family size (default 16, range 1–64), and `--max-pages` to bound each family discovery and task reconciliation (default and maximum 32768).
+ Chrome control adds a native green tab-group marker. An inactive, ungrouped profile tab gets a temporary singleton group; an active, ungrouped tab keeps favicon-only control. Controlling an existing group requires an explicit `group_control` grant covering every member, all inactive, unpinned, in one window, permitted for their sites and leased to the same Session. Tab listings include `groupID`. Group changes end control, and release restores the saved appearance only while ownership and inactive membership remain unchanged.
+ Local extension builds support CRX3 signing with an RSA key read only from standard input and checked against the bundled extension identity. `install:local` verifies the signed package against the unpacked build and replaces it alongside the executable and extension. An installed signed package requires a valid matching package on later local updates; signing and file placement do not install the extension in Chrome or add a CRX to published release archives.

## Changed

+ Computer calls draw no cursor, label or overlay, and browser control draws no in-page cursor, label or ripple. The browser favicon marker, toolbar badge, marker expiry and cleanup remain, along with ordinary input delivery and existing safety checks.
+ Built-in agent and Project guidance directs independent work to proceed without administrative handoffs, check slots or resource-limitation waits. Built-in shell guidance leaves commands uncapped unless the project or user explicitly configures a memory limit. Permissions, safety gates and designated model and profile choices remain unchanged.

## Fixed

+ Session activity reads load only the ancestry needed for outstanding work instead of every Session. Transcript snapshots read instruction notices within their requested page, including inherited notices, and configuration reload queues retain only matching configuration or provider-connection updates rather than unrelated transcript events. Ordered updates and durable history remain intact.
+ The TUI releases inactive metadata promptly when a retaining view closes and prevents disposed activity reads from publishing stale results or scheduling more work. Obsolete Session reads are cancelled when their owner is disposed or the connection drops; older history reads are cancelled when the transcript is evicted or replaced. Reconnecting can load the selected Session without waiting for an obsolete response.
+ TUI Find waits for a replacement transcript snapshot before continuing through older history and leaves an evicted Session unloaded. Read failures remain visible and retryable.
+ Web Project context can collapse independently of the Session rail and remembers that choice across refreshes. Waiting counts remain visible while context is hidden. Member details and Settings open on demand, Settings drafts and disclosure state survive data refreshes, and Project and Session rows preserve keyboard focus as their data changes. Phone sheets and management actions remain available.
+ Continuous family decision watching covers large and changing families, including compaction descendants, with bounded live subscriptions and sequential retained-log replay. Busy, retry and idle transitions re-evaluate membership; active members beyond the live pool remain covered through global invalidations and finite replay.
+ Retiring a decision subscription or temporarily losing family membership preserves acknowledged cursors, pending delivery and deduplication history. Re-entry resumes the latest acknowledged cursor, and existing version-1 state resumes without conversion. Retained delivery waits for family observation to be ready and its state save to succeed. Discovery or recovery-budget exhaustion preserves recovery state rather than reporting readiness or discarding unresolved work.
+ A saved decision-follow endpoint mismatch reports a specific sanitized `state-invalid` diagnostic without changing the original endpoint binding, cursors or pending delivery. Source invocations can select the original release server explicitly with `--server`.

## Limits

+ The desktop app targets Apple silicon macOS (`darwin-arm64`) only. It is signed with the self-signed YCoding Code Signing certificate and not notarized, so Gatekeeper still blocks the first open until you allow it.
+ In-place updates need a `.app` bundle in a location the current user can write to. Otherwise `Updates` reports that the update cannot be installed and states why.
+ Memory diagnostics do not collect heap snapshots, force garbage collection, attribute native allocations or establish the cause of a stall or leak. Bun heap sampling remains unavailable because its sampling cost is unverified. Enabling DEBUG on a client does not instrument an already-running server.
+ Decision-follow state remains limited to 1 MiB and 8192 retained cursors. Exhausted discovery or recovery budgets require recovery rather than silently accepting partial family coverage.
+ Chrome group restoration is best effort. A crash or restart can leave a green group, and the extension does not infer cleanup authority from its color or title. Reload the extension after replacing its files; the extension and backend must use bridge protocol version 6. Existing pinned-tab and favicon Content Security Policy restrictions still apply.
