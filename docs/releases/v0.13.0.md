# YCoding v0.13.0

## Changed

- A new installation uses the Rust runtime. On macOS or Linux, run the shell installer from the installation page. Rust starts with its own `core.redb` store and does not import Bun Session history, Usage, or saved data.
- The default installer leaves an existing Bun installation or database alone. To stay on Bun, run `YCODING_VERSION=0.12.2 sh install.sh` using the downloaded installer. To replace the executable with Rust, let active Sessions finish and run `sh install.sh --replace-bun`. That command leaves your Bun database intact on disk.
- GitHub Latest stays on Bun 0.12.2, so an existing Bun installation stays on Bun when it runs `ycoding update`. On Rust, the same command checks for stable Rust releases.
- Open `/remote` for Bun 0.12.x devices or `/remote/rust` for Rust devices. Both use the same Web sign-in, and existing Bun links still work.
- The Rust runtime uses the v5 WebSocket API for Session, Project, and configuration operations. Call a named operation with `ycoding api session.list`, or use a v5 client. The Bun REST routes for these operations are not available on Rust. Run `ycoding api --help` for operation syntax and `ycoding --help` for the Rust command list.
