# YCoding v0.11.6

Lighter Session switching and reliable recovery

## Added

+ Runtime memory diagnostics and periodic telemetry include lifetime-peak RSS, Bun-reported current and peak commit bytes, separate minor and major page-fault counters, and the number of active model attempts. Unsupported or unavailable measurements remain explicitly unreported.
+ Web Team views can inspect child conversations and discover paginated descendants, with parent navigation and decisions kept with their owning Session.

## Changed

+ Web refreshes public pages, documentation navigation, Session controls, Projects and Team views with shared typography, self-hosted monospace fonts and phone layouts. Conversation, Usage and Settings columns start at the same edge while prose keeps its reading measure; hover and keyboard tooltips work inside dialogs.
+ Decision-watch recovery messages separate State, Work, Counts, Action and inspection commands. They bound long task and member summaries, identify current failures separately from settled child failures, and leave progressing work alone without reading root todos during active recovery.

## Fixed

+ Resuming a decision watcher tolerates a missing former Project member while reconciling current membership. Missing root or family Sessions and other task-read failures still stop observation; acknowledged cursors and pending delivery remain intact.
+ Location metadata, configuration diagnostics and durable Session reads acquire only the services they need instead of starting execution services or MCP clients. Interrupted MCP startup closes its acquired clients and clears its tools.
+ Skill and configured Markdown reads avoid retaining full documents in the parser cache. MCP tool-catalog refreshes replace superseded output-schema validators, and failed OAuth exchanges, including response-body failures, leave the shared exchange cache so later requests can retry.
+ The TUI Session switcher loads global pins and project-local recent roots without enumerating unrelated unpinned Sessions or loading full child-task progress pages. Waiting and running roots remain visible across projects, lifecycle refreshes are coalesced, and progress-only updates do not refresh global picker queries.
+ Node CLI builds isolate native-only Desktop and SQLite imports. Database recovery uses Node's read-only SQLite API, allowing the packaged Node executable to start without importing Bun SQLite.
+ Meeting Stop remains available for this page's active capture when state reads fail, are denied or stall. It releases local capture sources before waiting for runtime confirmation and reports an unconfirmed runtime stop when acknowledgement is unavailable.
+ Chrome and isolated-browser control discard a lost execution context without replaying the failed page action. A fill or select whose result was lost may already have changed the page; fresh observation is required before another action.
+ Claude quota warnings retain rejected subscription and model-scoped windows for the bound profile until their reported reset or a later response for that window. Optimistic usage polls and partial responses cannot clear an exhausted future-reset window, and local alerts identify the provider, safe profile label and quota window.
+ Expired Claude response quota windows are removed from usage reads and forecasts at their reset boundary. Cached quota is used when reported; a cold cache leaves quota unreported rather than retaining expired exhaustion.

## Limits

+ Desktop targets Apple silicon macOS (`darwin-arm64`) only. It uses the self-signed YCoding Code Signing certificate and is not notarized; Gatekeeper requires first-open approval. In-place updates require a writable `.app` location.
+ Desktop client execution requires the native YCoding executable and is unavailable in the Node CLI.
+ Memory summaries do not attribute native allocations or allocator-retained capacity, take heap snapshots, force garbage collection or establish measured live RSS savings. Bun commit counters are runtime-specific accounting, and page faults are cumulative counts rather than proof of paging-related stalls.
+ Releasing Meeting capture sources does not prove that the runtime accepted Stop. An unconfirmed stop requires inspection in YCoding before retrying.
+ Already-running CLI processes, decision watchers and daemons retain their loaded runtime. Reload the unpacked Chrome extension after replacing its files; extension and backend must use bridge protocol version 6.
