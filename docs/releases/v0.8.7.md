# YCoding v0.8.7

## Fixed

- Report Cursor's **cache read** and **cache write** as portions of the context total on the Usage rail, so a warm Cursor turn shows its cache hit percentage instead of leaving cache unreported. A real zero stays **0%** and a step with no cache ratio stays unreported rather than showing zero.

Cursor models keep running with YCoding's own tools, permissions, and guardrails, and the sticky `X-Session-Id` still lets later turns in one Session reuse Cursor's prefix.
