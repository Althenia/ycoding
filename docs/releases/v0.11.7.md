# YCoding v0.11.7

## Added

+ Every visible built-in tool is available through Code Mode `execute`, not only plugin and MCP tools. Nested calls use the same permissions, guardrails and hooks as direct calls, and each completed nested call is recorded before the program continues, so completed work survives a later program failure or restart. Regex operations in Code Mode programs run in a separate process with a one-second default deadline; an expired operation fails the program with `TimeoutExceeded`.
+ The browser tool reads cross-origin iframes: page text and elements from approved frames appear in observations, actions work inside child frames, and screenshots no longer fail on every page that contains an iframe. Frames from unapproved origins contribute nothing and are reported as unobserved. New actions: back, forward, reload, key, wait, history search, clipboard read and write, file upload, download wait, developer logs, MHTML export, and WebMCP tool listing and invocation, all under the existing per-site permissions. Isolated mode accepts the actions that need no user profile; history, clipboard, upload and download wait stay profile-only.
+ The computer tool adds `desktop.query`, `desktop.select_text` and `desktop.perform_action`, and lists recently used applications that are not running.
+ Speed is measured for every provider request attempt, including fallback models, background title, goal, compaction, decision, prediction and prompt-generation calls, and replies shorter than one second. Each request records whether it completed, failed or was cancelled. The TUI sidebar and subagent footer keep the last measured speed instead of blanking at each step, and hide the row until something is measured. The Usage screens in the TUI and web add mean and aggregate speed, first-output and total latency percentiles, concurrency and error-rate columns, speed charts in the web Usage page, and a live block that polls only while requests run. Requests recorded before this release carry no outcome.
+ A parent can switch a direct subagent to an explicitly selected provider, model, profile and advertised variant at the next Step boundary. Omit the profile to use the target provider's default; the previous provider's profile is not transferred automatically.

## Changed

+ The Usage dashboard opens from prepared, render-ready data instead of aggregating request history on every open. One `usage.dashboard` read (`POST /api/usage/dashboard`) returns a preparing, error or ready view with provider quota filling in separately; clients poll only while a view is preparing and keep table position, paging and sort while quota loads. Existing usage endpoints are unchanged.
+ A one-time startup migration rebuilds the usage tables from retained request records. The first start after upgrading can take longer, and the database grows because it now stores the prepared data. Later starts reuse the prepared views and rebuild only views whose catalog prices changed.
+ The TUI and web Usage screens and task-cost details show only known values. Missing cells render empty instead of `unreported`, `Unknown`, `N/A`, `Waiting` or `Measuring`; a partially priced cost shows its priced subtotal; lines with nothing known are omitted; untitled Sessions read `Session <id>`. The `>=` lower-bound marker, priced and unpriced request counts, `so far` and `incomplete` labels stay. A subagent with accounting but no priced request shows `$0.00` with `so far` or `incomplete`.
+ `codemode: false` on an MCP server or plugin tool registration now also advertises the tool's direct definition while it stays available in Code Mode. Permissions apply to both paths; disabling `execute` disables Code Mode and leaves independently advertised direct tools available.
+ Retryable pre-output provider failures use at most three physical attempts (the first plus two retries) instead of ten, with two- and four-second delays. A configured model fallback starts after those three attempts.
+ Built-in agent guidance asks for one consolidated verification pass per finished feature: complete the feature across all affected layers, batch corrections, rerun only invalidated checks, and stop only at completion, a blocker or an approval gate.
+ Computer-use input no longer shifts keyboard focus away from you, and pixel input to a Chromium window on another Space fails immediately instead of being dropped silently.
+ **Chrome extension:** the extension and backend now use bridge protocol version 5. After `ycoding update`, select **Reload** for the unpacked YCoding extension in `chrome://extensions`, or the extension stays disconnected. If the popup shows unpaired, create a new pairing code and connect again. History search and download waiting need optional `history` and `downloads` permissions, which the popup requests when you pair or reconnect.

## Fixed

+ Restarting the service no longer fails running managed child Sessions with `Agent not found`. Shutdown now stops running drains before releasing Locations, so children end interrupted and suspended and are recovered after restart.
+ Recovery after a restart ends its request on a user or tool turn. Providers that reject assistant prefill, such as Claude Opus 5.5, no longer fail with "The conversation must end with a user message".
+ Touching a directory no longer builds its whole Location graph. Services load on demand, idle Locations are released, model discovery is shared across Locations, and Location builds, configuration reads and first loads no longer publish catalog, agent, command, skill or config update events when nothing changed. Connected clients stop reloading Locations after each such event, which lowers the memory a long-running service holds.
+ The "Will run out" and "Cutting it close" quota alerts fire once per warning level and re-arm only after the pace stays ahead for 15 minutes or the window resets. A restart no longer repeats warnings already delivered.
+ Pasted and dropped local files in the TUI are read by the TUI and sent as content, so a file the service cannot read (for example in another macOS account's home) no longer fails with "Attachment rejected". The 20 MiB limit, text line ranges and directory listings are kept, and the receipt shows the rejection reason.
+ The web prompt receipt no longer keeps showing Processing under a finished Session after a reconnect. The status read retries up to five times with doubling delays, and a missed execution outcome is recovered from the Session log.
+ Antigravity Claude requests carry tool call ids on every function call and its matching response, so conversations with tool history no longer fail with `tool_use.id: Field required`. A call or result without a matching id fails locally before sending. Gemini requests are unchanged.
+ The TUI Connect Chrome dialog sizes to its content instead of leaving blank rows above the scroll hint, and shows the one-time-code instruction only while a pairing code is displayed.

## Limits

+ Models defined only by external plugin packages read as unpriced in Usage, because pricing does not load external plugin packages.
+ Code Mode value-size caps are soft limits, not hard heap isolation.
