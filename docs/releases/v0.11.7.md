# YCoding v0.11.7

## Added

+ The Project tool's `create` action lets a Project's Master start a member Session in its own new managed Git worktree and branch, owned by the Master or by a live subagent the Master launched, with an optional first message. Worktree creation uses the same permission and guardrail review as the worktree tool, and `create` is refused when the worktree tool is not allowed by configuration. The member starts under the Master Session's permission ceiling plus the Master agent's effective deny rules (agent denies not covered by a later non-deny agent rule with the identical action text (or `*`) and identical resource text (or `*`)).
+ Provider connection details report whether a stored profile came from an OAuth sign-in or an API key, without exposing credential material.

## Changed

+ Member notifications go only to the member's current owner, or to the Master when the member has no owner; other Sessions receive none. A finished owner subagent resumes when a member notification wakes it and reports back to the Master when its turn settles. Waiting and starting owners keep notifications pending until they run. Cancelling, cancelled, failed and lost owners never receive member notifications: their members return to the Master with their pending requests, and a request handed off to the Master is not delivered twice.
+ A member's completed notice is sent only when the member's Session family has no background work and the member's own pending input (steer, queue or compaction barrier) is empty. The check does not read the member's goal state, open reviews, an active revert or descendant Sessions' pending input, and behavior with an active goal has not been verified. The notice is sent to exactly one receiver and deduplicated by a deterministic notice identity, and replaying earlier events at startup does not wake any Session or resend notices already delivered.
+ Project role instructions direct the Master to delegate independent scopes to owner subagents, each member working in its own worktree, and direct owners to act on every member notification and stay responsible for their members until the work is verified.
+ `ycoding decision watch --family` no longer reports work as completed while a Session in the family still has queued work; the work state is `background`. A plain watch ignores descendant Sessions. When the work assessment cannot be read before the deadline, JSON output reports `assessment: "unavailable"` instead of omitting the field.
