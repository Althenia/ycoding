# YCoding v0.11.3

## Added

- Relay MCP provides `session_dots_decision_form`. For one eligible ordinary decision already listed by a Dots task exchange read, it asks the authenticated client for the answer through a standard MCP `2026-07-28` form. It requires a native-approved delegation with decision scope and a client whose same request declares `elicitation: {}` or object-valued `elicitation.form`; URL-only or unknown-only declarations do not qualify. The answer is client data, never human approval. Only accepted, validated content becomes a delegated decision, and decline, cancel, missing or dropped responses leave the native request pending. Form state is single-use, expires after five minutes and is bound to the caller, the arguments and the exact candidate. Hard reviews, custom-rule reviews, `requireHuman` requests and Always grants stay human-only. Forms support strings, numbers, integers, booleans and fixed single or multiple selections; conditional fields, external forms and multiple custom answers are refused with an explicit error. No defaults are filled in, and `false` remains a value.
- `ycoding remote mcp status` can include optional `clientCapabilities` observations of the declared protocol version and form support per client request. Omission means unreported, not unsupported. Observations carry no client names, identifiers or payloads, are not persisted and clear on disconnect, revocation or close.
- The native Dots bindings dialog can Bind several Sessions in one pass. Nothing is preselected: choose each Session, the scope, the expiry (at most one hour) and, when a Session has more than one source principal, the source. Each Session needs its own native approval, and a denied Session does not undo an approved one. Session-basis binding needs no current native task, and a decision-only grant cannot be bound because it could never admit its own task. Unbind revokes exactly the displayed grant. An unknown outcome locks the dialog to read-only refresh.

## Changed

- Eligible ordinary permission, guardrail, Form and question requests from a delegated task can be settled through the delegated decision exchange. Native checks repeat inside the settlement lock against the exact request fingerprint and canonical source, a decision is never replayed, and an unknown outcome keeps the exchange lane read-only until an exact read reconciles it.
- Form answers settled through Dots delegation show an external-client source in the TUI and web, distinct from you and from native coordinators; a malformed source reads as unreported rather than attributed to you.
- Compact permission and Form details size to their content, keep the keyboard-selected option visible in long lists, and stay bounded and answerable on short or narrow terminals.
- A parent that cannot switch a child's model because the child is not its direct child, or because the causing input is not a native user prompt in that Session, receives a sanitized explanation. Ownership and permission gates are unchanged.
- Project creation resolves a leading `~` or `~/` against the home directory and shows an absolute-directory correction for other relative paths before any Session is created.

## Fixed

- Multiline free-text and custom answers show their last line in short terminals and submit the complete value.

## Limits

- A running connector observes only the handler code it has loaded. `clientCapabilities` is a diagnostic and never authorizes a later request or another client.
