# YCoding v0.11.3

## Changed

+ This release follows the version sequence restarted at v0.11.0. The v0.11.3 label was also used on 2026-10-26 for a different build; the shared release notes distinguish that historical publication from this release.

## Fixed

+ SQL guardrails distinguish supported literal printing, searches, comments and bounded read-only queries from destructive execution. An inert mention cannot hide a later destructive operation in the same command or another resource. Recognition is literal and bounded, not a general proof that a script is safe.
+ Reviews retain confirmed and uncertain evidence across command segments and resources. Opaque or dynamic interpreter input keeps non-dismissible review with an explicit reason that execution is unproven; arbitrary interpreter source is not treated as proven SQL execution. Hard reviews, catastrophic denies, custom rules and explicit permission denies remain enforced.
+ SQL client arguments preserve local-client file operations, including database operands, file-valued options and supported PostgreSQL and SQLite client commands. SQLite imports with unresolved import targets retain ordinary file-operation review without inventing a destructive database operation or losing known outside targets.
