# YCoding v0.11.3

## Added

+ Native Dots remote control has a profile-aware model picker. `model/list` keeps separate entries for each eligible credential profile, using canonical IDs `providerID/id` or `profile#providerID/id`, with each entry's own `supportedReasoningEfforts` and default marker. Effort travels separately from the ID. On a cold start with no eligible root Sessions, discovery reads the home-directory catalog. `config/read` reports `model_provider: "ycoding"`, the YCoding provider definition, and the effective model and effort. `config/batchWrite` saves defaults in the local SQLite KV store under `dots.native.default-model`, without changing `ycoding.jsonc`, the active credential or existing Sessions. It accepts only `model`, `model_reasoning_effort`, `profiles.<name>.model` and `profiles.<name>.model_reasoning_effort`. Model and effort selection works through `thread/settings/update`, `thread/start`, `thread/resume`, `turn/start` and `turn/steer`, preserving the selected profile instead of falling back to another account. Invalid or unavailable model, profile and effort choices return `-32602`. Non-null `approvalPolicy`, `approvalsReviewer`, `sandbox` and `sandboxPolicy` overrides are rejected with `-32602`, even when they match reported defaults. Only `model` and `model_reasoning_effort` may appear in `config` on `thread/start` and `thread/resume`; other configuration overrides, including any non-null `config` on the other three selection calls, are rejected. Changing an existing thread's `cwd` is also rejected; `thread/start` requires an existing absolute directory and creates no directory. These choices apply to local YCoding Sessions, not the cloud Dot's model or executor.
+ The Project Master can use `project remove` to detach a settled member after its delivery is verified complete and integrated or finished. Removal ends membership and ownership while preserving the Session, its Location, goals, agent, model, permissions, files, messages, and Session and Project histories. It refuses non-Masters, targets outside the roster, running or queued work, unfinished background work, and pending questions, forms, permissions or guardrail reviews anywhere in the member's family. Settled supervisors with no remaining owned members complete. `project release` still parks ownership without removing the member from the roster.
+ `project model` reads and persistently replaces a member's saved `{ providerID, id, profile?, variant? }` selection. A replacement requires the exact `expectedModel`, including whether profile and variant are present; `null` compares against an unset selection, and omitted optional fields in the replacement are cleared. The model is validated at the member's Location, and a change during an active Step waits for its safe boundary without interrupting or waking execution. Ownership and the expected selection are checked again before saving; a stale comparison needs fresh readback, not a blind retry. `project send` model overrides remain temporary and do not change the saved selection.

## Changed

+ Web and Desktop share the Ledger workspace layout.
+ The left rail is 256px wide. `[Y] YCoding` and a compact `New chat` button share the top row, followed by `Search sessions` and an `All · Waiting · Running · Idle` filter strip with counts. Sessions are flat single-line rows under a lowercase workspace heading, each with a leading status icon: a spinning arc for running, a hand and `Waiting` for waiting, an alert triangle for failed and a quiet dot for idle. The rows have no pin buttons and the rail has no machine footer.
+ The conversation header keeps the title and workspace details on one line, with compact icon actions at the end.
+ The centered transcript grows to a 720px reading column and shows assistant replies directly on the page. `Worked for … · N tools` and `N files changed +A −D` are flat inline rows that expand on demand. Your prompts sit in a right-aligned bubble with inline image thumbnails, file chips and one `Queued` receipt. Typing dots mark work before visible output and between steps, without duplicating a live tool or reasoning indicator.
+ The composer is one rounded card: the `Ask YCoding…` field on top, and attach, agent and model, effort, Autonomous and a round send button inside the same card. On phones the agent, model and status chips take their own line above the send controls.
+ The `Session companion` has text-only `Activity`, `Running`, `Changes` and `Context` tabs. `Running` lists running subagents and shells. `Context` shows the `Active window` total on one line, a three-column breakdown and `Step & prompt cache diagnostics`, with `Open Usage · cumulative spend` and a transcript-message disclosure labeled `Retained transcript messages` on Desktop and `Loaded transcript messages` on Web.
+ `Settings` is one open column: `Machine` with machine selection, rename and `Keep machine awake` first, then `Appearance`, `Notifications`, `Permissions` and `App`. Desktop keeps `Updates` in the same column.
+ Web collapsible rows animate height and fade together when they expand or collapse; reduced motion removes the height motion and shortens the fade.
+ Project guidance defaults to direct Master-to-member ownership and adds a supervisor only for more than three long-running parallel members. Executors scale from zero to five subagents across genuinely disjoint file and check lanes, keep small or coupled work in one Session, and keep one writer per file. Heavy builds, workspace compiles and browser suites run one at a time; fast single-package typechecks may run concurrently within bounded memory. Main Sessions and subagents retain their designated models and profiles without substitution. Verification evidence goes directly in replies. Authorized local integration runs selected checks, one complete commit, a linear rebase, a fast-forward merge and safe worktree cleanup in one pass; overlapping conflicts or failed checks stop that sequence, and the guidance grants no new approval or execution authority.

## Fixed

+ Project creation uses the selected repository Project's canonical directory for standalone root members, without creating an unwanted branch or worktree; an explicitly requested managed worktree uses its own directory. New TUI Masters resolve the chosen directory before Session creation, and a failed lookup creates nothing. Creation receipts reconcile retries and report actual placement, enrollment and saved model without deleting a Session on failure. Hard and custom guardrail approvals, explicitly human-owned permissions and forms, and mandatory safety decisions stay with the human; coordinators may decline safely but cannot approve around those gates. Escalation identifies the Session where the human must answer. TUI Project controls show direct delete hints and keep `?` as a waiting-state marker. Dot notices and connection dialogs consistently call the work `Dot threads`.
+ The TUI Session palette stays responsive during activity. Activity refreshes are coalesced without rediscovering all root Sessions on each update, unchanged picker rows and running indicators stay mounted, and stale responses cannot update a closed or replaced picker.
+ Web and Desktop keep the last transcript content and decision controls clear of the floating composer as a draft grows. Command palettes and model pickers refine keyboard navigation and scrolling. Web preserves the reading position when a disclosure expands, and its command palette selects models directly. Desktop's model picker includes recent choices and can stage effort locally during execution without changing the Session or queued prompts. Running-state displays include active descendant tasks and shells, while `supervising` remains unfinished ownership rather than active model execution. Empty, loading and failed workspace reads have distinct states and recovery controls; Desktop provider connection methods appear after choosing a provider.

## Limits

+ The desktop app targets Apple silicon macOS (`darwin-arm64`) only. It is signed with the self-signed YCoding Code Signing certificate and not notarized, so Gatekeeper still blocks the first open until you allow it.
+ In-place updates need a `.app` bundle in a location the current user can write to. Otherwise `Updates` reports that the update cannot be installed and states why.
