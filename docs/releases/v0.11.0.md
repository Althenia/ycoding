# YCoding v0.11.0

## Added

- Projects pair one Master Session with member Sessions in any directory. Create a Project, add an existing Session, create a new Session in a directory, remove a Session from the Project, or delete it, from the TUI Projects screen (`/projects`) or the web Projects view. A Session belongs to at most one Project.
- Opening a Project opens its Master chat. You give instructions there; the Master directs members with the `project` tool (list, send, answer, interrupt), either directly or through its own subagents. Members' finished, failed and interrupted turns and their questions, permission asks and reviews arrive in the Master chat, or with the Master subagent driving that member, and wake it automatically.
- The Master is labeled and pinned first in every member list, and member chats name their Project and Master with a way back. Member rows show live state, last activity and the Master subagent driving them.
- Your message in the Master chat activates its Project; interrupting the Master or a backend restart pauses it until your next message. An optional Project concurrency limit refuses new work with a reason instead of queueing it.
- The CLI (`ycoding coordination list|get|create|update|delete`), the remote web client and Relay MCP use the same Project operations.
- Routine delegated questions, permission asks and ordinary guardrail reviews use the existing native decision paths under a centrally revocable policy. Project settings can narrow that policy. Denies, permission ceilings, hard reviews and human-only decisions retain their existing authority.
- External notification filters can limit TUI attention, web System alerts and phone push to Master Sessions and selected event categories. Each client keeps its own filter; in-app notices, pending questions, permissions and reviews remain visible.
- Enable ChatGPT and Claude account connectors in Sessions through hosted MCP. Both providers default off and use an existing YCoding OAuth profile with per-connector allow and deny policies.
- Connector tools retain their selected account binding and recheck profile replacement, provider disablement and connector denial before dispatch. Actions ask by default and preserve permission ceilings and Session guardrails.
- Claude organization-blocked tools are unavailable. Organization-required approvals and tools requiring user interaction need a fresh human decision; saved approvals and automation cannot satisfy them.

## Changed

- Machine display names are account-owned aliases shared across browsers. Rename an owned machine inline in Settings, including while it is offline; the hostname and stable machine identity remain unchanged. Browser-local aliases are not imported, and failed saves retain the draft and confirmed name.
- Built-in Git worktree guidance creates worktrees at `<data>/worktrees/<repo-key>/<name>`, the managed worktree location, and built-in agents reach every managed worktree without an outside-directory prompt.
- Messages the Master sends to members use the same first-person user-message presentation as typed instructions, without a separate sender persona. Authenticated origin stays in audit metadata, and message text cannot settle native controls.

## Fixed

- Human messages activate paused Projects without re-decoding live event payloads. Pending decisions and failures reach the supervising Session even while dispatch is paused.
- Supervisors can decline routine requests and escalate unresolved decisions with an attributed reason chain. Human-only approvals, explicit denies and permission ceilings remain enforced.
- Project creation preserves fresh revisions and supports titled new Master Sessions. Session pickers filter as you type and retain distinguishing directory names; roster counts, editable fields and keyboard hints remain consistent.
- Scoped keymaps share one destruction listener per renderable, and process warnings go to the TUI log instead of overwriting the terminal. Project membership no longer prevents normal Session data from loading.
- Automatic titles preserve explicit names and exclude structured provider commentary from title text.
- Canonical system temporary paths do not trigger outside-repository prompts. Symlink escapes, explicit denies, ceilings and destructive-action checks remain enforced.

## Account connector limitations

Connector availability depends on hosted-service access and completed upstream authorization. Claude profiles require the `user:mcp_servers` grant. Set up connectors and consent in ChatGPT or Claude. Account connectors launch no native client, copy no external client's credentials, and use no desktop cookies. ChatGPT connectors use the hosted endpoint's `initialize` handshake because its `server/discover` advertises a revision its list results do not satisfy. Claude connector requests use the Claude Code client identity, including the `X-Mcp-Client-Session-Id` header the proxy requires. When a hosted catalog fails or returns a listing invalid for its negotiated MCP revision, that provider's tools are unavailable for the request, the backend log names the connector server, and prompts still run. Each catalog contains only the connectors installed and authorized in that account.

## Local upgrade

- Projects created by earlier 0.11.0 development builds are reset when the local database upgrades; Sessions and their histories are unchanged.

## Relay upgrade

- Apply the additive `0008_device_alias.sql` and `0009_push_coordination_filter.sql` D1 migrations before deploying a relay Worker that uses these fields. Existing rows receive nullable metadata; migration execution is separate from the release workflow.
