# YCoding v0.11.0

## Added

- Manage coordination groups in dedicated Projects screens in the TUI and remote web client. Assign existing Sessions across directories, edit their roles and limits, inspect queued work, leases and receipts, and explicitly arm, stop or complete a group. The CLI and Relay MCP expose the same local-runtime controls.
- Each coordination dispatch records an explicit execution agent, model and advertised reasoning variant with a one-line selection reason. Every dispatch receipt retains that choice. The active assignment uses its selected settings without replacing the worker Session's defaults.
- Coordination uses durable, fenced writer claims, dependency queues and bounded event waits. Stopping a group leaves its workers running; a backend restart requires explicit re-arm.
- Routine delegated questions, permission asks and ordinary guardrail reviews use the existing native decision paths under a centrally revocable policy. Group settings can narrow that policy. Denies, permission ceilings, hard reviews and human-only decisions retain their existing authority.
- External notification filters can limit TUI attention, web System alerts and phone push to verified coordinator Sessions and selected event categories. In-app notices, pending questions, permissions and reviews remain visible.
- Enable ChatGPT and Claude account connectors in Sessions through hosted MCP. Both providers default off and use an existing YCoding OAuth profile with per-connector allow and deny policies.
- Connector tools retain their selected account binding and recheck profile replacement, provider disablement and connector denial before dispatch. Actions ask by default and preserve permission ceilings and Session guardrails.
- Claude organization-blocked tools are unavailable. Organization-required approvals and tools requiring user interaction need a fresh human decision; saved approvals and automation cannot satisfy them.

## Changed

- Machine display names are account-owned aliases shared across browsers. Rename an owned machine inline in Settings, including while it is offline; the hostname and stable machine identity remain unchanged. Browser-local aliases are not imported, and failed saves retain the draft and confirmed name.
- Coordination instructions use the same first-person user-message presentation as typed instructions, without a separate sender persona. Authenticated origin stays in audit metadata, and message text cannot settle native controls.

## Account connector limitations

Connector availability depends on hosted-service access and completed upstream authorization. Claude profiles require the `user:mcp_servers` grant. Set up connectors and consent in ChatGPT or Claude. Account connectors launch no native client, copy no external client's credentials, and use no desktop cookies or native-client identity. Live account entitlement and hosted connector catalog access remain unverified.

## Relay upgrade

- Apply the additive `0008_device_alias.sql` and `0009_push_coordination_filter.sql` D1 migrations before deploying a relay Worker that uses these fields. Existing rows receive nullable metadata; migration execution is separate from the release workflow.
