# YCoding v0.10.17

## Added

- Fixed file, image, and HTML feasibility demo over an enabled Relay MCP connection. `artifact_demo_preview` serves an authored List/Cards preview with an isolated-frame probe; `artifact_demo_export` returns one original-byte PNG resource link with its filename, MIME type, size, SHA-256, and a 15-minute expiry. The two tools accept no Session, directory, file path, or generated HTML.
- Relay MCP transport groundwork for typed resource links, resource discovery, and authorized resource reads.
- Session-owned local HTTP app registration with explicit literal-loopback ports, route and method allowlists, bounded requests, and a generic MCP App wrapper. Public embedding requires separately configured isolated HTTPS preview origins and a compatible chat host; registration alone does not publish a service. WebSocket, SSE, and upstream cookie login are unsupported.
- MCP Events for hosts implementing Session webhook subscriptions, with signed delivery, durable local subscriptions, bounded replay, and fresh grant checks. Protected signing-key storage is required and unavailable on Windows. Actual chat-host subscription and delivery require host setup and verification.

## Fixed

- Decision helpers use strict structured output on supported provider routes and bounded recovery for malformed responses. Typed failures retain their cause instead of becoming an invented judgment, and TUI/web guardrail views distinguish those failures from an explicit model escalation.
- Keep the web Sessions sidebar steady during background refreshes: unchanged rows no longer show a "Loading more sessions" placeholder or toggle the scrollbar, and fine pointers reserve the scrollbar gutter.
- Opening and immediately closing the TUI Session rename dialog no longer focuses a destroyed input.
- On Windows, directory, Session file, and attachment containment rejects paths on other drives or UNC shares; project inventory search and pagination use native directory paths; Git checkout trust resolves short-name aliases strictly and grants no trust when resolution fails.

Update the connected machine and refresh the MCP client's tool catalog to see the demo tools.

## Demo limitations

The demo is not the general artifact pipeline. Session-scoped artifact IDs, listing, status, and export, PDF export, complete proposal bundles, and generated-HTML isolation are not implemented.

An actual chat client called both demo tools successfully, but did not present the interactive widget ("widget unavailable") and offered no way to fetch the resource bytes or create a native attachment. Interactive rendering and native file delivery are unverified and were not supported by that client; this release does not fix that client behavior or add native attachments. A resource link or inline image is not proof of a downloadable attachment.

A compiled-binary `resources/read` test returns the exact authored HTML and the 79-byte PNG with their expected hashes, and enforces expiry and unknown-resource errors. The PNG access expires 15 minutes after the connector's MCP server initializes on the first forwarded MCP request; calls do not renew it.

## Validation caveat

The local Usage dashboard benchmark exceeded its 10-second first-read budget (10.308 seconds) and its 2-second warm-read budget (2.246 seconds). This release carries an accepted performance exception; the budgets remain unchanged, and a quiet-host comparison is unverified.

The `unit` matrix (Linux and Windows) and the Windows `portability regressions` job in `.github/workflows/test.yml` are disabled until the Rust release. Those jobs do not verify this release. Windows support remains incomplete; the deferred work is recorded in `docs/windows-runtime-backlog.md`.
