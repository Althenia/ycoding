# YCoding v0.7.3

## Added

- Create remote Sessions from repositories already opened on the connected machine, including recorded directories with no existing Session. Creation stays idle until you send a prompt; an explicit retry checks the same Session ID instead of automatically creating a duplicate.
- Control macOS windows in the background without raising them, switching Spaces, or moving the system pointer. Native input briefly shifts key focus and restores it; concurrent typing can reach the target window.
- Stage supported off-Space Chromium, Electron, and WebKit windows on a private agent display for pixel input and capture. Unstage restores the window frame on the main display's current Space, not its original Space.
- Control Safari and Chrome tabs through native browser automation. JavaScript evaluation, plus Safari history and reload actions, requires **Allow JavaScript from Apple Events** in the target browser.
- Control supported Electron windows through a process-owned debug bridge. Explicit debug-enabled relaunch supports apps whose inspect fuse is disabled and leaves an unauthenticated localhost debug port open until the app quits. Application quit requests remain graceful and preserve unsaved-work prompts.
- Show a separate YCoding cursor and click ripple for Chrome agent interactions without moving the system pointer or intercepting page clicks.
- Pin Sessions on the backend. Every TUI connected to that backend and the web remote client list pinned Sessions first in pin order; in the TUI, pin or unpin from the session list with `ctrl+f` and open the first nine pins with `<leader>1` through `<leader>9`. Pinning does not change a Session's last-activity time.
- Show a download progress bar in `ycoding update`, followed by checksum verification and installation steps. Redirected output prints each step once.
- For source builds, `bun run install:local` installs the `ycoding` executable, the macOS **YCoding Computer Use** app, and the Chrome extension from `bun run build:tui` together in `~/.local/bin`. An incomplete build or an app that fails signature verification leaves the existing installation unchanged.

## Changed

- **Breaking Change:** Local HTTP requests no longer accept `auth_token` query parameters. Update integrations to send an `Authorization: Basic` header with username `ycoding` and the configured service password; remove credentials from request URLs.
- Browser and desktop actions skip guardrail review prompts. Explicit deny rules, tool permissions, and required operating-system or site authorization still apply.
- Confirm machine changes in the phone picker before switching connections. Tablet navigation keeps Sessions, Conversation, Activity, and Settings visible and lets the conversation sidebar collapse and reopen.
- Redesign usage reports and Stats. Project rows show the project name and worktree, large token values stay on one line in compact form with exact values in details, costs render without estimate suffixes, totals are shown as lower bounds when cache reads are unreported, and Models, Sessions, Projects, and Agents open sorted by total tokens. Stats renders a colored graph sized to the terminal with favorite model, Session count, streaks, active days, totals, and busiest day.

## Fixed

- Open existing remote Sessions directly in Conversation and keep unsent drafts through remote-page navigation and same-machine reconnects. Closing a creation dialog prevents late completion from changing the current route; creation from Conversation closes its dialogs correctly.
- Keep Chrome pairing codes visible, distinguish a saved pairing from a new pairing attempt, and recover saved connections after Chrome or YCoding restarts without requiring another code.
- Restore Daybreak capability discovery, show whether the selected model is actively using it, and apply a landing-screen Daybreak selection before the first prompt or goal starts.
- Preserve alternative shapes in provider tool schemas and accept JSON-encoded browser action objects without losing normal action validation.
- Click and scroll hidden Chrome tabs with page scripts instead of mouse events that Chrome discards. These actions keep the tab in the background and report scripted input; they cannot open popups, use the clipboard, or open file pickers because they carry no user activation.
- Keep valid answers that a Responses provider delivers only in its completion payload, without duplicating text or tool calls. After a transport or provider-internal failure that follows visible output, continue from durable history in a new recovery step instead of replaying the failed request. Provider error rows explain the failure category when details must stay hidden.
- Improve off-Space Electron capture settlement and window-placement detection. Keep remote header controls inside tablet viewports, contain mobile picker keyboard focus, and align the landing-page divider with the content grid.

## Security

- Enforce read approval before returning file-search contents, reject search roots that escape the active Location through symlinks, and check URL permission at every web-fetch redirect destination, with a ten-redirect limit.

## Upgrade notes

- Reload the installed YCoding Chrome extension after updating; create a new pairing code if an older pairing is not recognized. A directory absent from the remote repository picker must be opened locally once, then refreshed in the picker.
- After a macOS release update, remove the old **YCoding Computer Use** entries in Privacy & Security and allow the updated app when macOS prompts. Safari and Chrome automation also requires the corresponding Automation grants.
- On first start, the TUI moves pins saved in its local `session.json` state file to the backend in their saved order, then removes that file; pins for deleted Sessions are skipped. The database gains a pin column automatically at startup.
- New remote Sessions use the selected directory's local agent and model defaults. Drafts are kept in memory, not across a page reload or an explicit disconnect.
