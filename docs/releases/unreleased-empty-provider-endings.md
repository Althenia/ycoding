# Empty provider endings

## Fixed

- A provider response that ends without an answer or without finishing no longer fails the Session. Reasoning-only, empty, unknown-finish, and unsettled endings, including Gemini and Antigravity streams that end with finish reason `other`, previously failed with "Provider ended the response without an answer and without a finish reason" or "The provider returned no answer after text-only recovery". Each now enters the existing bounded text-only recovery, limited to one request per input, whose request no longer ends on the unfinished assistant output that providers rejecting assistant prefill answered with a request error. If the response is still answerless, an empty response with finish reason `stop` ends the turn as a silent reply, and any other ending closes its Step as `provider.invalid-output`, keeps its partial output in the transcript without resending it, and leaves the Session idle. The provider's finish reason is never rewritten to `stop`, and no answer is recorded.
- `ycoding run` exits with its ordinary status when a `provider.invalid-output` Step failure is followed by a successful run, and reports no `error` JSON line for it; text output prints the message as a dim notice. A delegated child, subagent, or Project member whose last message ended with an error reports that error message instead of its partial text, and a goal-managed Session does not start a goal continuation after it.
- A Gemini or Antigravity stream that ends with finish reason `other` and no answer is no longer retried with backoff or routed to a fallback model; it receives the recovery request. Transport, authentication, tool, and in-stream provider errors, and interruption, still fail or stop the Session.
