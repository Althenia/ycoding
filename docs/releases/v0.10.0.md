# YCoding v0.10.0

## Added

- Run different named provider profiles concurrently in Sessions and subagents without changing the provider-wide default. Authentication, model discovery, effort choices, Daybreak access, quota observations, and provider state follow the selected profile. Choose a profile in the model picker or use `profile` in a structured model configuration.
- Open the web command palette from the header or with Ctrl+K/Cmd+K. Search Session actions, configured commands, skills, navigation, and settings. The TUI palette also searches slash names and aliases and exposes more supported actions without requiring prompt focus.
- Choose One Dark, One Dark Pro, and high-contrast appearance options across the web client and TUI. Web appearance preferences persist locally and respect system contrast when using the default system appearance.
- Opt into question-option suggestions with `decisions.questions` and an explicit `min_confidence` or `min_probability` threshold. Suggestions respect permissions, bounded concurrency, and a shared timeout; normal mode keeps human choice authoritative. Agent confidence remains an uncalibrated estimate.

## Changed

- Use full-screen agent, model, machine, and workspace selectors on phones. Search and scrollable choices follow the visible viewport, and autocomplete stays above the composer when keyboard space is reduced.

## Fixed

- Reduce repeated backend work when opening and reading remote Sessions by avoiding full-inventory scans for known Sessions and reusing captured-change summaries until durable events invalidate them. Location and directory authorization remain enforced. Update the connected machine to apply these improvements.
- Keep usable custom TUI themes when another theme file is malformed, and resolve standalone-theme text roles instead of displaying missing-token colors.
- Report invalid decision requests, authentication failures, and malformed provider output distinctly, and reject empty native decision requests before sending them.

## Upgrade notes

- Update YCoding on the connected machine to use concurrent profiles and the remote performance improvements. Existing Sessions retain provider-default behavior until a named profile is selected.
- The local database upgrade preserves existing credentials and Session history. Historical account ownership is not inferred. Removing, renaming, or replacing an explicitly selected profile blocks provider work until you select an available profile again; ordinary token refresh does not require reselection. There is no automatic account rotation.
