# YCoding v0.10.0

## Added

- Run different named provider profiles concurrently in Sessions and subagents without changing the provider-wide default. Authentication, model discovery, effort choices, Daybreak access, quota observations, and provider state follow the selected profile. Choose a profile in the model picker, or write one in a model string with `profile#provider/model#variant`, for example `Work#openai/gpt-6-luna#high`; an omitted profile uses the provider default.
- Select a provider, model, and profile from the web command palette, and connect a provider profile on the selected machine with a key or a remote-capable sign-in. Keys and manual authorization codes pass through the authenticated relay to that machine. Connecting makes the profile that provider's default and does not change a Session's explicit selection; login methods that need a local browser say so. The provider connection dialog marks the default profile as **Default profile** and offers **Make `<name>` the default** for other stored profiles.
- Open the web command palette from the header or with Ctrl+K/Cmd+K. Search Session actions, configured commands, skills, navigation, and settings. The TUI palette also searches slash names and aliases and exposes more supported actions without requiring prompt focus.
- Choose One Dark, One Dark Pro, and high-contrast appearance options across the web client and TUI. Web appearance preferences persist locally and respect system contrast when using the default system appearance.
- Capture meetings locally with consent-gated audio capture, configurable local Thai transcription, native TUI review, and approval-gated MCP knowledge proposals. Run `ycoding meeting [directory]` from the installed executable to start a private server and open the **YCoding Meeting** live page on the loopback address, with transcript, summary, findings, Ask AI, pairing, stop, and retry controls; `--no-open` prints the page address instead. The live page captures the meeting tab's audio; each Start asks for fresh consent and policy acknowledgement, and Chrome's share picker must include tab audio. Microphone capture is optional. **Ctrl+C** stops and finalizes an active recording. The `/meeting` TUI commands still require the source launcher. When speech recognition fails, Meeting stops recording and keeps the audio and transcript so far; use **Retry failed audio** or `/meeting retry`, then press Start again with fresh consent.
- Give a machine a browser-local display name in Settings → Machine. The alias appears in the machine picker, the Devices table, the command palette, and the desktop rail while the relay hostname stays visible; it never leaves the browser.
- Hide the composer in Session detail. A named toggle collapses the dock to a one-row handle that keeps the status pill; a new Session, an arriving request, or a palette draft expands it again, and the choice persists per browser.
- Office agents work and rest like a team. Research reads at its reference spot, verification checks at the QA desk or device rack, and coordination points at its board. Idle members take finite, varied breaks: a desk stretch, a pantry stop, a seated rest, or table play; two or three idle peers occasionally gather beside the meeting table; movers yield politely on shared corridors. Every label still comes from a backend fact, and any work, attention, or unavailable fact ends a break at once.
- Hover or click an Office object on the map to see its name, room, state, and who is using it. Agents use the bookshelf, whiteboard, desk, device rack, and coffee machine according to their real Session activity; decor varies per desk and lighting follows the time of day.
- Pin subagent tasks so they stay first. Press `p` in the TUI Subagents list (`session_task_pin_toggle`) or use **Pin** in web Team; pinned tasks are grouped first in the order you pinned them.
- Create and list Git worktrees from an agent with the `worktree` tool. A new worktree gets its own branch under `~/.local/share/ycoding/worktrees/`, needs the `worktree` permission (ask by default), and passes guardrails. Files inside a worktree that Git lists for the current repository no longer ask for outside-directory access.
- Save usage, speed, and latency on your own machine after you agree. An undecided machine shows **Help improve YCoding** in the TUI and the web workspace; change it later with **Telemetry: on/off** in the TUI or **Save telemetry on this machine** in Settings → Diagnostics. With consent, each provider request records time to first output, total time, and retry wait, and the TUI and web record prompt, live-update, and transcript-load timings. Samples stay in the machine's local database for 30 days; the relay keeps nothing. Usage reports add first-output and total time (p50/p95) and output tokens per second, and show unknown values as unreported.
- Find text in the loaded TUI transcript history with `ctrl+shift+g` or **Find in loaded history**. Matches show `n of m`; Enter or Down moves forward, Shift+Enter or Up moves back, and Escape closes Find without moving the transcript.
- Get a suggestion for your next message after each settled reply on an idle main Session. Prediction is enabled by default from recent conversation text; set `prediction.enabled` to false to disable it. With `prediction.memory` on and the agent allowed to read memory without asking, the helper also sees bounded snippets from project and shared workspace memory. Choose its model with `efficiency.helper_models.prediction`; its requests appear in usage as `prediction`. Press Tab in an empty TUI or web composer to fill it without sending; Right arrow also accepts it, `prompt.prediction.accept` rebinds the TUI shortcut, and the web keeps **Use suggestion**. Accepting never sends or replaces typed text. Suggestions support 2–40 words and up to 400 characters; Tab keeps normal behavior when no suggestion is shown. Dismissing a suggestion keeps it dismissed across Session navigation, a late result never replaces a newer suggestion, and predictions with bidirectional marks or Unicode line or paragraph separators are never shown.

## Changed

- Use full-screen agent, model, machine, and workspace selectors on phones. Search and scrollable choices follow the visible viewport, and autocomplete stays above the composer when keyboard space is reduced.
- Navigate the web client through one Focus workspace. Sessions, Usage, and Settings live in a collapsible desktop rail and a three-item labeled phone bar; New session is an explicit action, Session detail pins its title and Back action above the transcript, and a contextual Resume session link returns to the selected Session from other screens. Routes, Session URLs, drafts, approvals, and runtime operations are unchanged.
- Sessions, Usage, and Settings widen their content column to 1600px from the expansive breakpoint. The web conversation uses up to 120 characters of width on wide screens, and assistant transcript text fills that column on desktop and mobile.
- The web Usage page refreshes quotas from a compact icon button that spins while quotas reload and stays still under reduced motion.
- The web model control's lightning button opens offered same-provider **Standard**, **Fast**, and **Ultrafast** choices. Switching preserves the provider's model ID and the selected profile, keeps effort only when offered by the target, and otherwise omits the effort override. Unavailable profiles remain blocked rather than switching accounts.
- Cursor's known reasoning efforts display as **Low**, **Medium**, **High**, and **Extra High** without redundant model, speed, or context prefixes; requests retain the raw offered variant. The compact **Profile · Default ›** row opens profile choices in the same model panel and keeps unavailable-profile warnings. Pending choices still apply with the next send.
- The web reasoning slider's decorative motion runs for about four seconds when opened or when the selection changes, then settles. Reduced-motion mode keeps the decoration static.
- Explicitly selected helper and subagent models without a profile use the provider default instead of inheriting their parent's profile. Selecting the parent's whole model keeps its profile.
- **Make … the default** in the TUI provider dialog closes the dialog and confirms without waiting for the profile, model, and provider lists to refresh in the background.
- YOLO levels are reordered. YOLO 1 auto-approves permission asks and ordinary guardrail reviews, and YOLO 2 also answers questions and forms. YOLO 3 behaves like YOLO 2. Hard reviews always need you. Sessions keep their saved level, so a Session already at YOLO 1 now auto-approves permissions and ordinary reviews.
- The TUI AUTONOMY section shows who decides Permissions, Guardrails, and Questions (`ask you`, `auto`, or `auto · goal`), and a `decision` tool call appears as one short row.
- Guardrails have two tiers. Hard reviews, which always need you, cover destructive actions: deleting the project, a folder above it, or a folder directly inside your home folder; `git reset --hard`, `git clean -f`, `git checkout -- .`, `git restore --worktree`, and `git branch -D`; force push; and destructive database statements. Deleting the filesystem root, any user home, or a system directory is denied. Ordinary reviews, which YOLO 1 and higher approve automatically, cover only work outside the repository: edits, writes, patches, and shell commands that change into or name a path outside it. Work inside the repository, this repository's managed worktrees, and temporary folders never triggers a review, and read-only commands are never reviewed. Recursive deletion of temporary paths and of several ordinary targets is not reviewed. Publishing, production deploys, security changes, and MCP execution do not trigger guardrails; tool permissions still apply.
- Decisions happen only when an agent calls the `decision` tool, which main Sessions, subagents, and side chats can use unless a permission ceiling denies it. The tool runs on the built-in decision agent. Invalid requests name the field, the allowed values, and a corrected example. When the evidence does not support an answer, the judge abstains and the result tells the agent to gather the missing evidence or ask you. Decision-agent calls are not limited by a configured deadline; cancellation still works.
- Built-in primary agents act as orchestrators: they split work into bounded tasks and run subagents in parallel, choose each subagent's model from the active provider and always set its variant, sizing the tier by the task's size, difficulty, complexity, and risk, and use the `decision` tool for judgments the evidence cannot settle.
- Configuration recovery keeps valid settings and drops unknown or removed keys and the smallest schema-invalid unit, which can be a whole named MCP server, provider, command, or reference. `GET /api/config/diagnostics` and the TUI Status dialog list each affected JSON path, and the server logs why a document was ignored. Invalid permission rules become denies, and invalid `guardrails` keep guardrails enabled with default limits; both are marked **fails closed**. Files with invalid JSON or JSONC are skipped.
- Opening, resuming, or reconnecting a Session in the TUI keeps its header, transcript area, composer, and footer on screen instead of showing a full-screen waiting view. The header shows **Connecting…**, **Loading session…**, or **Reconnecting…**; you can type a draft right away, and sending waits until the Session is connected and loaded.
- The TUI loads a Session's newest 100 messages first and fetches older ones as you scroll up, keeping your place. Scrolling up, revealing rows, and compaction do not leave a stale "newer history" marker, and the TUI does not auto-load older history while following at the bottom. At most 400 transcript rows are drawn at once. Copy and export include the whole transcript; Find, Fork, and Timeline work on the history loaded so far. Captured-change totals mark unread older child history as incomplete without an earlier-changes notice or command.
- Prompts show a receipt beneath the bubble. The web shows a static receipt: **Sending** until the prompt is admitted, **Processing** while the Session is running, **Queued** for queued input, and **Sent** or **Read** when the Session is idle. The TUI animates a dot trail while sending, shows `✓` once the prompt is admitted (`✓ Queued` for queued input), and `✓✓` once the model has read it, both while running and after the Session settles.
- The TUI Home and Session shell becomes usable without waiting for optional plugins or MCP initialization. Built-in enable/disable selectors settle first, and Status shows plugin loading and failures. Initial MCP authentication requirements and failures stay in MCP and Status instead of corner toasts; later failures and authentication transitions still alert you.
- The web app reuses up to 32 resolved image sources within an 8 MiB data-URL text budget, evicting least-recently used sources. Mounted previews and open full-size views keep their image; evicted sources can be fetched again. This is not a decoded-bitmap memory cap.
- Running YCoding from a source checkout works with any current Bun release; the repository no longer pins a Bun version. Native executables include precompiled Bun bytecode.
- Only one background service can use a database at a time. The `latest`, `beta`, and `prod` channels share `ycoding.db`, so a second channel's service exits instead of running alongside the first.
- Each `location services booted` log line includes a `stages` map of per-service startup times. The remote connector logs its state changes and failure causes, including which sign-in step the relay rejected and its HTTP status, without credentials.

## Fixed

- Remote web requests no longer wait on each other in the relay: independent requests are authorized without holding one another back. Reads, including several reads of one Session, proceed independently; mutations keep arrival order per Session; a cancel waits only for its own request; and agent responses are not held behind status or event processing. Every request is still authorized.
- Reduce repeated backend work when opening and reading remote Sessions by avoiding full-inventory scans for known Sessions and reusing captured-change summaries until durable events invalidate them. Location and directory authorization remain enforced.
- Keep Claude Code and OpenAI (ChatGPT and Codex) sign-ins connected when another YCoding process on the same machine has already refreshed them; YCoding uses the newer stored sign-in instead of failing. The ChatGPT quota card refreshes an expiring sign-in before reading usage instead of showing unauthorized.
- Setting a goal from the web composer no longer shifts the YOLO and Goal controls or draws over the attach button; the Setting goal indicator stays inside the status slot.
- Keep usable custom TUI themes when another theme file is malformed, and resolve standalone-theme text roles instead of displaying missing-token colors.
- Report invalid decision requests, authentication failures, and malformed provider output distinctly.
- Read complete file paths in web composer suggestions. Paths use the available row width and wrap on narrow screens instead of being cut off beside empty space; keyboard and pointer selection keep the full path.
- Keep the tool's own message when `edit`, `shell`, or another tool fails. A failure without a session error type, such as "File changed after permission approval. Read it again before editing.", reaches the transcript as a `tool.execution` error with that text instead of a blank `unknown` error.
- `ycoding --continue` opens the most recent Session, and a resumed TUI Session keeps its own agent, model, profile, and effort. Choices made on Home apply to the next new Session, and sending keeps the draft with a warning until the Session's catalogs load.
- The TUI subagents panel updates on cancel and completion without reopening.
- Subagents no longer show as failed after a background-service restart once they are resumed, started again, or finished. Startup records interrupted subagents as lost once, never restarts their model work, and flags the parent Session for attention; the lost notice is delivered the next time the parent runs.
- The TUI no longer keeps memory for every finished run's notification, for closed Sessions beyond the 50 most recent, or for live updates to Sessions you never opened.
- The same project folder written two ways, such as a path that leaves and re-enters it through `..`, no longer starts a second copy of that project's services.
- The remote connection recovers from connections that stop responding, gives up a stalled browser connection attempt after 30 seconds, cancels timed-out browser requests so they stop counting against the relay's request limit, shares one read when **Retry catalog** is pressed repeatedly, and rejects requests for Sessions whose project folder no longer exists before starting anything there. A request that may already have been sent is reported as unknown and never sent again automatically.
- The TUI no longer runs the same list refresh twice at once, and an older result can no longer overwrite newer data.
- Web confirmation dialogs indent their text and buttons to match the dialog title.
- A local MCP server whose working directory is missing fails with `Working directory does not exist: <path>` instead of a misleading `ENOENT … posix_spawn` error, and every `mcp connect failed` log line names the project directory and, for local servers, the working directory.
- A skill that is already active no longer flashes a Loading skill row in the TUI.
- A running Edit appears as a compact row and shows its captured changes as soon as it finishes, even while a parallel command is still running, and background subagent launches no longer leave blank lines in the TUI transcript.
- Office agents no longer turn grey with "Update YCoding on this machine to show agent activity" after one slow activity read, and selecting another agent no longer makes the Office flicker or reset positions.
- Settings account rows keep their inline padding inside the bordered card.
- The Running and recent carousel drags with the mouse and no longer leaves a focus ring on a card opened by click.
- Startup checks background-service readiness more frequently during the initial wait without shortening the backoff between server spawn attempts.
- Preparing model history after validated local compaction reads only the retained suffix before decoding messages. Canonical transcript export and snapshot history remain intact.

## Upgrade notes

- Update YCoding on the connected machine to use concurrent profiles, web provider connection, the new model selector syntax, the remote performance improvements, and the connector changes. Existing Sessions retain provider-default behavior until a named profile is selected.
- The local database upgrade preserves existing credentials and Session history. Historical account ownership is not inferred. Removing, renaming, or replacing an explicitly selected profile blocks provider work until you select an available profile again; ordinary token refresh does not require reselection. There is no automatic account rotation.
- Remove the `decisions` configuration section, including `decisions.advisory`, `decisions.questions`, `decisions.scoping`, and `decisions.guardrails`. A configuration file that still contains it loads with that section dropped and one configuration diagnostic.
