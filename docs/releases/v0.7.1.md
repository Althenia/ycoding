# YCoding v0.7.1

## Added

- Pair Chrome from the Mini or full Session and use eligible open profile tabs, including the active tab. Open Session-owned background tabs separately; group or ungroup eligible inactive profile tabs. Observations and captures stay bounded by site permissions and browser fences.
- Inspect, capture, and act on one explicitly targeted running macOS app window. Accessibility actions can press controls, set text, scroll, and confirm; window capture requires Screen Recording authorization. Desktop operations retain fresh hard human review.
- Record Runpod Ollama cached-input counts and request timings in Session usage when the worker reports them, without treating missing reports as zero.
- Include refreshed model catalog pricing and Muse Spark entries, including Muse Spark 1.3 and its contributor model.

## Changed

- Read, scroll, and capture paired Chrome tabs with site read permission but without a standard hard profile-access review. Profile mutations still require site permissions and fresh hard human review; owned tab opens and desktop operations retain their hard reviews.
- Package the signed YCoding Computer Use app alongside the macOS CLI and native helper. Installation and self-update replace or roll back the three components together. Accessibility and Screen Recording grants may need renewal after an ad-hoc signed update.
- Accept installed Chrome version 152 or newer for temporary isolated browsing on macOS arm64, subject to startup capability checks.
- Keep eligible model-visible tool definitions stable across provider-cache requests without promising a cache hit. The GSD agent can implement directly or delegate independent work and verify the result.
- **Breaking Change:** The paired Chrome extension uses bridge protocol 3 and `/api/browser/connect`. Run it with the matching local backend, reload the unpacked extension, and re-pair if its stored connection is lost. Pairing now requests tab and tab-group metadata permissions. Approved site actions may indirectly trigger downloads.

## Fixed

- Keep the Session header's model and variant in sync with selection, show a pending default variant when cycling, and skip non-selectable variants.
- Use the returned Session ID when starting a goal from the landing screen.
- Restore eligible paired-tab access after a Chrome bridge reconnect and clean up incomplete pairing attempts.
