# YCoding v0.11.10

## Fixed

+ The web Dots connection dialog no longer flickers while it refreshes every five seconds. Connect or Disconnect, Refresh, and the attach control stay usable and the status text stays in place during a background refresh, which is announced to assistive technology instead. A confirmation to use this computer for Dots tasks stays open through refreshes and closes only when the computer, access, connection or read actually changes.
+ Reading Dots status no longer outlasts the web request. The check of your Dot's computers finishes within 20 seconds and otherwise reports that your Dot's computers could not be read; it never reports a computer as attached or detached from a read that did not finish. Status reads and access changes allow 30 seconds and attaching a computer allows 90 seconds, so a slow read no longer turns Connect into a timeout. When a change's outcome is unknown, the dialog reads the current state again and never repeats the change.
+ Pending permission, guardrail, question, Form and review requests keep reaching a connected native Dots client after a temporary failure. A failed read of pending decisions no longer stops later requests for that Session on the connection, is retried after 1, 2, 4, 8 and 16 seconds, and no longer reports a request that is still pending as resolved.

## Limits

+ The native Dots connection delivers requests only while it is open, and Dots can read pending decisions with `ycoding decision watch`. This release does not change or verify delivery to an idle Dots conversation.
+ Each request is sent once per connection. A client that reconnects receives every decision that is still pending, not notifications it missed while disconnected.
+ After the fifth failed retry, pending requests for that Session arrive with its next event.
