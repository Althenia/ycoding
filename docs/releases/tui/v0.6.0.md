# YCoding v0.6.0

## Changed

+ **Breaking Change:** Running `ycoding remote connect` grants the authenticated device owner access to every existing and future Session on that backend. Per-Session `remote allow` and `remote deny` commands are not supported. Stop the connector to end remote access to the backend.
+ **Breaking Change:** Upgrade installed connectors and refresh browser tabs for the coordinated remote protocol update. Existing device enrollments and browser sign-ins remain valid; re-enrollment is not required unless a credential has independently expired or been revoked.
+ Rework the public landing page and remote workspace for desktop, tablet, and mobile, with custom device, delivery, and autonomy menus.
+ Present notification preferences as five event categories with independent workspace and desktop channels. Desktop notifications require browser permission and an open page; there is no background push.

## Fixed

+ Discover all backend Session pages and refresh the list when Sessions are created, moved, or deleted.
+ Report device availability from the live connection, keep offline and revoked records in Settings, and preserve the selected machine when it becomes unreachable instead of silently choosing another.
+ Distinguish account loading, unavailable devices, and a connected backend with no Sessions.
+ Restore live Session subscriptions when the local connector is replaced, and release them when a browser disconnects.
+ Stop forwarding Session events for expired or revoked browser subscriptions rejected during relay restoration.
+ Recover the Session inventory stream even when no Session is selected.
+ Keep Session status chips inside their rows and make custom menus keyboard-accessible and viewport-bounded.

## Upgrade

+ Stop existing remote connectors, upgrade YCoding, refresh the remote workspace after deployment, and restart `ycoding remote connect` using the existing enrolled identity.
+ Model, tool, shell, file, and Session execution remain on the connected machine. The browser cannot choose an arbitrary backend working directory, and uncertain mutation outcomes are not automatically replayed.
