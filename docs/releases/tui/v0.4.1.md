# YCoding v0.4.1

## Added

- Separate Daybreak Blue and Daybreak Red model entries for ChatGPT connections whose authenticated model catalog explicitly advertises those access programs.
- Discover MCP-served skills through the Skills extension without eagerly reading their content. Load approved skills and supporting resources lazily, with manifest-bound permission, size, digest, and frontmatter verification.
- Deliver ntfy attention from Session lifecycle events when notification configuration is enabled and the effective permission already allows it. Requests resolved within the 500 ms checkpoint remain silent. Global MCP forms retain local TUI alerts only.

## Fixed

- Keep routine subagent completion and active-goal settlement silent, while preserving alerts for pending human input and top-level completion. Retained exhausted goals do not replay an error alert for later ordinary work.
- Preserve terminal goal labels when a Location first loads, and suppress an automatic successful-terminal ntfy post when an explicit ntfy call already succeeded during that execution.
- Compaction refreshes protected live state after helper generation, so background task updates during summarization do not discard useful work and repeat helper requests. Transaction-time protection still rejects changes before activation.
- Replace stale authoritative snapshots across scalar and collection checkpoint fields during repeated compaction, preserving unrelated continuity text.
- Isolate malformed model-catalog entries so valid Daybreak availability from other entries is retained.
- Reconnecting the TUI preserves execution events received while active Session status is loading. A delayed snapshot cannot revive a finished Session, hide newly started work, or overwrite status restored by a newer connection.
- Namespaced MCP commands do not prevent managed skills, commands, and agents from refreshing.
- Repeated managed skill, command, and subagent invocations use their durable invocation boundaries instead of colliding at boundary zero. Exact retries retain stable activation timestamps.
