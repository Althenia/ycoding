# YCoding v0.11.5

## Added

+ Native Dots task admission and typed decisions use private server-process Channels. Live turns stream assistant text and canonical Session execution events, with distinct completed, failed and interrupted outcomes.
+ Persistent Session-family Dots access: existing roots default off, native-created roots are enabled atomically, and children inherit. The root Session's TUI and web command palettes offer **Enable Dots access** and **Disable Dots access** with revision checks.

## Changed

+ **Breaking Change:** incoming Relay MCP/OAuth, webhook Events, `local.app` tools, `artifact.demo` tools and old Dots peer controls are retired, including `ycoding remote mcp`, `/dots` and the old send/pause/resume/report tools. Replace that connection setup with global `dots.enabled: true` and `dots.profile` naming an exact OpenAI OAuth profile, then enable access for each existing root Session. Project configuration cannot enable Dots or replace its pinned account. Ordinary browser Remote, configured outbound MCP and Task MCP remain available.
+ Native decisions require the exact typed candidate and current source/revision. YCoding permissions, explicit denies, ceilings, guardrails and autonomy remain authoritative; ownership, archive state, account replacement, access revocation and connection retirement invalidate stale authority. Unknown outcomes are not replayed automatically, and prompt text cannot settle a decision.
+ A parent can select a directly owned child's model regardless of causal input origin. Direct ownership, effective permission, final deny, revision and logical Step-boundary checks remain enforced; the switch does not interrupt or replay work.

Global configuration example; replace the profile name with an existing OpenAI OAuth profile:

```json
{
  "dots": {
    "enabled": true,
    "profile": "<OpenAI OAuth profile>"
  }
}
```

## Fixed

+ Usage speed percentiles batch repeated histogram updates while preserving exact results.

## Limits

+ Large Usage dashboards can still exceed the two-second warm-read target.

+ Native approval, reviewer and sandbox labels are adapter-specific, not strict Codex policy equivalence. They describe surfaced typed reviews and no Codex-enforced OS sandbox, not unrestricted YCoding authority or every automatic decision. Non-null model, provider, approval, reviewer, sandbox or configuration overrides reject before effects, including matching values; null or omitted fields preserve defaults. Resume and turn requests cannot change the recorded directory. Exact external ChatGPT decoder compatibility is unverified.
+ Historical text is a transcript-summary projection of actual user and assistant messages, excluding internal system, synthetic and compaction records without relabeling them. A completed summary means its stored projection is complete, not original execution success; pruning can remove those old outcome associations. Live execution statuses use canonical events. Unrecorded metadata remains unknown or null. Stored history and retention policy are unchanged, and no lost execution outcome is reconstructed.
