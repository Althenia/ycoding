# YCoding v0.10.6

## Added

- Get an opt-in suggestion for your next message. With `prediction.enabled`, a helper model proposes a short follow-up after each settled reply on an idle main Session; accept it with Right arrow in the TUI (`prompt.prediction.accept`) or Right arrow or **Use suggestion** in the web composer. Accepting fills the draft and never sends or replaces typed text. When `prediction.memory` is on and the agent may read memory without asking, the helper also sees bounded snippets from project and shared workspace memory. Choose its model with `efficiency.helper_models.prediction`; its requests appear in usage as `prediction`.
- Find text in the TUI transcript with `ctrl+shift+g` or **Find in transcript**. Matches show `n of m`; Enter or Down moves forward, Shift+Enter or Up moves back, and Escape closes Find without moving the transcript.
- Pin subagent tasks so they stay first. Press `p` in the TUI Subagents list (`session_task_pin_toggle`) or use **Pin** in web Team; pinned tasks are grouped first in the order you pinned them.
- Create and list Git worktrees from an agent with the `worktree` tool. A new worktree gets its own branch under `~/.local/share/ycoding/worktrees/`, needs the `worktree` permission (ask by default), and passes guardrails. Files inside a worktree that Git lists for the current repository no longer ask for outside-directory access.
- Save usage, speed, and latency on your own machine after you agree. An undecided machine shows **Help improve YCoding** in the TUI and the web workspace; change it later with **Telemetry: on/off** in the TUI or **Save telemetry on this machine** in Settings → Diagnostics. With consent, each provider request records time to first output, total time, and retry wait, and the TUI and web record prompt, live-update, and transcript-load timings. Samples stay in the machine's local database for 30 days; the relay keeps nothing. Usage reports add first-output and total time (p50/p95) and output tokens per second, and show unknown values as unreported.
- Inspect Office objects. Hover, click, or pick from the keyboard list to see an object's name, room, state, and who is using it. Agents use the bookshelf, whiteboard, desk, device rack, and coffee machine according to their real Session activity; decor varies per desk and lighting follows the time of day.
- Run Meeting from the installed executable with `ycoding meeting [directory]`. It starts a private server with the meeting runtime, arms a meeting, and opens the **YCoding Meeting** live page on the loopback address, with the transcript, summary, findings, and Ask AI alongside pairing, stop, and retry controls; `--no-open` prints the page address instead. **Ctrl+C** stops and finalizes an active recording. The `/meeting` TUI commands still require the source launcher.

## Changed

- YOLO levels are reordered. YOLO 1 auto-approves permission asks and ordinary guardrail reviews, YOLO 2 also answers questions and forms, and YOLO 3 also allows automatic subagent dispatch from the `scope` tool. Hard reviews always need you. Sessions keep their saved level, so a Session already at YOLO 1 now auto-approves permissions and ordinary reviews.
- The TUI AUTONOMY section shows who decides Permissions, Guardrails, Questions, and Scope dispatch (`ask you`, `auto`, or `auto · goal`), and a `decision` tool call appears as one short row.
- Guardrails have two tiers. Hard reviews, which always need you even at YOLO 3, cover destructive actions: deleting the project, a folder above it, or a folder directly inside your home folder; `git reset --hard`, `git clean -f`, `git checkout -- .`, `git restore --worktree`, and `git branch -D`; force push; and destructive database statements. Ordinary reviews, which YOLO 1 and higher approve automatically, cover only work outside the repository: edits, writes, patches, and shell commands that change into or name a path outside it. Work inside the repository, this repository's managed worktrees, and temporary folders never triggers a review, and read-only commands are never reviewed. Publishing, production deploys, security changes, and MCP execution no longer trigger guardrails; tool permissions still apply. The optional `decisions.guardrails` risk check runs only for work outside the repository, where a confident low-risk judgment lets the action through.
- Built-in primary agents act as orchestrators: they split work into bounded tasks and run subagents in parallel, choose each subagent's model from the active provider and always set its variant, sizing the tier by the task's size, difficulty, complexity, and risk, and use the `decision` tool for judgments the evidence cannot settle.
- Running YCoding from a source checkout works with any current Bun release; the repository no longer pins a Bun version.
- Task advisories recommend only a model and a tool. Remove `decisions.advisory.directions` from your configuration after updating; a file that still contains it is ignored as a whole and listed in configuration diagnostics.
- The web conversation uses up to 120 characters of width on wide screens, while message paragraphs keep a readable line length.
- The web Usage page refreshes quotas from a compact icon button that spins while quotas reload and stays still under reduced motion.
- When speech recognition fails, Meeting stops recording and keeps the audio and transcript so far instead of retrying automatically. Use **Retry failed audio** or `/meeting retry`, then press Start again with fresh consent.

## Fixed

- Generation speed counts only output streamed during its measured window, so models that stream a reasoning summary, fold thinking into their output, or answer with tool calls no longer show impossibly high tok/s. The speed trend shows only the current model and variant. Speed is unreported instead of inflated for Anthropic models with thinking on, whose output count includes thinking generated before the first streamed text.
- A skill that is already active no longer flashes a Loading skill row in the TUI.
- A running Edit appears as a compact row and shows its captured changes as soon as it finishes, even while a parallel command is still running, and background subagent launches no longer leave blank lines in the TUI transcript.
- Office agents no longer turn grey with "Update YCoding on this machine to show agent activity" after one slow activity read, and selecting another agent no longer makes the Office flicker or reset positions.
- Setting a goal from the web composer no longer shifts the YOLO and Goal controls or draws over the attach button; the Setting goal indicator stays inside the status slot.
- Turning on the microphone in YCoding Meet capture opens a YCoding tab that asks for microphone access, because Chrome cannot show that prompt from the toolbar popup; an expired pairing code tells you to start the meeting again.
- OpenAI (ChatGPT and Codex) sign-ins stay connected when another YCoding process has already refreshed them; YCoding uses the newer stored sign-in instead of failing. The ChatGPT quota card refreshes an expiring sign-in before reading usage instead of showing unauthorized.
