# YCoding v0.3.0

## Added

- A provider can hold several named profiles: multiple accounts or multiple API keys for the same provider. A profile is the stored credential's user-facing name. Connecting asks for that name (`/connect`, the command palette's `Connect integration`, or the model selector's connect action), and re-using a name updates that profile instead of replacing the provider's credentials. Exactly one profile per provider is active: it is the one a model request resolves, the one provider usage reports, and the one named in the session header and model selector. Switching the active profile keeps the others, and removing the active profile promotes the remaining one. A provider with a single profile reads exactly as before.
- The native desktop client ships as a platform archive attached to the same GitHub Release as the CLI. The maintained installer adds it only when asked (`install.sh --office`); macOS installs `YCoding Office.app` from the disk image into `/Applications` when writable and `~/Applications` otherwise (`YCODING_OFFICE_DIR` overrides), Linux places the executable and data pack beside `ycoding`, and Windows ships a client ZIP alongside the terminal ZIP.
- The desktop client answers keyboard shortcuts with the platform modifier (Cmd on macOS, Ctrl elsewhere): show or hide the sidebar and prompt composer, reduce motion, open the source drawer for the selection, switch light and dark panels, enlarge interface text, and select the next or previous session. While the caret is in the composer only Escape is acted on, so a shortcut never takes a keystroke from the text being written.
- Interface text scale is bounded to 100–200% in steps and cycles; out-of-range requests clamp, a corrupt stored value falls back to 100%, and the scale enlarges text and panels without magnifying the office art.
- The desktop client attaches to a running `ycoding` service for live sessions with a reference composer and reload, and works offline with synthetic playback otherwise. Blocked-session, model, and drawer workflows run against the live session and model-catalog contracts.
- The TUI composer pastes a clipboard image with Cmd+V exactly like Ctrl+V: the gesture reads the host clipboard directly and attaches it as `[Image N]` instead of inserting nothing.

## Fixed

- Automatic update works again. The background update check resolved the newest version from the npm registry and installed it with a package manager, but `@ycoding-ai/cli` is not published there, so every check failed with `Update check failed with status 404` and logged `automatic update failed`. The check now resolves the newest release from GitHub Releases and installs it with the same checksum-verified release installer that `ycoding update` uses, and it runs only after the background service is running or attached because the release install replaces the executable that service spawns from.
- Interrupting a Session while a provider retry is in backoff now settles it. The pending step publishes its terminal event, so the transcript row closes and the header leaves the working state instead of staying pinned at "cooking".
- An ordinary multi-line user prompt renders whole. The bubble preview was measured in source lines, so a prompt with two or three lines showed only its first; the preview now bounds the rows the bubble actually paints, which still caps a pasted document while leaving a normal prompt intact.
- A model request to the `opencode` or `opencode-go` provider carries `x-opencode-session` set to the Session ID, the stable per-conversation identifier those gateways use for routing and prompt caching. Other providers receive no such header, and the value is never a credential.
- Desktop presence, projection, and team-row behavior render the corrected session state.
- The TUI composer no longer drops a Cmd+V image paste on macOS; Ctrl+V, empty bracketed paste for an image-only clipboard, and pasted file-path attachment behavior are unchanged.

## Changed

- OpenCode Zen's anonymous free tier is no longer presented as usable. The gateway rejects it for every client identity, including the official one, so the runtime stops injecting the `public` sentinel and disables every OpenCode model without a real credential, instead of advertising access that could only fail with a 403.
- `Credential.create` no longer replaces every credential for an integration: it inserts or updates one profile by `(integration, label)` and makes it active. The stored `credential.active` column carries the selection and already exists in every database, so no migration runs.
- The `credential.activate` Protocol operation (`POST /api/credential/:credentialID/activate`) makes one stored credential the active profile for its integration. `Connection.CredentialInfo` gains a required `active: boolean`. Both changes are additive; generated clients are regenerated and no stored data changes meaning.
- The `autoupdate` policy is unchanged: `false` disables the check, and major releases are never installed automatically.
- The desktop client is a presentation surface over the existing public service contracts and owns no execution authority; the CLI/TUI path remains the proof path for session, prompt, tool, permission, subagent, skill, artifact, cache, and transcript behavior.

## Limitations

- A downloaded desktop bundle is not notarized: macOS may refuse it as coming from an unidentified developer until allowed deliberately in System Settings → Privacy & Security. Building with `apps/office/tools/build-release.sh` avoids the warning.
- Published native archives use the Bun TUI runtime. Node SEA builds are not included in this release's distribution workflow.
