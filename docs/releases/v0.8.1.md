# YCoding v0.8.1

## Changed

- The relay admits 120 browser requests per 10 seconds per connection instead of 30, so opening a Session, visiting Usage and Settings, and the warm-up reads behind them fit in one window without queueing.
- Remote views no longer go blank while their reads are in flight: Usage, Settings, and New session render their frame at once and keep the previous data visible while a refresh runs.
- Usage reads are keyed by day and time zone and stay fresh for a minute, so returning to Usage shows the cached report immediately and refreshes it in the background instead of refetching everything.
- Hovering, focusing, or touching a remote navigation link preloads that view's reads, and the Usage, keep-awake, and workspace reads warm up once after the selected Session is ready, so the first visit is instant.
- The cold load at `/remote` shows the loading placeholder until the Session list arrives instead of flashing the New session composer first, and no longer issues duplicate workspace and Session list reads.

## Upgrade notes

- Run `ycoding update` on each machine, then reload the remote workspace or reopen the installed web app. The raised request budget is enforced by the relay; an older relay still closes a browser that exceeds 30 requests per 10 seconds, so deploy the relay and the web client together.
