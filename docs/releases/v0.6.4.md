# YCoding v0.6.4

## Added

+ Register a custom OpenAI-compatible endpoint from the command palette (the `provider.custom-endpoint` action or the `/custom-endpoint` slash command). Provide the endpoint base URL, choose `chat` or `responses`, and optionally a provider id and API key; the entry is written to your configuration file as a `providers` entry with `settings`.
+ Select the OpenAI-compatible request surface (`chat` or `responses`) in configuration with `providers.<id>.settings.api` or a per-model `providers.<id>.models.<id>.api`. The value resolves after the source-code default and the catalog, and a model entry overrides the provider setting, so explicit configuration always wins.

## Fixed

+ Resolve a Session that selects the `none` model variant to its base model instead of reporting the variant as unavailable.
