# YCoding v0.8.2

## Added

- A built-in `cursor` provider runs models from a Cursor subscription. Connect it with `ycoding auth login` (or `/connect`) through Cursor's browser sign-in, a `crsr_` API key, or `CURSOR_API_KEY` in the environment. Use it only with a Cursor account you own: it speaks Cursor's private agent protocol, which Cursor may change or restrict without notice.
- YCoding discovers the account's Cursor models when the connection starts or changes. Each model's effort, thinking, and Fast choices are its variants, long-context options appear as a separate `<model>-1m` entry, and Composer and Grok expose separately priced `<model>-fast` entries.
- Cursor runs use YCoding's own tools, permissions, and guardrails. A failed or rejected tool result reaches Cursor as an error, and usage Cursor does not report stays unreported instead of showing as zero.

## Upgrade notes

- Run `ycoding update` on each machine. On the first run after connecting, `ycoding run --model cursor/<model>` can report the model as unavailable until model discovery finishes; the TUI and later runs use the cached model list.
- Cursor-native requests that have no YCoding tool (interactive background-shell input, image generation, native web, pull-request, source-control, and MCP-resource requests) are declined to Cursor and the run continues.
