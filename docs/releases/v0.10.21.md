# YCoding v0.10.21

## Added

- `ycoding keep-awake setup` installs a one-time sudoers rule that allows only `pmset -a disablesleep 0` and `pmset -a disablesleep 1` without a password. With it, Keep machine awake also disables macOS system sleep, so a closed-lid Mac on battery stays awake until the battery runs out; turning keep-awake off or stopping YCoding restores system sleep, and the next start restores it after a crash. While the hold is on, choosing Sleep and low-battery sleep do not sleep the machine. Remove the rule with `sudo rm /etc/sudoers.d/ycoding-keep-awake`.
- Keep machine awake reports the system part in the TUI palette, Status dialog, and web Settings → Machine: `system` when held, `system needs setup` without the rule, `system held elsewhere` when another YCoding process owns it, and `system error` when applying or restoring fails.

## Changed

- The sidebar AUTONOMY rows name who decides with `manual`, `auto`, and `yolo`: `auto` while a rule switch decides, `yolo` while YOLO evaluates what the rule switches leave, and `auto, then yolo` for Questions when auto-answer and YOLO are both on. Permissions and Guardrails read `model, then manual` while baseline model assessment is on.

## Fixed

- Keep machine awake reasserts lid-closed sleep control every second instead of every 30 seconds, so macOS clearing it after a wake, power-source, or display change no longer leaves a long window in which closing the lid sleeps the machine.
