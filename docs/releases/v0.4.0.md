# YCoding v0.4.0

## Added

- On-demand [repository memory and shared knowledge](../memory.md) stored as linked Markdown. A repository's main checkout and linked worktrees share one collection identified by its canonical Git common directory; shared knowledge is available across repositories and outside Git. The memory tool supports explicit listing, lexical search, reading, and digest-guarded writes, with configurable storage paths and limits.
- Self-contained offline memory graphs with search, type filtering, keyboard selection, related-concept navigation, and a concept reader. Repository exports include shared knowledge and cross-collection links without loading remote assets.
- Recoverable memory deletion with collection-local trash, exact-byte restore, and digest-guarded permanent purge of a selected trash entry. Vacuum previews cleanup without writes; applying it requires the matching preview digest and preserves live concepts, trash, and unrelated files.
- Grouped documentation navigation, component summaries, on-page contents, keyboard skip links, and responsive light/dark layouts, including a task-oriented configuration guide and the memory reference.

## Changed

- Selecting a different model in an existing Session interrupts active requests and tools, waits for settlement, and checks the target model's context budget before committing the selection. If needed, it joins existing compaction and may admit one additional target-budget compaction. Raw transcript history is retained; interrupted work is not silently replayed. Invalid targets leave active work untouched, and a failed switch retains the prior model.
- Model pickers, recent/favorite cycling, and variant selection await the durable switch. The TUI shows the pending target without treating it as committed, and submission waits for selection before admitting new work.
- `/goal <text>` explicitly calculates and replaces a user-owned objective, including tracked multiline pasted text. Ordinary chat and agent tools cannot rewrite it. Bare `/goal` stops an active goal or resumes a retained objective without recalculation; failed calculation preserves the previous goal and composer draft.
- **Breaking Change:** Goal calculation always uses a model; remove `efficiency.goal_synthesis` from configuration. Customize the pre-prompt with `agents.goal.system`. Model selection uses `agents.goal.model`, then `efficiency.helper_models.goal`, then the Session model. A configured-model failure does not silently fall back to raw text or another model.
- The active credential Profile appears in the Context sidebar immediately above Provider instead of in the Session header. Model-picker profile labels remain available.

## Fixed

- Long user messages and pasted documents render at full wrapped height, with final lines, attachments, and following transcript rows reachable by scrolling. Tool-output collapsing remains separate.
- A failed pending model selection retains the draft and attachments without admitting a prompt or starting explicit goal calculation. Rapid queued selections retain the latest progress indicator; stale completions cannot retarget another Session or agent's local preference, and selecting the default variant clears a previously stored variant.
- A late goal calculation cannot undo a user stop or overwrite a newer autonomy change. Empty, failed, or unsettled provider output cannot activate a replacement goal. Existing no-progress accounting and explicit resume counters are preserved.

## Limitations

- Context fitting is an estimate of model-visible history, not a guarantee that a provider will accept every request. Switching may make a billable compaction-helper request. Canceling the switch waiter does not cancel an already-admitted compaction; a validated summary may remain active even if selection fails, while raw history stays intact.
- Memory is explicit and file-based: it performs no automatic recall, extraction, learning, migration, or expiration. Collection locks coordinate tool writers, not arbitrary external editors; digest checks detect stale edits. Unknown files and existing stores are not migrated or deleted automatically.
- Goal calculation may make a billable provider request. Bare stop/resume controls do not recalculate the retained objective.
