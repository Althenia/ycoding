# YCoding v0.11.0-beta.1

## Changed

- Native terminal builds include the Rust runtime and launch it as the local backend. The installed computer-use app stays beside the terminal executable.
- Native startup uses the bundled model catalog when cached data and the catalog service are unavailable; startup failure diagnostics preserve the stdio readiness protocol.
- CLI operations use the authenticated binary v5 connection. Large file attachments use file references and remain caller-owned until admission is confirmed.
- Meeting control uses the Rust backend and restores recorded Meeting history from its redb store. Native and Node CLI frontends keep backend execution and plugin composition in the embedded runtime.
- Remote enrollment and connection controls are backend-owned. Enabling access grants the enrolled owner access to every Session on that backend.
- `ycoding mcp add` persists and reloads server definitions through the backend and reports its selected configuration file.
- TUI registry packages resolve through the backend's verified presentation-package cache.
- **Breaking Change:** `ycoding api` accepts operation names and typed request JSON. Replace HTTP method/path arguments with calls such as `ycoding api health.get` or `ycoding api session.rename --data '{"params":{"sessionID":"ses_example"},"payload":{"title":"Example"}}'`.
