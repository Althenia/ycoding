# YCoding v0.11.0-beta.1

## Added

- Local clients can read retained family changes, selected team economics, and live family activity through the canonical revision 5 operations, with backend-owned Location checks and explicit errors for unavailable Sessions.
- `ycoding run --format json` reports step identity, context and cache telemetry, plus one final summary with per-Session steps and turns, token usage, priced costs when available, and run-window family usage including background subagents and hidden helpers. Default text output performs no usage reads.
- Run private evaluations with `ycoding run --config <file>` for a highest-priority JSON/JSONC document and `--isolated` for temporary runtime data, cache and state. Isolated runs keep stored credentials, stable data and existing beta import markers outside their roots, and remove temporary storage after shutdown or error.
- Try the Rust-backend beta with `curl -fsSL https://beta.ycoding.althenia.app/install.sh | sh -s -- --beta`. Beta uses separate configuration, state, data, and cache directories under `ycoding-beta`; stable remains a separate channel.
- On first beta start, import a private copy of stable Session data. When a Location first opens with Meeting enabled, import its stable Meeting history too, including transcripts, findings, summaries, plans, and proposals. Stable files remain unchanged; each import runs once, without merging later stable changes.
- Interrupted imports resume verified whole-table checkpoints only while the original source is unchanged. Each store activates atomically after verification, including managed attachments and artifact content for Core; marker-loss recovery preserves later beta database and resource writes.
- First beta start retries observed stable database changes three times, then refuses with close-and-retry guidance. Stable processes are not stopped or fenced. Sources need WAL evidence or a valid file rollback journal; MEMORY/OFF and ambiguous rollback snapshots are refused. A live stable Meeting owner refuses that Location's import. Version-1 beta import markers require an explicit recovery disposition or a separate empty beta root; existing data is never reset.

## Changed

- Acquired Locations rebuild from current model/account discovery and authenticated well-known configuration while held calls keep their captured generation. Failed discovery, reference fetch, MCP or service replacement retains the previous usable generation.
- Resource policy filters provider discovery, availability and generation. Well-known configuration follows project files and precedes inline content, resolves with its latest saved key, and refreshes even when its manifest is unchanged.
- Shells, terminals and one-shot connection tickets survive configuration reloads. Location eviction and Session ownership changes cancel pending decisions and native work; shutdown joins Location observers and service owners before storage closes.
- Root Sessions automatically title their first promoted prompt according to the configured local, model or off policy. Reference guidance follows the current generation, and explicit resource refresh fetches Git references while ordinary reads use cached checkouts.
- Capability changes apply at the next Session step, including tool catalogs and durable instruction removals, without restarting unrelated MCP servers. Web-search provider pins apply across Sessions and reloads.
- Production retention prunes eligible local compacted history at startup and hourly, preserves remote manifests, and drains active sweeps during shutdown.

- Compacted-history retention preserves the verified checkpoint, required durable facts, usage and prompt-retry identity while removing covered message rows and message-only events in bounded transactions.
- Forks retain the compaction summary and retained conversation prefix. Fork and revert targets outside retained history return a typed compacted-history error without changing Session or file state.

- The terminal, Mini, and remote web client control the local Rust runtime through revision 5 connections. Repository work, tools, model requests, durable Sessions, goals, and background subagents run on your machine.
- Global Forms in the full TUI and Mini retain their owning Location for replies and cancellation, including after reconnect.
- Terminal family views read canonical captured changes, economics and bounded current activity through the local runtime, with complete cursor paging and explicit read failures.
- Native terminal and Node CLI builds include the Rust runtime. The installed computer-use app stays beside `ycoding`.
- Startup can use the bundled model catalog when cached data is unavailable, including when the catalog service cannot be reached. Startup diagnostics preserve the stdio readiness protocol.
- CLI file attachments use file references and remain caller-owned until admission is confirmed.
- Meeting control uses the Rust backend and restores recorded Meeting history from its redb store.
- Remote enrollment and connection controls are backend-owned. Enabling access grants the enrolled owner access to every existing and future Session on that backend.
- `ycoding mcp add` persists and reloads server definitions through the backend and reports its selected configuration file.
- TUI registry packages resolve through the backend's verified presentation-package cache.
- **Breaking Change:** `ycoding api` accepts operation names and typed request JSON. Replace HTTP method/path arguments with calls such as `ycoding api health.get` or `ycoding api session.rename --data '{"params":{"sessionID":"ses_example"},"payload":{"title":"Example"}}'`.
- Beta providers are OpenAI (API key and Codex subscription), Anthropic (API key and Claude Code subscription), OpenRouter, Cursor, Meta (Muse and API key), Cline (`cline-pass`), Z.ai, MiniMax, Kimi, and OpenAI-compatible custom endpoints. Configurations naming other providers load with an unsupported-provider diagnostic.
- Provider quota refresh preserves eligible response observations, including Muse subscription usage, when no credential is selected or the refreshed source has no supported quota data.
- Runtime customization uses explicit trusted process extensions and MCP servers. Runtime JavaScript/npm plugins are unsupported; terminal presentation plugins stay in `cli.json`.
- On a beta build, `ycoding update` selects the higher of the newest beta and newest stable release. Stable builds stay on stable automatically.

## Fixed

- Remote relay deliveries recheck browser authority before sending Session events, status, and subscription controls, blocking revoked or expired browser sessions while authorized recipients stay connected.
- Remote Session creation stays connected when a backend epoch advertisement overlaps its subscription reply during relay authorization; transmitted mutations are not automatically replayed.
- Compacted-history checkpoints stay out of web and terminal chat and navigation choices, stop older paging, and lead terminal copy/Markdown/JSON exports. Pruned fork/revert targets show actionable compaction wording, and failed undo or message-dialog revert preserves the composer.
- Idle Locations release replaced service generations and extension processes with the skill tool registered; active MCP skill calls and external service holders retain their captured generation until released.
- Recover project-artifact writes interrupted during filesystem activation, preserving exact content, version history, and automatic-write accounting across repeated reconciliation.

## Install and switch channels

- Configure accounts and preferences in the beta configuration directory; stable configuration is not copied automatically. Unsupported executable-plugin declarations must be removed from runtime configuration before that document can load.
- Use the matching beta web client and backend together. Revision 5 requires matching contracts; existing device enrollment still belongs to its enrolled relay origin.
- Switch back with `curl -fsSL https://ycoding.althenia.app/install.sh | sh`. Stable and beta histories remain separate, and switching back does not import beta changes into stable.
- Meeting remains opt-in through the native `ycoding meeting` command or `ycoding serve --meeting`; capture requires fresh consent and the configured local speech dependencies.
