# YCoding v0.11.0-beta.1

## Added

- Shell commands support a machine-wide queue with per-Session limits and resource-aware admission. Waiting commands hold no running-shell family slot and deliver background completion notices after execution.
- Provider-request records retain initiating-prompt attribution across nested tool calls, child dispatch and compaction without changing model input or prompt-cache identity.
- Usage APIs expose provider/profile/model, prompt and nested-task dimensions, cost coverage, measured-speed populations and scoped quota forecasts. Session speed diagnostics retain estimated-sample labels and duration-weighted rates.

- Keep-awake separates the manual preference from root-family holds, reports idle and lid inhibition independently, and supports `/keep-awake`. macOS lid control uses exclusive ownership, periodic reapplication, and startup recovery; terminal and web controls expose held or failed lid control and battery/heat warnings.
- Local clients can read retained family changes, selected team economics, and live family activity through the canonical revision 5 operations, with backend-owned Location checks and explicit errors for unavailable Sessions.
- `ycoding run --format json` reports step identity, context and cache telemetry, plus one final summary with per-Session steps and turns, token usage, priced costs when available, and run-window family usage including background subagents and hidden helpers. Default text output performs no usage reads.
- Run private evaluations with `ycoding run --config <file>` for a highest-priority JSON/JSONC document and `--isolated` for temporary runtime data, cache and state. Isolated runs keep stored credentials, stable data and existing beta import markers outside their roots, never inherit `YCODING_SQLITE_IMPORT_SOURCE`, and remove temporary storage after shutdown or error.
- Try the Rust-backend beta with `curl -fsSL https://beta.ycoding.althenia.app/install.sh | sh -s -- --beta`. Beta uses separate configuration, state, data, and cache directories under `ycoding-beta`; stable remains a separate channel.
- On first beta start, import a private copy of stable Session data. When a Location first opens with Meeting enabled, import its stable Meeting history too, including transcripts, findings, summaries, plans, and proposals. Stable files remain unchanged; each import runs once, without merging later stable changes.
- Interrupted imports resume verified whole-table checkpoints only while the original source is unchanged. Each store activates atomically after verification, including managed attachments and artifact content for Core; marker-loss recovery preserves later beta database and resource writes.
- First beta start retries observed stable database changes three times, then refuses with close-and-retry guidance. Stable processes are not stopped or fenced. Sources need WAL evidence or a valid file rollback journal; MEMORY/OFF and ambiguous rollback snapshots are refused. A live stable Meeting owner refuses that Location's import. Version-1 beta import markers require an explicit recovery disposition or a separate empty beta root; existing data is never reset.
- Select a disposable store with `YCODING_DB=:memory:` or a physical store with an absolute or data-directory-relative path. Default beta and other-channel slots have separate leases, analytics and import markers; `latest` and `prod` share the stable slot, and an unset channel selects `local`. Exactly `1` or `true` in `YCODING_DISABLE_CHANNEL_DB` selects the stable slot for other channels. Default beta and other-channel slots import their SQLite source once; the stable slot requires an explicit import. Set `YCODING_SQLITE_IMPORT_SOURCE` with a file `YCODING_DB` to select that source. Sealed imports never reread the source, while variable syntax remains validated.
- Backend usage reports (`usage.get`, `usage.report`) read retained usage facts that outlive their Sessions, while Session and Session-tree usage read each Session's own request ledger. Set retention with `session_retention.records_days` (7 days of Session idleness), `analytics_retention.usage_days` (30 days) and `analytics_retention.latency_days` (30 days) in global configuration. Deleting Session records or expired facts waits for the verified pre-prune backup. SQLite imports keep existing facts, including those of deleted Sessions. Startup and hourly retention continue during usage-analytics outages; usage reports remain unavailable until the pending purge completes.

## Changed

- Questions, Forms, and subagent questions are answered automatically only when that Session's `/auto-answer` toggle is on (default off), independently of YOLO, goals, and sleep.
- Usage centers the monthly total inside its donut, abbreviates only when the exact value does not fit, and preserves exact accessible totals and provider legend values.
- Automatic retention requires a verified one-time redb backup with database-size-plus-1-GiB disk headroom; compacted-history pruning uses byte-bounded batches and native free-page reclaim without blocking runtime workers.
- Acquired Locations rebuild from current model/account discovery and authenticated well-known configuration while held calls keep their captured generation. Failed discovery, reference fetch, MCP or service replacement retains the previous usable generation.
- Resource policy filters provider discovery, availability and generation. Well-known configuration follows project files and precedes inline content, resolves with its latest saved key, and refreshes even when its manifest is unchanged.
- Shells, terminals and one-shot connection tickets survive configuration reloads. Location eviction and Session ownership changes cancel pending decisions and native work; shutdown joins Location observers and service owners before storage closes.
- Root Sessions automatically title their first promoted prompt according to the configured local, model or off policy. Reference guidance follows the current generation, and explicit resource refresh fetches Git references while ordinary reads use cached checkouts.
- Capability changes apply at the next Session step, including tool catalogs and durable instruction removals, without restarting unrelated MCP servers. Web-search provider pins apply across Sessions and reloads.
- Production retention prunes eligible local compacted history at startup and hourly, preserves remote manifests, and drains active sweeps during shutdown.

- Compacted-history retention preserves the verified checkpoint, required durable facts, usage and prompt-retry identity while removing covered message rows and message-only events in bounded transactions.
- Forks retain the compaction summary and retained conversation prefix. Fork and revert targets outside retained history return a typed compacted-history error without changing Session or file state.

- The terminal, Mini, and remote web client control the local Rust runtime through revision 5 connections. Repository work, tools, model requests, durable Sessions, goals, and background subagents run on your machine.
- Global Forms in the full TUI and Mini retain their owning Location for replies and cancellation, including after reconnect.
- Terminal family views read canonical captured changes, economics and bounded current activity through the local runtime, with complete cursor paging and explicit read failures.
- Native terminal and Node CLI builds include the Rust runtime. The installed computer-use app stays beside `ycoding`.
- Startup can use the bundled model catalog when cached data is unavailable, including when the catalog service cannot be reached. Startup diagnostics preserve the stdio readiness protocol.
- CLI file attachments use file references and remain caller-owned until admission is confirmed.
- Meeting control uses the Rust backend and restores recorded Meeting history from its redb store.
- Remote enrollment and connection controls are backend-owned. Enabling access grants the enrolled owner access to every existing and future Session on that backend.
- `ycoding mcp add` persists and reloads server definitions through the backend and reports its selected configuration file.
- TUI registry packages resolve through the backend's verified presentation-package cache.
- **Breaking Change:** `ycoding api` accepts operation names and typed request JSON. Replace HTTP method/path arguments with calls such as `ycoding api health.get` or `ycoding api session.rename --data '{"params":{"sessionID":"ses_example"},"payload":{"title":"Example"}}'`.
- Beta providers are OpenAI (API key and Codex subscription), Anthropic (API key and Claude Code subscription), OpenRouter, Cursor, Meta (Muse and API key), Cline (`cline-pass`), Z.ai, MiniMax, Kimi, and OpenAI-compatible custom endpoints. Configurations naming other providers load with an unsupported-provider diagnostic.
- Provider quota refresh preserves eligible response observations, including Muse subscription usage, when no credential is selected or the refreshed source has no supported quota data.
- Runtime customization uses explicit trusted process extensions and MCP servers. Runtime JavaScript/npm plugins are unsupported; terminal presentation plugins stay in `cli.json`.
- On a beta build, `ycoding update` selects the higher of the newest beta and newest stable release. Stable builds stay on stable automatically.

## Fixed

- Native JPEG normalization preserves the same pixels across supported decoder platforms.
- Closed terminal input stops writes promptly so shell expiry and runtime shutdown can finish.
- Usage reports preserve request-level enrichment for sparse and high-cardinality filters.
- Remote Session status distinguishes lost-result attention from pending questions, Forms, and reviews; team shells preserve owner and process-lifecycle status without queue positions.
- Native builds embed the runtime from Cargo's resolved target directory rather than an unrelated cached artifact.
- Runtime shutdown completes when a Session has pending work; interrupted runs do not start replacement tasks during teardown.
- Meeting connector settings reflect completed tool discovery instead of a stale pending state.
- `/suggest` accepts predictions in languages written without spaces between words, such as Japanese and Chinese, instead of discarding them as one-word replies.
- Subagent routing sets a child model only when its exact provider, model, and variant are known to be available; otherwise the child runs on the session's model.
- Built-in primary agents implement or delegate according to their own roles, keep working on ready tasks while subagents and background shells run, keep todo lists current, verify suggested causes and fixes by reproducing the symptom, and name each changed file path and the exact checks in their reports. Built-in subagents return undecidable destructive choices as blockers. Goal steers and synthesized goals are plain text without Markdown.
- Returning from Office to Conversation restores the visible transcript window and uncertain-send retry controls without requiring a resize.
- Remote Session log reads use the source epoch of the Session's loaded snapshot, so history reconciliation works through the relay.
- Usage shows credits as negative USD: totals are net, the daily chart draws credit days below its zero line, and a month with credits shows net known spend instead of provider shares.
- Session and Session-tree prompt usage reports attribute requests with a missing stored anchor to their admitted input, task grouping includes requests from Sessions nested below non-task Sessions, and an explicit zero provider generation duration no longer enters measured speed rates.
- Generation speed history at a revert point excludes later requests and keeps the model's identity when no valid samples remain.
- Subagent waiting timers start when the child asks its question and update together in the TUI header and blocked-question view until the question settles.
- Usage summaries and reports keep Session reads and writes responsive, preserve one snapshot per result, and invalidate cached prices when the catalog changes.
- Git guardrails keep flags within their own shell command, so a routine push followed by `rm -f` or `grep -f` does not request force-push review. Destructive Git commands and SQL heredocs retain hard review.
- Terminal history pages backward after delayed Location hydration, including when the newest snapshot arrives before its viewport mounts.
- Remote Sessions open with concurrent reads, retain visible rows during list refreshes, and reconcile missed history without redundant reloads. Usage loads on demand, and native captured-change reads share work while preserving current ownership checks.
- Sessions created with a named model profile bind to that account, including inherited parent selections; unavailable profiles fail without selecting another account.
- Remote relay deliveries recheck browser authority before sending Session events, status, and subscription controls, blocking revoked or expired browser sessions while authorized recipients stay connected.
- Remote Session creation stays connected when a backend epoch advertisement overlaps its subscription reply during relay authorization; transmitted mutations are not automatically replayed.
- Compacted-history checkpoints stay out of web and terminal chat and navigation choices, stop older paging, and lead terminal copy/Markdown/JSON exports. Pruned fork/revert targets show actionable compaction wording, and failed undo or message-dialog revert preserves the composer.
- Session loading presents a message field only when its editor can receive typing, and retains the first draft while history loads.
- Idle Locations release replaced service generations and extension processes with the skill tool registered; active MCP skill calls and external service holders retain their captured generation until released.
- Recover project-artifact writes interrupted during filesystem activation, preserving exact content, version history, and automatic-write accounting across repeated reconciliation.
- A failed compaction does not trigger another attempt when its context, policy, and target are unchanged.
- Project-artifact evaluation keeps the goal outcome when an execution finishes after its goal changed.
- Stopping a shell command verifies its process-group identity, force-ends descendants that ignore graceful termination, and reports cancellation only after cleanup succeeds. Failed cleanup keeps the command, its output, and its restart record tracked and reports an error. Timeouts and memory limits flush captured output and end capture after a bounded final drain, even while escaped descendants keep writing; a normally exiting command keeps late output.
- Lost shell notices from finished subagents stop marking their root Session as waiting for attention, and a completion notice for a deleted Session is discarded.
- Include the license notices for the Rust runtime's locked third-party crates, bundled native sources (DuckDB, SQLite, LMDB, AWS-LC, libgit2) and ported code in the separately published `NOTICE` asset and native package notice files. `bun script/rust-notices.ts` regenerates the section and `--check` fails when it drifts.

## Install and switch channels

- Configure accounts and preferences in the beta configuration directory; stable configuration is not copied automatically. Unsupported executable-plugin declarations must be removed from runtime configuration before that document can load.
- Use the matching beta web client and backend together. Revision 5 requires matching contracts; existing device enrollment still belongs to its enrolled relay origin.
- Switch back with `curl -fsSL https://ycoding.althenia.app/install.sh | sh`. Stable and beta histories remain separate, and switching back does not import beta changes into stable.
- Meeting remains opt-in through the native `ycoding meeting` command or `ycoding serve --meeting`; capture requires fresh consent and the configured local speech dependencies.
