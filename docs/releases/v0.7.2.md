# YCoding v0.7.2

## Added

- Provider-native compaction: run Codex remote compaction on the owner request with a bounded local fallback, persist and replay private compaction items for matching models across model switches, enable Copilot Responses compaction and Claude Chat cache markers, and preserve Anthropic empty/redacted thinking with reported one-hour cache writes at the provider rate.
- Ship the signed `YCoding Computer Use` app (`app.ycoding.computer-use`) beside release executables. Resolve desktop windows by exact CG window ID, probe Accessibility elements on other Spaces, request Accessibility/Screen Recording/Automation access, and sign releases with a configured Developer ID identity so privacy grants persist across updates; ad-hoc builds fail at release time.
- Install and update the paired Chrome extension alongside the CLI release; show its folder in the Connect Chrome dialog. Fix the Chrome extension ID via manifest public key.
- Accept installed Chrome 152 or newer for release acceptance checks.
- Add built-in git worktree guidance to core instructions so sessions can create, inspect, and integrate worktrees with linear fast-forward history on `main`.
- Show provider usage by profile in the TUI: one quota snapshot per stored credential profile, hide providers without a usable credential or usage path, and render unreported values as `-`.
- Add built-in `ycoding/workspace-memory` guidance: agents search workspace memory before substantive work and, after validated work, save newly verified durable facts with their sources through the `memory` tool.
- Show a dedicated OAuth sign-in screen when the remote workspace is opened while signed out; Google is the supported provider, and sign-in returns to the route that was opened.
- Publish the documentation for AI agents as `/llms.txt`, `/llms-full.txt`, and one `/docs/<slug>.md` per page, generated from the same registry as the site. Every documentation page now gives exact commands, full configuration examples, field tables with types and defaults, verification steps, and troubleshooting, including the three guardrail tiers and what triggers a hard review.

## Changed

- Remove standard hard guardrail reviews for desktop access, Chrome owned opens, and Chrome profile mutations; site permissions and custom rules still apply.
- Scope `prompt_cache_key` per Session on key-carrying routes while keeping shared ledger namespace; Codex session-id, thread-id, x-client-request-id and WebSocket affinity follow the Session-scoped key.
- OpenRouter Responses replay reasoning, phase and tool metadata under the `openai` metadata key; keep encrypted reasoning until item completion; request `reasoning.context all_turns` for GPT-5.6+; send `prompt_cache_options` only in explicit mode; send top-level `cache_control` only for Anthropic models.
- Standardize selectable primary agent reporting contract across providers.
- Send tool results that contain images or files as provider-native content parts instead of JSON-encoded base64 text.
- Reusing a prompt message ID returns the first admitted durable record and wakes execution instead of failing; reuse across Sessions or across input kinds is still rejected.
- Redesign the remote workspace: the selected conversation is one centered column with pending requests after the transcript and one composer box; permission, guardrail, and question cards share one layout, and hard reviews stand out with a danger outline and a "Human only" badge. Activity lists pending decisions first below 1280px, and the machine picker states how many offline or revoked machines Settings manages.
- A selected machine that goes offline keeps its name, reconnect action, and last session list, which stays read-only until the machine reconnects.
- Remote tool rows show at most 4,000 characters with path-free truncation labels; unsent prompt drafts stay with their Session across reconnects; the offline shell cache keeps the built entry script and stylesheet.
- Align the public site, documentation, changelog, footer, and not-found layouts to one grid with one card style; inline code renders in documentation text.

## Fixed

- Avoid deadlock when a child subagent asks its parent during session coordination.
- Keep the shell sidebar accurate for fast exits and unloaded owner processes.
- Improve provider prompt-cache reuse and reasoning retention on key-carrying routes.
- Keep one Anthropic cache TTL per request source.
- Align question recommendations with user requirements instead of model defaults.
- Remote workspace: state an unavailable or unreachable machine once instead of repeating it in a notice; report a listed-online machine whose agent does not answer as not reachable; keep header controls inside the viewport at tablet widths; keep notification channel headings on one line.
