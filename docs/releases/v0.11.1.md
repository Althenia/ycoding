# YCoding v0.11.1

## Added

- Permissions, guardrails and answers each have their own autonomy mode: Manual (the default), YOLO or Auto. One Autonomous control sets them: `/autonomous` in the TUI and web, the command palette, and `ycoding run --permissions|--guardrails|--answers <mode>`. Up/Down selects a category, Left/Right cycles its mode, and `1`, `2` or `3` sets every category to Manual, YOLO or Auto. The separate YOLO and automatic-approval commands, palette entries and flags are removed.
- Manual leaves every unresolved request to you and makes no model call. Auto applies fixed rules only: permissions approve ask requests, guardrails approve ordinary standard reviews while you are awake, and answers use only a valid default or a single option labelled Recommended. YOLO lets that category's model evaluator settle what the rules leave open. Hard and custom-rule reviews always need you.
- Session footers show the effective Permissions, Guardrails and Answers modes, inherited-mode labels, and an asleep marker. The Autonomous dialog identifies each inherited mode's source. The sidebar keeps goals and waiting reviews without a separate autonomy section.
- Project members can have a recorded owner. The Master assigns a member Session to a subagent it launched, or owns it directly; the owner then receives that member's requests and lifecycle notices, including execution starts and settled-step progress, even while idle. Members without an owner route to the Master. Only the Master assigns or transfers ownership, and the Master or the owner releases it as completed or released. Idling, failure, interruption and a settled turn never release it; removing the member, deleting the owner or replacing the Master does. Executor children of an owner receive no Project control. Project participants report their owner to clients.
- The `project` tool gains `inspect`, `assign` and `release`. `inspect` reads one pending member request: bounded, redacted action and resources (or question fields), review rules and flags, escalation reasons, and whether it may be approved or declined, only declined, escalated, or is human-only.
- The Projects tab in the Session composer (`<leader>p`) shows the roster and native actions.
- Antigravity subscription accounts: connect a Google account you own with `/connect` and run its Antigravity models, with per-model quota in Usage. Effort-specific gateway models that share a base model appear as one model with selectable effort variants, and image, video and PDF input follow what the gateway reports. Google may change or restrict the gateway, and live inference against a subscription has not been verified.

## Changed

- ChatGPT and Claude account connector tools are called in Code Mode at readable paths built from the connector and tool names, such as `tools.chatgpt.ycoding.session_catalog` and `tools.chatgpt.ycoding_work.session_catalog`, instead of names containing the connector ID and a hash. The old names are not callable. Permission rules, saved approvals and tool capability settings still match each tool's existing registered name. Matching names get a short suffix from the connector ID, and two tools with the same Code Mode path are rejected instead of one replacing the other.
- Maintained primary agents and subagents select focused test files or cases at every checkpoint, including integration and merge. Their shared instructions prohibit full-repository, workspace-wide and entire-package test runs, including scripts or batches that recreate them, while retaining affected non-test checks.

## Fixed

- Interleaved transcript notices stay between their surrounding text through settlement, reconnect and forks, using recorded text offsets even when notice clocks or message IDs disagree. Historical text keeps unknown timing and deterministic ordering; hidden state updates do not split visible text.
- The Context rail distinguishes missing cache telemetry from a reported zero hit ratio and keeps its cache status visible when diagnostics are absent.
- Antigravity streaming preserves multiline responses and fragmented UTF-8, including thinking, assistant text, tool signatures and cache usage. Stream cancellation and read failures propagate to the source. Missing cached-input telemetry stays unreported instead of displaying a zero cache read; an explicit zero remains reported.
- Project notification cards keep long titles, status and Open actions in a compact header, with full-width bounded previews underneath. Long paths and hashes stay contained on desktop and mobile.
- Project chats retain their Session panels and standard footer. Compact layouts keep the draft and useful transcript space visible alongside a five-Session roster. Completion notices wait for a member's background work to settle.
- Human messages activate paused Projects without re-decoding live event payloads. Pending decisions and failures reach the supervising Session even while dispatch is paused.
- Supervisors can decline routine requests and escalate unresolved decisions with an attributed reason chain. A decline can reject an ordinary unclassified permission ask or standard review but never approves one. Human-only approvals, hard reviews, explicit denies and permission ceilings remain enforced, and under Manual a decline is sent to you instead of settling.
- Project creation preserves fresh revisions and supports titled new Master Sessions. Session pickers filter as you type and retain distinguishing directory names; roster counts, editable fields and keyboard hints remain consistent.
- Scoped keymaps share one destruction listener per renderable, and process warnings go to the TUI log instead of overwriting the terminal. Project membership no longer prevents normal Session data from loading.
- Automatic titles preserve explicit names and exclude structured provider commentary from title text.
- Canonical system temporary paths do not trigger outside-repository prompts. Symlink escapes, explicit denies, ceilings and destructive-action checks remain enforced.
- Settled automatic guardrail approvals and match dismissals no longer fill the conversation, including while a Session loads. Model rejections appear in order within the loaded chat, pending reviews stay at the end, and guardrail status keeps the full record.
- Failed autonomy refreshes show unknown modes instead of stale permissions, inheritance or sleep state, without emitting a wake notice. A successful refresh restores the current state.
- Compact parent and child layouts keep the composer and pending-review controls visible with the autonomy footer.
- Chrome connection dialogs keep the pairing code and actions visible in short terminals. Page Up, Page Down and the mouse wheel reach the full installation path, service address and permission note.

## Local upgrade

- Existing Session autonomy settings convert once: an automatic toggle becomes Auto, otherwise YOLO stays YOLO, otherwise Manual.
- The local database upgrade adds an optional owner to Project members. Existing members remain without an owner, and no owner is inferred.
