# YCoding v0.11.1

## Added

+ The macOS desktop app is an Electrobun app published as `YCoding-Desktop-v<version>-darwin-arm64.zip`. It can also be built from source with `/bin/sh <absolute path to packages/desktop>/script/build.sh --outdir=<fresh-output-directory>`.
+ At startup the desktop app offers Start my own backend, a private bundled backend that stops when the window closes, and Connect to a shared backend, an explicit HTTP(S) origin or the running managed service, which keeps running when the window disconnects. The window uses the same generated native client and events as the terminal, not the relay, and saves the chosen mode and a credential-free shared origin in `backend-preferences.json` in its application configuration directory.
+ The desktop transcript and the web transcript share a conversation navigation rail with a tick for each prompt and a jump control to the top or the latest message.
+ Backend startup and connection errors appear in the desktop connecting state. They are also written, redacted and together with the backend's standard error output, to `desktop.log` next to `backend-preferences.json`.
+ The Workspaces page creates a project copy from the project's own worktree, registering that worktree as a project directory when it is not listed yet.
+ `ycoding decision watch <root> --family --follow` accepts `--deliver dot` and `--deliver <task-thread-id>`, together up to 8 times, to push events through `dots.thread.send` without polling. `dot` sends to the Dot's current root conversation, looked up again before every delivery, so a rotated root keeps receiving messages; the state file keeps `dot`, not the resolved thread. Pushed events are execution started, succeeded, failed and interrupted, completed work, pending permission asks, guardrail reviews, questions, forms, reviews and child questions, and Project ownership changes and releases. Each message carries the IDs, the read and decide commands that `ycoding decision list` prints, and a statement that settling stays within the user's existing authority. Delivery never answers a decision. Each message is sent the way ChatGPT.app sends to a Dot, without queueing: it starts a turn on an idle thread and joins an active one. Project ownership found when the watch starts is sent once per Project as current state, not as changes; its JSON lines carry `snapshot: true`. Delivery progress is kept in the follow state file, so a restarted watch neither drops nor re-sends events. A rejected send, or 10 unconfirmed attempts in a row, ends the watch with `[delivery-failed]`; a rejection's JSON-RPC code, error code, error type and sanitized message appear in the failed delivery line and on stderr. The YCoding operator skill for Dots describes this watch with `--deliver dot` and tells the Dot to create YCoding coordination threads with computer V selected.

## Changed

+ A Session that joins a Project as a member, through `project create`, a Project create or update, or the TUI new-member and add-member actions, takes the Master's effective permissions, guardrails and answers modes at join time. A later change on the member persists, goal and sleep state are not copied, and the member's subagents inherit the member's modes.
+ Questions, forms, permission asks and guardrail reviews raised by a Project member's subagents, at any depth, reach the member's owner, or the Master as an escalation when the member is unowned. They carry `requestSessionID`, appear in the member's pending list without blocking sends to it, and the owner inspects, answers and escalates them with the member's Session ID. Deny rules and permission ceilings still deny, and a Master escalation leaves the request open for the user in the requesting Session.
+ The desktop transcript uses the wider column; tool, reasoning and Markdown blocks share one column edge, and loading shows a skeleton and an indeterminate running bar.
+ The desktop effort slider, Usage page and palette accents use the same surfaces as the web client.
+ The Edited files card belongs to the turn that captured the edits, and Undo appears only there. Turns without captured changes show no card, and the Session changes tab lists session-wide changes without Undo.
+ A CLI command that fails after its arguments are parsed writes its fatal error report to stderr, with the same exit codes. A `ycoding serve --stdio` that fails during startup leaves stdout empty and reports the failure on stderr.

## Fixed

+ `ycoding dots send` waits for the Dot thread's `thread/resume` subscription before sending, as ChatGPT.app does. When ChatGPT rejects the subscription or the message, the command prints the reason, `ChatGPT rejection code <code>, type <type>, error <code>: <message>`, instead of the raw JSON error body, and the `dots.thread.send` error body carries it as `rejection`. `--queue` still sends a queued message; ChatGPT.app never queues Dot messages, and ChatGPT can reject one.
+ `--server` with the URL of the registered local service, and the desktop app's shared backend, use that service's password even when its health check takes longer than two seconds. Such a slow service no longer fails as unavailable or incompatible.
+ `decision watch --state` suggests a canonical path only when that path would be accepted. Otherwise `[state-invalid]` states that the state directory must be owned by the current user and not writable by group or others, and that omitting `--state` uses the private default location. A path under `/tmp` no longer suggests a `/private/tmp` path that is then rejected.
+ While its durable connection stays up, the Dots computer lists the Dot's task threads again every 30 seconds. A task thread created for this computer is reported ready within about 30 seconds instead of at the next reconnect. The `readiness-scan` diagnostic reports listed, matched, pending and page counts. `readiness-failed` reports its stage, reply kind, JSON-RPC code and a sanitized message class, and neither diagnostic includes thread IDs or upstream text.

## Limits

+ A Dot task thread created without this computer selected has no environment for it. Readiness cannot add one, so the thread reports `No usable execution environment is available.` until the Dot creates a thread with the computer selected.
+ The desktop app targets Apple silicon macOS only. It is unsigned and not notarized, so macOS blocks the first open until you allow it.
