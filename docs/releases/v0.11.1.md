# YCoding v0.11.1

## Added

- `ycoding decision watch <root> --family --follow` keeps one native observer armed on a root Session and its descendants until you cancel it or it stops with an error. It does not end when a decision is pending, a reply arrives, the root goes idle with work unfinished, or an execution completes. It prints one JSON line per observation containing identifiers only: Session, request and event IDs, request kind, event type and sequence, whether the root is active, and a resolution when a request leaves the pending list. Request text, decide commands, answers and transcripts are never printed.
- Follow covers pending permission, guardrail, question, form and review requests, observed replies, durable execution, step, input, work-completion, task and review events, and descendants created after the watch starts. When the native connection fails or a stream ends, it reconnects with backoff, rereads current pending requests and replays missed history from its saved positions; it stops with an error after ten consecutive failed attempts, and a recovery that makes progress resets the count. Other failures, such as an unauthorized or malformed response, stop it immediately. Between observations it reads nothing extra: it rereads current state only at startup, after a reconnect, for a newly created child and for review-box changes. Between observations it prints a heartbeat line at the `--timeout` interval (default 300 seconds, at most 3600). The heartbeat shows only that the follow process is running; it does not prove the native stream is connected, and a silently dead connection is detected only when the runtime reports a failure or the stream ends.
- Follow keeps a private state file, by default under the application data directory and named for the server and root Session, or at the path you give with `--state`. It stores a history cursor per Session, which advances only after an observation has been printed and saved, plus the pending requests and the request and terminal records that suppress repeats, so a restarted follow continues from them. The file is bound to the root Session, the server address and the server's process epoch; a different root, server or restarted server is refused instead of reused. It is created with owner-only permissions. Symbolic links, links to other files, files owned by another user or open to group or other access, and a concurrent writer are refused, and each update replaces the file atomically instead of overwriting it in place. A failure prints only a classification (`epoch-mismatch`, `state-lock-held`, `state-invalid`, `state-conflict`, `cursor-ahead`, `budget-exhausted`, `output-failed` or `observer-failed`), never a path, server address, version or request content.
- `ycoding decision watch --family` now reports a descendant's execution settlement or post-cleanup status change as `outcome: "family"` with exit 0, bounded `changes` naming the observed Sessions and events, and the root's current `work`. A descendant's settlement never becomes the root's execution result or completes its goal, and the root's `--input` correlation stays open. `--checkpoint <token>` resumes a family watch across invocations; the token carries only per-Session history positions, never permission, work or completion authority. Family watches cover at most 64 Sessions including the root and fail explicitly beyond that; pending decisions are re-read after each connection rather than reconstructed from history.
- Memory search ranks with local lexical BM25 over title and ID, type, tags and description, and body (boosts 4, 2 and 1), with ties sorted by concept ID. It is not semantic search and keeps no persisted index.
- The `memory` tool adds `delete` (moves a concept to recoverable trash), `trash`, `restore`, `purge` and `vacuum`. Delete, restore, purge and applied vacuum require the current SHA-256 `expectedDigest` and change nothing when it is missing or stale; vacuum previews by default and removes only recognized obsolete generated indexes and orphan trash receipts. Mutating actions need `memory_write` and take a `file_mutation` guardrail reservation; `trash` and the vacuum preview need `memory_read`. Nothing expires automatically, and maintenance has no rollback across files, so inspect with `read`, `trash` and a vacuum preview after an interruption. A relative memory `path` resolves against the repository's main checkout, or the current Location folder outside Git.

## Changed

- Muse (Meta) account sign-in embeds `YCODING_MUSE_CLIENT_ID` and optional `YCODING_MUSE_CLIENT_SECRET` during native and Node builds instead of storing a client ID in source, ignoring runtime overrides; an empty or omitted secret runs as a public device client sending `client_id` only, and source builds without an embedded client ID reject device sign-in before making an HTTP request.
- `--follow` requires `--family` and rejects `--input`, `--after` and `--checkpoint`; `--state` requires `--follow`. Without `--follow`, `ycoding decision watch` returns one bounded result, then exits.
- The web site, docs, changelog and remote client, and mobile layouts replace boxed cards, nested panes and ruled rows with open tonal surfaces: typography and whitespace carry hierarchy, controls are pills and the composer is a single capsule. Color tokens, keyboard focus and 44px touch targets are unchanged, and coarse-pointer landscape phones use a 56px vertical navigation rail.

## Fixed

- Muse (Meta) subscriptions align with current Muse Code: key minting supplies initial quota windows and the reported subscription tier name in the Usage label, explicit OAuth quota refreshes mint at most once per minute while ordinary reads remain in memory and direct keys never mint, overage percentages above 100% are preserved, OAuth model discovery remints once on HTTP 401 and includes `ultra` when advertised, and inference requests send surface-mapped `x-client-id`, Session-derived Muse session and thread UUIDs without internal YCoding headers, `x-tbh-contributor-mode`, and `auto`-normalized `tool_choice`.
- Goal synthesis, drafted prompts, main agents and subagents carry the user's model, provider, profile, permission, ownership, workflow, check, toolchain and filesystem constraints, and report the exact gap and the decision needed instead of substituting a binding, widening access or redirecting toolchain, cache or config locations.
- Recorded questions and parent answers in the web transcript render as borderless tonal planes; only pending request cards and hard reviews keep a boundary.
- Muse (Meta) OAuth accounts are no longer rejected as a non-Muse Code client when a Session declares YCoding's built-in tools: tool declarations travel under a private provider-side namespace and returned tool calls map back, so Session, history and runtime tool names are unchanged. Direct Meta API keys and `META_API_KEY` are unaffected.
- Antigravity Claude replays each thinking signature with its own thinking block, and thinking history without a nonempty signature is left out of Claude's provider request while the Session transcript keeps it.

## Limits

- Follow runs only while its process runs. It observes and prints identifiers; it never answers, approves, resumes or retries anything. It does not wake an idle or completed Dots, cloud or other external task, so keep a native follow process or task running for as long as you need notifications.
- Delivery is at-least-once, not exactly-once: after a crash or a failed output write, a restarted follow can print an observation again. Every line carries stable identifiers, so ignore a repeat you already handled, and reread current state before acting.
- A family is limited to 64 Sessions including the root, and a follow state to 1 MiB with at most 8,192 request and terminal records, whichever comes first. The global connection and each stream stop after ten consecutive failed reconnects. Exceeding a limit stops the follow with an error instead of dropping records. Durable events are tracked by the cursor alone, so they never fill a ledger. Replay depends on retained history: pruned history, and requests that appeared and disappeared while follow was disconnected, cannot be reconstructed. After a server restart, start a new state file.
- Run follow in the foreground or as an active background task. Nothing restarts it if it ends, and a background shell task has a finite lifetime.
