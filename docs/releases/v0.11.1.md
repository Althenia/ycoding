# YCoding v0.11.1

## Changed

+ A Session that joins a Project as a member, through `project create`, a Project create or update, or the TUI new-member and add-member actions, takes the Master's effective permissions, guardrails and answers modes at join time. A later change on the member persists, goal and sleep state are not copied, and the member's subagents inherit the member's modes.
+ Questions, forms, permission asks and guardrail reviews raised by a Project member's subagents, at any depth, reach the member's owner, or the Master as an escalation when the member is unowned. They carry `requestSessionID`, appear in the member's pending list without blocking sends to it, and the owner inspects, answers and escalates them with the member's Session ID. Deny rules and permission ceilings still deny, and a Master escalation leaves the request open for the user in the requesting Session.
