# YCoding v0.11.9

## Added

+ `credential.refresh` (`POST /api/credential/{credentialID}/refresh`) forces a token refresh for a stored OAuth sign-in and returns `refreshed` or `failed` with the provider's failure text. The TUI `/connect` dialog and the web Connect provider dialog show Refresh for OAuth profiles.
+ Reconnect for OAuth profiles and Replace key for key profiles. The optional `credentialID` on `integration.oauth.connect` and `integration.connect.key` replaces that profile in place, keeping its ID and name, only after the new sign-in or key succeeds; cancelling or failing keeps the old credential.
+ Credential connections report a connection state: `connected`, `expired` or `refresh_failed` with its message. Both dialogs show the state of each profile.
+ The relay operation `provider.auth.refresh` refreshes a profile from the web.

## Changed

+ When a request fails with HTTP 401 on a stored OAuth sign-in, the runtime refreshes the credential once and retries once. If the refresh fails or the retry is rejected again, the request fails with an error that names the provider and says to reconnect it. Muse returns its final 401 to this path.
+ Managed Claude profiles now refresh through their credential store.
+ API keys typed in the TUI are masked.

## Fixed

+ The TUI Dots connection dialog no longer fails "Use this computer for Dots tasks" and detach with "The operation timed out." after 5 seconds. Attach and detach wait up to 90 seconds and status reads and access changes up to 30 seconds, the same budgets the web dialog and the service use, so a slow service still reports the attached or detached computer.
+ The TUI Dots connection dialog no longer stays on "Waiting for current status" with a "(last reported)" connection while its two-second refresh runs. The current status and its actions stay available until a refresh fails.

## Limits

+ The refresh-failed state is kept in Server memory and resets on restart.
+ Reconnect and Replace key require re-selecting a profile that a Session explicitly bound.
+ Refresh failure text is the provider's own text; the relay strips control characters and caps it at 2048 characters.
