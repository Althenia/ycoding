# YCoding v0.11.9

## Added

+ Settings and Usage sections carry a numbered `§01`, `§02`… marker before their headings. The numbers follow the sections actually shown, so Office on a phone leaves no gap, and screen readers skip the marker. Usage keeps its icon-led headings and the Group select.
+ Every transcript turn opens with a folio head: a `§NN` marker, a role label, and the turn's delivery receipt or response details. Markers keep their number as older history loads and the window scrolls, and a turn whose position from the start of the Session is not reported shows no marker.
+ Usage figures and labels use larger figure type with uppercase labels, so spend and generation values read at a glance.
+ `dots.name` in trusted global configuration sets the label this computer shows in ChatGPT's computer lists: 1–100 printable ASCII characters without leading or trailing spaces. Without it, a new registration uses the host name followed by a six-character suffix derived from this installation, such as `studio.local (3f9a1c)`, so computers sharing a host name stay distinguishable; an existing registration keeps its label. A rename reuses the existing registration and account binding, retires no connection, and never selects which computer is attached. The TUI and web Dots connection views show the registered name and the executor name ChatGPT reports beside the computer's host name.
+ `ycoding decision watch` settled and timeout results add a work assessment read once at exit: `completed` only with a current accepted work-completion receipt, otherwise `needs-decision`, `running`, `lost`, `background`, `unconfirmed`, `incomplete` or `idle`, with open todos, pending decisions, child tasks, running Sessions and pending inputs. Settled results include their start and end events and a command that watches the next transition. Timeout progress reads `running` only while the service reports the Session active, `unconfirmed` for an open execution the service does not report, and otherwise `idle`.
+ Code Mode `tools.chatgpt.library.prepare` reads an authorized nonempty local file of at most 20 MiB into managed attachment storage for a later Library upload. It needs `read` permission and, for a path outside the project, `external_directory` permission, and makes no network request.
+ A Dots task command can upload one file of up to 20 MiB to your ChatGPT Library through YCoding's private helper channel, selected by a leading `/usr/bin/env CODEX_APPS_MCP_URL=ycoding-library://process`. The task's sandbox, read authorization, Library permission and guardrails apply; the channel never returns credentials or signed transfer URLs, and uncertain writes are not replayed. Default and custom hosted endpoints are unchanged.
+ For source builds, `YCODING_MACOS_SIGNING_KEYCHAIN` names the keychain that holds the macOS signing identity, and `bun run install:local --preserve-computer-helper` installs the CLI and Chrome extension while keeping an existing, validated `YCoding Computer Use.app`.

## Changed

+ The remote workspace uses flat sections separated by single rules instead of nested frames. Text fields, menus and sheets, the focus ring, and the hard-review outline keep their boundaries.
+ The desktop sidebar is a sunken spine. The current destination shows with stronger text and an accent icon, without a green fill or halo. The phone bottom bar keeps three labelled destinations with the label under the icon.
+ Connection, notice, and consent strips are flat bars with an inset status edge. Their text and actions are unchanged.
+ Sign-in and invitation pages are one narrow column under a full-width top bar, with an `or` divider between Google and the access key. Errors appear as an inset bar.
+ The Sessions list shows rows separated by rules, with plain status text and underline filters. Rows grow with their content. Appearance and Office choices in Settings use the same underline style, and Settings records, devices and notification choices are ruled rows.
+ Question options and guardrail decision grades in request forms are ruled rows. The selected option shows a coloured start edge and heavier text. The hard-review outline is unchanged.
+ The reading position stays steady when the sidebar collapses or the transcript re-wraps at a new width, including rows that gain a folio head.
+ The Office roster, inspection card, and attention bar use the same flat rows. The Office floor is unchanged.
+ Sessions that the Dots executor creates for its tasks no longer appear in TUI or web Session pickers, searches, pins, quick switches, recent and workspace lists, Project Session choices, the TUI Chrome directory chooser, or the web Session carousel. `session.list` with `background: "exclude"` omits them before ordering, cursors and limits; without it every Session is listed, and opening one by ID, its history and native Dots root listings are unchanged. Roots started through Dots stay listed.
+ A one-time startup migration adds the Session origin and marks existing Dots executor Sessions that a current executor mapping still names; an executor Session whose mapping was already replaced stays listed.
+ `dots.attach` and `ycoding dots attach` forward the Dot, thread and environment shown before confirmation as `expectedTarget`, and the attachment is refused when the observed target has changed. The TUI and web ask for confirmation before replacing your other computers. Calls without `expectedTarget` remain valid.
+ `ycoding decision watch` exit 0 reports only that an execution settled, never that the work is finished, and `--family` includes the work of a root Session's descendants.
+ The service keeps one installation ID in `remote-control.json` and shares it between the native Dots connection and the Dots executor. A state file whose installation ID is missing or unreadable is an error and is never rewritten.
+ A Library upload whose account changes after the upload started is reported as uncertain and is not retried.

## Fixed

+ Dots capability discovery reloads after its file watcher fails instead of trusting a stale cached result.
+ Opening a subagent from Team selects it directly. Main is no longer offered for the previous parent while the subagent opens, the parent Session is not read again, and Main returns to the same reading position and draft.

## Limits

+ The web Session lists send `background: "exclude"`, which a YCoding service older than v0.11.9 rejects. Update the service on each connected computer so its Session lists load.
+ Display labels never let several computers stay attached: attaching this computer still detaches your other computers from the Dot.
+ Live Library delivery through ChatGPT from a Dots task is unverified.
