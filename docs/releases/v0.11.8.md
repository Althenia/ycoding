# YCoding v0.11.8

## Added

+ The YCoding service keeps this computer's Dots executor online while Dots access is On. It reuses one stored device enrollment, reconnects after drops with backoff, runs Dots task commands and file operations under local permission checks, and stops when access turns Off. Each ChatGPT Dots task gets its own YCoding Session in the task's folder, which records the task's commands, file changes and denials; Dots can list your YCoding projects and pick one as the task's folder. After a dropped connection, a Dots task can resume its executor session, including running commands, for 30 seconds.
+ A Dots action that needs your decision is refused at once without running. It opens a review item in the task's Session and returns the exact `ycoding api session.review.decide` commands for once, always or reject; hard reviews offer no always. After you approve, Dots retries the identical action; a rejected action stays refused, and a full review box refuses without opening an item. A file, directory or working directory outside the task's folders asks `external_directory` for its resolved directory, and explicit denies still refuse.
+ `ycoding decision list [--json]` and `decision.list` (`GET /api/decision`) list pending permission asks, guardrail asks, questions, forms and open review-box items across Sessions and Locations, with their exact decide commands. Requests are read only from loaded Locations; listing does not start services to find more.
+ `ycoding decision watch <session>` waits on one Session and prints one bounded result: exit 2 with up to 20 pending decisions and their decide commands, exit 0 when the execution settles or the input is rejected, exit 3 with progress after its timeout (default 300 seconds), and exit 1 on an error. With `--input`, succeeded, failed or interrupted is reported only when retained history proves which execution ran that input; otherwise the status is `unknown`, which is never reported as succeeded. Its resume command keeps `--server` or `--standalone`. The watch never answers, approves or retries a decision.
+ `ycoding dots attach` and `dots.attach` (`POST /api/dots/computer`) attach this computer's Dots executor to your Dot, which ChatGPT's own settings cannot do for a computer other than the one ChatGPT runs on. Attaching detaches your other computers from the Dot, so the command asks for confirmation unless `--yes` is given and reports the state ChatGPT lists afterwards. Dots status and the TUI and web Dots connection views show whether this computer is attached.
+ Native Dots clients can create a root Session in any existing local directory, and rename, archive, unarchive or delete eligible roots. Delete removes the whole root family only when no descendant is foreign-owned.
+ The service installs the bundled `ycoding-operator` skill where this computer's Dots executor advertises it to Dots; YCoding's own Sessions do not load it. Whether ChatGPT reads that skill location is unverified.

## Changed

+ The installed `ycoding` executable now includes `ycoding api`, `ycoding decision` and `ycoding dots`. `ycoding api` keeps a non-2xx response body on stdout, prints `ycoding: API request failed: HTTP <status>` on stderr, and exits 1.
+ Pending permission, guardrail, Form, Question, deferred-review, recovery and managed-child decisions on eligible roots reach the native Dots client immediately, including roots it has not opened.
+ Native Dots `initialize` and executor environment information report `macos` and `windows` for those platforms.
+ The Dots executor runs ChatGPT commands and file operations that request a sandbox instead of rejecting them. It applies the requested filesystem restrictions to its own file operations and to the command's working folder, under your home directory and the usual permission checks, and reports a refusal as a sandbox denial so ChatGPT can ask for approval and retry. Commands still run with your user account's access: YCoding cannot confine a running program's file or network access.
+ Any local process with access to the service, including the Dots agent, can record a review decision; the decision API does not establish that a person supplied it. Deny rules and the review-box cap still apply. Stop in Dots does not stop a command on this computer: the command runs until it exits, reaches the 600-second default limit, is terminated explicitly, or its executor closes. Messages and results of other YCoding Sessions are not pushed to Dots; use `ycoding decision watch` to learn them.

## Fixed

+ Direct OpenAI Responses requests for GPT-5.6 and later keep eligible earlier message boundaries as cache lookup markers, so growing conversations can reuse previously cached prefixes. For supported OpenAI and Anthropic models, changing effort keeps the earlier effort and applies later choices as chronological updates; a profile-label change keeps that history only when the account identity is known and unchanged. ChatGPT Codex requests remain key-only, and no cache hit is guaranteed.
+ A short-lived command that loads global configuration and stored credentials exits once its work finishes, even when it finishes before the configuration watcher has started.

## Limits

+ `ycoding decision watch` prints its result when it exits. The executor forwards command output as it is produced, but when Dots reads that output is not specified, so the watch does not rely on Dots reading output before exit.
+ Pending decisions are a point-in-time read: a listed item can settle by its Session's own mode or appear twice while it moves to the review box. Each decide command rechecks it.
