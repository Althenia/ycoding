# YCoding v0.11.8

## Changed

+ The Master and supervisors now settle every member request themselves through `project answer` in every autonomy mode, including Manual: routine, decline-only and explicit-decision requests, hard, custom-rule and outside-repository guardrail reviews, permissions, and questions and forms. Approve allows a request once, decline rejects it with the rationale as the member's feedback, and an answer settles a question or form. Deny rules and permission ceilings still hold, so an approval of something they cover stays denied. A guardrail review raised by an invalid guardrail configuration cannot be approved because its deny rules are unreadable: `answer` returns `escalated` with reason `configuration-invalid`, and a decline settles it. Supervisors resolve their members' issues and take to the Master only blockers they cannot resolve or coordination needs across members, and the Master resolves supervisor escalations itself.
+ A member request reaches you only by escalation: a coordinator's explicit `escalate` (member → owning subagent → Master → you), or an `answer` that refuses, errors or is uncertain and returns `escalated` with a reason the coordinator then escalates. Project inspect reports each request's delegation class (routine, decline-only or explicit-decision) as risk information for the decision. The Master and supervisor prompts and the Project tool description state this rule.

## Fixed

+ `project create` accepts an optional `repository`, an absolute directory path inside a Git repository. The member's worktree and Session are created in that repository, so a Master whose Location is not a Git repository can create members. A `repository` outside any Git repository fails naming the path, and omitting it keeps using the Master's current repository.
+ Commands that call `ycoding api` or `gh api` inside shell loops no longer trigger an outside-repository review, and the advisory scan no longer warns about API paths, `/dev/null` or temporary directories.
+ Project coordinator Sessions can run read-only commands such as `ycoding api GET`, `gh run view` and `gh run list`; commands that change anything stay blocked.
+ Deletion deny rules (deleting the filesystem root or home directory) now also apply inside shell loop and conditional bodies.
