# YCoding v0.8.4

## Added

- `ycoding update --force` (`-f`) restarts the background server even while Sessions are running. It prints how many running Sessions it interrupts before restarting. Without running Sessions the flag changes nothing, and it never overrides a failed read of the server's running work.

## Fixed

- The composer's agent and model pickers stay usable. A connection heartbeat is not treated as a reconnect, so the Session catalog is kept for the life of the connection, and a catalog that is missing while the connection is open is requested again.
- `ycoding update` reports the number of Sessions that are running. Queued input, an undelivered subagent notice, and an active goal do not count as running work and do not delay the restart.
- A Session whose execution was ended by a stopped server is settled as interrupted on the next server start and raises attention, so it no longer reads as idle. It is never resumed or retried automatically.

## Upgrade notes

- Run `ycoding update` on each machine. Use `ycoding update --force` to restart the background server without waiting for running Sessions to finish; they are interrupted and are not resumed.
