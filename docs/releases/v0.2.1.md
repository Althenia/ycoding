# YCoding v0.2.1

## Fixed

- Automatic TeamView observations no longer append another durable notice when only task revisions or task, progress, and question timestamps change. Timestamp and revision-only updates no longer grow model history or reorder the selected children.
- Long TeamView snapshots remain bounded to 32 KiB with an omitted-child count, and empty updates still explicitly clear a previously observed team.

## Changed

- Automatic TeamView observations use a model-facing projection that retains child and parent identity, description, agent and model, background mode, lifecycle state, progress text, and question identity, text, and data. Explicit TeamView inspection, subagent-control output, task persistence, and protected-state revision and digest tracking retain the complete operational metadata.
- Previously delivered observations remain byte-for-byte historical messages; a changed projection is appended at the next normal observation boundary and earlier history is never rewritten. Session-state observations continue to include full todo content, status, priority, autonomy and goal state, and permission ceilings.
- Provider request regression tests cover append-only chronological observations, preservation of earlier prepared blocks, early and recent cache anchors as history grows, and Codex cache-control exclusions. These checks verify wire construction only and do not imply a higher live cache-hit rate or lower cost.
