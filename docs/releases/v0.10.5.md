# YCoding v0.10.5

## Changed

- Tabs controlled by YCoding through the Chrome extension show the `Ⓨ` mark before the page title instead of the `[YCoding]` text, and the in-page cursor label shows the YCoding mark.
- The `worktree` tool no longer asks for permission by default; the read-only BTW advisor still asks.
- Guardrails review fewer harmless commands: read-only commands (including after `cd` or `|| exit`), read-only parts of mixed commands, interpreter script paths such as `python3 ~/script.py`, and program text in `python3 - <<'PY'` heredocs no longer trigger an outside-repository review. Hard reviews and real outside writes are unchanged.
- A shell started while the session family already runs its maximum number of shells waits up to 60 seconds for a free slot, in arrival order, instead of failing at once. Change the wait with `guardrails.shell_wait_seconds`. When the wait ends without a slot, the error names the limit and the running shells instead of reporting a guardrail rejection.
- MCP servers connect with protocol revision 2026-07-28 over stdio and Streamable HTTP when the server supports it, and fall back to the `initialize` handshake (2025-11-25) otherwise. A local server is started once per connect, the version probe waits at most 5 seconds, and a server known to use the older revision is not probed again until YCoding restarts. MCP OAuth sign-in validates the authorization server's `iss` before redeeming a code, and a stored MCP credential is used only with the authorization server that issued it.

## Fixed

- OAuth-authorized remote MCP servers stay signed in when their authorization server rotates refresh tokens: every connection uses the latest stored tokens of the active profile, concurrent refreshes in one process share a single token exchange, and a stored credential is removed only when the server rejects the refresh token it still holds.
