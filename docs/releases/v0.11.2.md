# YCoding v0.11.2

## Changed

- Native Dots controls offer Unbind with a separate confirmation. It releases only the Session's local attachment, preserves its draft and leaves the external Dot running; a fresh confirmation can bind a destination again.
- Session titles lead with the distinguishing action and subject. Built-in primary agents and Project controllers delegate bounded implementation, retain integration ownership and reuse valid verification evidence.
- A parent Session can change the selected model for one directly owned child Session. The switch applies after the current logical Step finishes, without interrupting or replaying work; idle children remain idle. The profile binding, questions, task state, permission ceiling, ownership and launch retry identity remain intact. A stale expected selection or incompatible context, provider connection, profile or variant leaves the selection unchanged. Reading the selected model does not prove that a provider request was made with it.
- Projects keep selection stable and provide direct Add session and Members actions. Enter opens the Master; wide-layout member previews open the selected member.
- Project Session pickers show titles and directories on separate rows, retain complete selected details, and filter without taking editing keys away from Find. Assigned Sessions stay visible but unavailable when choosing an existing Master; Add session lists unassigned candidates.
- Project creation retains form values and a confirmed new Session when membership fails. Retry checks membership and reuses that Session; an unknown creation outcome blocks another creation. Recovery lasts for the current TUI lifetime.
- Dots destination confirmation offers an optional display name for that attachment. Renaming requires confirmation and sends nothing. Named task exchanges identify the name as user-chosen external-peer text, with canonical source and target identities in secondary details; names grant no additional authority.
- Relay MCP provides explicit Dots task exchanges with a target Session, confirmed attachment and program-stamped routing identity. Eligible Sessions in the existing device-authorized inventory can be addressed without a native Master gateway; managed-child and human-only controls remain enforced. Correlated results and uncertain admissions are read without replaying work. Raw room messages, replies, revisions and echoes do not admit tasks.
- Native Dots delegation requires a separate human-only approval and allows only Continue or approved presentation preferences for one selected, existing human-authored task. It stays bound to that task, the authenticated coordinator, approved operations and current attachment. It cannot admit new work, answer native Forms, permissions, guardrail reviews or managed-child questions, control child Sessions, or expose Dots credentials or live native controls.
- Compact Dots notices summarize trusted enabled or disabled coordination state in chronological transcript position. Invalid notice metadata reads as unavailable; the TUI shows neither serialized metadata, generation values nor raw instructions. The TUI also hides the unnamed canonical Remote MCP attribution banner while retaining the body, canonical metadata, model context, web attribution, native Dot headers and named-exchange headers.
- Dots task reports carry program-generated source and reply headers. Enabled and disabled context is appended without rewriting earlier messages; completion notifications carry the native input identity. Report delivery still requires the receiving host's configured notification flow.
- The phone composer keeps its draft, attachment controls and send actions usable in a compact layout, with submission controls arranged for narrow screens. Usage filters reflow into a phone-friendly view while retaining provider, profile, model, effort and range selection; the status bar and settings controls adapt to the available width. Usage incident details and cost/accounting views preserve their selected context on mobile.
- Native pending-request notifications retain bounded origin, review-class and inspection/handoff metadata across delivery retries and restart cancellation.
- YOLO option assessments show the evaluator-reported confidence and evidence for each actual option. A single-choice recommendation requires a unique highest-confidence option at or above 0.8; a multiselect recommendation requires a separately validated compatible set of actual options meeting that threshold. The TUI and web show Assessing options while a YOLO assessment is pending, then the reported assessed or unavailable state and reason. A validated recommendation may answer automatically; weak, ambiguous, invalid, refused, failed or timed-out assessments leave the question waiting for you rather than inventing a recommendation. For these option questions, Manual and Auto make no model call and show Not assessed. Settled views distinguish automatic YOLO answers from answers supplied by you. Assessments do not approve unrelated actions.
- **Breaking Change:** Relay MCP exposes request inspection and coordination, not native human or parent settlement tools. Complete permission, guardrail, Form, review-box and managed-child answer decisions through authenticated native controls; native/browser controls and existing native delegation remain available.
- Remote MCP input retains external-source attribution in model context and durable metadata. Web attribution and native Dot and named-exchange headers remain visible; the TUI omits only the unnamed canonical Remote MCP banner. It cannot supersede native human-only questions or reviews, wake a sleeping family as a human prompt, or grant approval authority. Changed accounts, attachment generations, ownership and archived Session families block exchange admission or results.

## Fixed

- Antigravity uses the OAuth client pair embedded during native and Node builds for sign-in and token refresh. The release build receives the configured GitHub secrets; installed clients ignore runtime overrides. Custom builds must supply both client values at build time.
- Confirmation dialogs let Up/Down move through choices, keep Cancel and Confirm visible while details scroll, and settle a selection once.
- Mobile Usage, composer, Settings and Status layouts retain their controls without horizontal clipping. Usage filter selection and incident details remain available on narrow screens, and device-alias editing keeps its controls within the compact layout.
- BTW headers reflect that Session's own pending and execution states, omit the redundant agent name, and shorten long paths to fit alongside the remaining identity details.
