# YCoding v0.10.12

## Added

- Meeting owner settings select the model and variant for future Ask AI questions and add, remove, enable, or disable MCP connector bindings. Open the private owner link from the CLI or TUI; ordinary view links cannot change configuration. Knowledge writes still require approval, and changing a variant preserves the selected account profile.

## Changed

- YOLO has three named levels: 0 Ask first (manual), 1 Allow tools (approves permission asks only), and 2 Tools + reviews (also approves ordinary guardrail reviews while awake). A Session saved at level 3 moves to 2 automatically, and asking for level 3 is rejected. A goal only continues work; it approves no permissions, answers no questions, and settles no reviews.
- Automatic question, form, and subagent-question answers are a durable per-Session `/auto-answer` toggle, off by default. It is independent of YOLO level, goals, and sleep, applies only to the Session it is set on, and is not inherited by subagents or the parent. While asleep with it off, those requests wait in the review box without calling the model.
- The global `auto_answer` setting is replaced by `/auto-answer`. Remove `auto_answer` from your configuration and turn `/auto-answer` on in each Session that needs automatic answers.
- The terminal and web controls show the Session's actual effective approval and auto-answer settings. Hard guardrail reviews are still enforced when ordinary guardrail reviews are disabled.

## Fixed

- Idle or running root Sessions whose background-work result was lost show "Background result lost" instead of "Waiting for you" when no permission, question, or review is open, and the System alert says a background result was lost. Loss-only roots stay out of the Waiting filter, order, and dots. Update the connected runtime to receive the reason; an older runtime cannot send it.
