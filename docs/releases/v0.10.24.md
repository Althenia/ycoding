# YCoding v0.10.24

## Fixed

- Relay MCP Events subscriptions and deliveries stay available when several devices share one network address. The relay gives each enrolled device its own budget of 300 MCP Events authorization requests per minute, and it limits only failed authentications by address.
- The local connector checks MCP Events support at most once per relay connection and Relay MCP authorization. Grant resolution and grant checks still reach the relay on every subscription and delivery, so revocation, expiry, and disabling Relay MCP take effect as before.
- A failed relay authorization request writes a remote-connector diagnostic that names the action and the cause (`rate_limited`, `unauthorized`, `forbidden`, `unsupported`, or `unavailable`), at most once per minute for each action and cause. A delivery postponed because authorization is temporarily unavailable logs `MCP Events delivery deferred`.
- Registered local app tools report a relay authorization rate limit as `rate_limited`, and a relay outage, timeout, or explicit unavailability as `agent_unavailable` with reason `authorization_unavailable`, instead of `forbidden`. A rejected credential, a revoked or expired grant, and a Relay MCP disable still report `forbidden` with `access_unavailable`. A grant rejected during an app request no longer reports `upstream_unavailable`.
