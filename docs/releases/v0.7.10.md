# YCoding v0.7.10

## Added

- Choose the active machine from the new **Machine** section at the top of remote **Settings**.
- Remove revoked devices from remote **Settings**, one at a time or all at once, after confirming. Active devices stay enrolled.
- Switch the remote **Usage** page between UTC and your local time zone with its **UTC | Local** switch. Days, months, and hours follow the choice, which the browser remembers. The local server's usage report routes accept the same choice as an optional IANA `timeZone`.
- Hide or show the Sessions sidebar next to a remote Conversation on desktop; the browser remembers the choice.
- Reopen remote **Activity** on the last Session you used on this machine after a reload, or choose a running or recent Session from its picker. Switching machines or signing out clears the saved choice.
- See loading placeholders instead of blank space while the remote workspace loads your account and machine, the Sessions list, the repository picker, Team, shell output, Office, and Usage. They appear only after 140 ms, stay still when reduced motion is on, and a refresh of the same machine keeps what is already shown.
- Read or switch the machine's remote connection from local HTTP integrations with the authenticated `GET /api/remote` and `PUT /api/remote` routes.

## Changed

- Keep the machine's remote connection in its background YCoding server instead of a TUI or a terminal, so it stays on with no TUI open. Every TUI shows the same **Remote connection** state and can turn it on or off. `ycoding remote connect` now turns the connection on and returns (with `--standalone` it still runs in the foreground until Ctrl-C), the new `ycoding remote disconnect` turns it off, and `ycoding remote status` shows whether it is off, connecting, on, or failed.
- The remote carousel, now **Running and recent**, shows up to ten Sessions: running Sessions first, including one whose subagents are still working, then the most recently active ones. Each card shows Running or when the Session was last active.
- Keep the Conversation–Office switch and **Team** together in one bar above the scrolling workspace on tablets and desktops, so they stay in place while the transcript or Office scrolls.
- Center the remote **New session** screen under the full YCoding logo, with the repository picker aligned to the composer.
- Set a Session's autonomy level and goal only from its Conversation status; Settings no longer has an Autonomy section. **Desktop alerts** in Settings shows the permission button only until the browser decides, then whether alerts are allowed or blocked.
- Move Office characters more calmly: a character changes rooms only after its activity holds for three seconds and it has spent five seconds in its current room, walks to the Lounge only after six idle seconds, and eases in and out of each walk. Characters no longer show emote icons.
- Show desktop alerts through the site's service worker, so they also appear in browsers such as Chrome on Android, and show one notification when a desktop alert and a push alert report the same event. The installed app opens directly to the remote workspace.
- Align rows in the notification center. With a mouse, Dismiss replaces a notice's time while you hover over or focus it.
- Read Usage data for every Session in one batch instead of one Session at a time. On a machine with about 15,000 Sessions, that database read took 0.08 s instead of about 1 s.

## Fixed

- Show images and files attached to a remote prompt while it waits to be delivered, instead of failing to load them.
- Open the Session you choose while **New session** is open instead of staying there, and stop Back from returning to New session.
- Show a Session as running in the remote carousel and the **Running** filter while its subagents are still working.
- Restore push alerts after the relay drops this device's subscription: opening the remote workspace registers the subscription again, replacing it first if the relay's key has changed.
- Keep Usage values in place when a request's outcome is unknown after a reconnect, and retry that request once when the machine is reachable again.
- Stop the remote status timer from counting from an earlier run: each run starts its own timer, and a main Session, or a subagent it started, that went idle while the page was disconnected no longer shows as running once the page reconnects.
- Show the Session's state in the phone composer status instead of repeating its YOLO level when the Session has no running timer of its own, such as while only its subagents work.

## Upgrade notes

- Reload the remote workspace to load the updated browser client.
- Update YCoding on each machine, then open the TUI or run `ycoding service restart` so its background server runs the new version. The Remote connection on/off setting carries over.
- Stop any `ycoding remote connect` from an earlier version that is still running in a terminal. While it holds the machine's remote connection, the updated server reports an error; select **Remote connection** again after stopping it.
- Local time on the Usage page, running status for Sessions whose subagents are working, and attachments of waiting prompts need the updated YCoding on the machine. With an earlier machine, the Usage page asks for an update when you choose Local.
