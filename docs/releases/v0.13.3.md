# YCoding v0.13.3

## Added

- Open the Swarm board from a Project to see its Session hierarchy, owners, task dependencies, handoffs, results, and pending decisions. Start a Swarm from an eligible root Session and send the first assignment there to activate it without losing the Session's history or settings.
- Swarm records assignments and their results against stable task IDs. When a task waits for permission or another prerequisite, its dependents wait and independent work can continue.
- Desktop and Web can show read-only MCP Apps previews from completed tool calls. The preview runs in an isolated frame.

## Changed

- The native Dots executor runs requests from the authenticated Dots connection as the host user, without sandbox, Permission, or Guardrail checks and without limiting them to a workspace. It needs no executor entry in configuration. Turn Dots access Off to revoke it.

## Fixed

- The native runtime starts on large stores. Startup recovery settles leftover shells, lost-shell notices, and interrupted steps in bounded batches, and a usage-data rebuild that exceeds its deadline continues in the hourly maintenance run while startup completes. A startup failure names the stage that failed, for example `production composition failed: shell ledger`.
- Startup logs now show how long store preparation, recovery, and readiness take. Startup skips a redundant decode after it recognizes the current usage format. Analytics maintenance reuses a compatible store and yields during slow rebuilds. Web latency recording acknowledges samples once they commit, even if analytics maintenance is delayed.
- Remote connection shows why it could not connect. A failed status read shows the read error and leaves the saved choice unchanged. A connector failure after turning it on identifies what failed, including a rejected device, a declined WebSocket upgrade, or a socket that closed before Remote became ready. `ycoding remote connect` uses the local backend’s enrollment and reports the result of enabling Remote.
- Desktop and Web keep Project and Session context visible alongside the conversation. Intelligent UI tables keep their sort and keyboard focus when the transcript refreshes.
- The TUI Session picker searches Recent separately from the full Session list. The model picker distinguishes routes that share a provider label.
- The Chrome extension popup lets an in-flight connection status read finish before starting another one.
- Sessions retry interrupted provider responses when doing so is safe. A retry replaces the unfinished draft, and a completed tool result carries forward without running the tool again.

## Removed

- The `dots.fullAccessExecutor` setting is removed. Delete it from global configuration: while the key is present, configuration reports it as an unknown `dots` key and native Dots stays off.
- Antigravity and Muse are no longer available for sign-in or model requests. Sessions and configuration that still select either provider report `Provider no longer supported`. Select a supported model and profile to continue. Existing history and saved credentials remain unchanged.

## Installed Desktop observations

The installed macOS comparison used three launches per revision. Median launch time went from 1230.5 to 1405.3 ms, median Session open from 170.1 to 190.7 ms, median refresh from 169.1 to 140.5 ms, and refresh p95 from 8563.9 to 8754.9 ms. Median host RSS went from 590256 to 452800 KiB. These measurements describe those runs.
