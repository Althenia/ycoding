# YCoding v0.13.5

## Added

- Cue & Recall v2 chooses context from one retrieval contract across memory, skills and transcripts. Selection combines BM25 with embeddings, falls back to lexical matching when the embedding model is unavailable, and applies per-kind and total size budgets.
- Each trusted cue and each recall selection becomes a durable Session event, so the TUI, Web and Desktop transcripts show why context was added. Refused candidates stay in the record with their reason, and a retry never records twice.
- The Session runner records each Step's outcome (finished, follow-up or recovery) as a durable `session.lifecycle.recorded` event. A retried or answerless turn appears in the TUI, Web and Desktop transcripts as a collapsed row.
- A `harness` configuration section turns on harness adaptation in `disabled`, `adaptive`, `parallel` or `sequential` mode, with probe budgets and an authorization ceiling. When the section is present, the runner prepares a harness version before the first Step, appends the version's prompt and tool-guidance items to the system prompt, and reflects after the run settles. Probes are dry replays through the helper model with no tool execution. Adaptation keeps only edits with contrast evidence that stay inside the ceiling, never replaces or removes a guardrail, publishes each result as a reversible, content-addressed version, and records lessons from finished tasks as experience concepts in workspace memory. Five `session.harness.*` events record evaluation, probes, adoption, rollback and reflection, and the transcripts render them as collapsed rows.
- Permissions, Guardrails and Answers each have a saved default mode that new root Sessions start in. The Autonomous control in the TUI, Web and Desktop shows each category's default, saves the selected Session mode as the default, and resets a default to Manual. Saving a YOLO default asks for the same explicit risk acceptance as enabling YOLO in a Session and records it beside the default; a save without acceptance is refused. Set the same defaults in the global configuration with `autonomy.defaults`; project configuration cannot set them. Existing Sessions, child Sessions, defer, permission ceilings and deny rules behave as before.
- A refused subagent launch records the durable `coordination.subagent.request.blocked` event on the requesting Session with the requested agent, the reason (`concurrency-ceiling`, `agent-missing`, `permission-denied`, `project-paused` or `route-unavailable`) and the refusal message. No child Session, task or job is created for a blocked request, and a paused Project refuses launches.

## Changed

- Memory reads and writes OKF v0.3 with typed concepts, source footnotes, lifecycle metadata and recoverable trash. Validation checks every concept's frontmatter against the v0.3 content schema and reports the field and specification section without quoting the rejected value.
- A declared v0.3 bundle ignores the legacy `timestamp` key for trust and freshness. A footnote definition is no longer read as a link, which removes false broken-link reports.
- Skills follow the Agent Skills specification: a skill is a `<directory>/SKILL.md` file whose `name` equals the directory name, and activation metadata covers events, commands, paths and keywords.
- Swarm execution is the default driver of all work and comes from the shared base prompt, so every Session gets it: a Project Master, a Project member or a standalone Session. Whoever coordinates splits work into independent lanes, launches every ready lane at once, and runs its own integration and verification while they run. Each lane delegates independent subtasks to native subagents where its tools grant them. Dependencies, overlapping writes and shared integration stay serialized, and one writer owns each file, ref or build output. Built-in agents and configured agents with their own `system` text start from the same base prompt, and utility agents keep their own.
- The built-in `decision-input` instruction and the shared base prompt direct every Session to resolve blockers and issues itself: diagnose the root cause, try every local compliant fix, recover from failed checks, conflicts and environment errors, and keep working toward the goal without stopping at milestones, status reports or questions that evidence can settle. Permission, guardrail and human-only approval requests and missing secrets or credentials still go through their native controls.

## Removed

- Project Artifacts and the `project_artifact` tool. On upgrade, the store drops their tables, deletes their Session events and boundary messages, and strips artifact provenance from stored events, messages and pending inputs.

## Fixed

- The TUI resends a request that failed as unsent once the connection returns, and shows a transient connection notice instead of an error toast when the resend cannot complete. Unsent errors name what did not happen, and a resynced event stream resubscribes in place.
- A prompt-size overflow at the hard input cap is fixed.
- A Location boot no longer discards the Usage that was just published. The global Usage epoch changes only when the booted Location's cached prices differ from the current catalog, so quota publication no longer waits for a second full rebuild after a cold start (about 12 s on a 200,000-row store).
