# YCoding v0.10.22

Live app preview stays disabled in this release, and its hosting is not approved. Per-registration isolated preview origins remain a deployment prerequisite: an owned isolated domain with provisioned exact hosts, pending the owner's approval. Each origin serves one registration ever, so a single `workers.dev` hostname could serve at most one preview. Enabling also requires the connector on the owner's machine to run v0.10.22 or later with `appPreview` configured.

## Added

- Registered local HTTP apps can be previewed in a browser through a separate `ycoding-preview` Worker once preview origins are configured. Each registration receives its own single-use origin, which is never reused after expiry, revocation, disconnection, or a restart; when every configured origin has been used, `local_app_open` fails with `preview_exhausted`.
- `local_app_open` returns a short-lived, single-use bootstrap URL. The app is then served under `/_r/<lease tag>/` on its origin, so it must use relative URLs; the browser's partitioned `__Host-ycoding-preview` cookie reaches only the machine and lease that issued it, and only `GET` and `HEAD` requests pass through. Requests with a stale path or cookie are rejected before reaching any app, and unknown, used, revoked, and expired credentials are refused at the Worker without contacting any machine.
- `appPreview` in the global `remote.json` lists the preview origins, the loopback ports eligible for preview (for example `8767` only), and the origins allowed to embed the preview. Without it, or with an empty list, preview stays off.
- Operators can deploy the preview Worker with `bun run deploy:cloudflare-preview`. The release workflow deploys it after the relay only when the `YCODING_APP_PREVIEW_DEPLOY` repository variable is `true`.

## Changed

- The relay Worker provisions the `PreviewDirectory` Durable Object and reads a `PREVIEW_ORIGINS` setting, which is empty and therefore disables app preview. Connectors that do not configure `appPreview` send and receive no preview frames.
- Revoking a local app, turning Relay MCP or Remote off, and disconnecting end that machine's preview access at the relay.
- The sidebar AUTONOMY section no longer has a separate YOLO row; `/yolo` and its palette entry toggle it. Permissions, Guardrails, and Questions each read `auto` while their rule switch decides, otherwise `yolo` while YOLO is on, otherwise `manual` (`review box` while asleep), including while baseline model review runs first.
- Guardrail model assessment, both baseline `decide_reviews` and the YOLO evaluator, allows an ordinary review whose every command part only reads, lists, or searches, regardless of how much or where it reads. When the reads likely target production secrets, API keys, or credentials, the model weighs purpose and exposure before allowing, denying, or escalating.
