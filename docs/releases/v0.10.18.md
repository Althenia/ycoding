# YCoding v0.10.18

## Changed

- Required-answer questions, Forms, and task-backed child questions have no elapsed-time expiry. Time alone cannot supply an answer or resume dependent work. Explicit replies, cancellation, validation, auto-answer opt-ins, and permission/guardrail safety remain separate.
- The runtime configuration schema omits `question_timeout_seconds`. Remove that key after upgrading the owning backend. Retain `question_timeout_seconds: 0` on older backends until their upgrade; omitting it there restores their earlier default, and changing it does not disarm already-published requests.

## Fixed

- Settle one MCP Events subscription RPC atomically across registration, signing-secret rotation, replay reset, and response metadata. Metadata failures and interruption roll back the local settlement; authorization abort and expiry are checked before commit.
- Retry an enabled exact subscription identity without multiplying rows. Callback URLs and authorization scopes remain distinct, and disabled or revoked identities cannot be revived by refresh.
- Record categorized subscription and webhook failures without printing callback URLs, signing secrets, or raw exception details.

## Operational limitations

- Ordinary pending Forms and Question-service requests are process-local and are not restored after a server restart, even with the same database. Finish their answers or explicitly cancel them before restarting. Durable task-backed child questions retain their waiting state and exact question identity. An outbox delivery record is not a restored request.
- Hosted multi-RPC automation setup is not an atomic YCoding operation. Earlier successful RPCs survive a later host setup failure, and a lost acknowledgement after commit remains ambiguous. Retry only the same retained callback and valid authorization identity; new callbacks are separate subscriptions.
- Unmatched subscription records are candidate orphans until correlated with the host's saved automation bindings. This release does not identify ownership for opaque host records, clean up live subscriptions, or restore revoked grants. Reconcile through supported host controls and exact authenticated subscription operations.
- Task-backed questions notify and wake their parent locally at safe step boundaries. Ordinary child question Forms remain a separate human-facing route. There is no new sibling dependency scheduler or parent approval authority.

Upgrade each backend at a safe idle boundary. Publishing this release does not restart or replace an existing local backend.
