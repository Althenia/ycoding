# YCoding v0.9.0

## Added

- A managed server restart reconciles background shells left by a crashed server. On systems where process identity can be verified, YCoding terminates a surviving orphaned shell group and reports an owed completion notice as lost. The remote workspace marks the Session family for attention; it does not replay the command or resume an interrupted model request. Shell recovery is unavailable when process listing cannot verify ownership.

## Changed

- The remote connector and browser use WebSocket protocol v4. Upgrade the connector **and its managed local server** together, deploy the matching relay and web build, and refresh open browser tabs before reconnecting. A v3 connector or tab cannot use the v4 relay. Existing device enrollment remains valid.
- API operation IDs drop the `v2.` prefix, and ephemeral permission and question events use `permission.asked`/`permission.replied` and `question.asked`/`question.replied`/`question.rejected`. Update `ycoding api` invocations and event subscribers and regenerate Client integrations against the current API; the old names have no aliases.
- Custom TUI theme consumers use the semantic `theme` surface instead of `themeV2`. Built-in theme values remain matched to their existing palettes, with the selected endpoint action using a readable foreground/background pair.
- `ycoding update --force` applies an installed update even when it cannot read the running server's outstanding-work status, reporting that it may interrupt work. Without `--force`, that failed read leaves the server running for an explicit restart.

## Removed

- The unproduced `@ycoding-ai/schema/ide-event` subpath and the non-resolving `@ycoding-ai/cli/daemon` export are absent. Remove imports of either entrypoint; no IDE installation event is emitted.
- An upgrade drops the inactive `account`, `account_state`, `control_account`, and `session_share` tables while preserving Session rows. Back up the local database before upgrading; rollback requires restoring a backup. The new background-shell ledger has no down migration, so do not downgrade while shell rows still need reconciliation.

## Fixed

- Local tool-result images are analyzed for text-only models so their contents reach the model as text rather than an unsupported image part.
- A rejected terminal shell command retains its draft with explicit Retry and Discard choices instead of throwing an unhandled error or replaying a second Enter. An unknown backend outcome still requires the user to check the Session before retrying.
- Repeated Conversation–Office switches and viewport changes no longer trigger the web workspace's virtual-row ResizeObserver loop error.
