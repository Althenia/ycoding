# YCoding v0.10.10

## Added

- The shell tool has a queue channel for expensive commands such as typechecks, builds, and package-wide test suites. Queued commands from every YCoding process on the machine share running limits (two at once and one per Session by default), wait for enough free memory and a low enough CPU load, and report completion like background commands. Set the limits under `shell_queue`; the TUI and the web Team view show queued commands and their position.

## Changed

- Built-in agents commit only complete, self-contained changes: each commit includes its code, tests, docs, and release-note entries, is made after its checks pass, and has a summary that states its intent and a body that states why it exists, what behavior changed, and how it was verified.
- Built-in agents reply and write documentation, instruction files, code comments, and commit messages as directives and facts from verified evidence in the reader's own terms, without unrequested explanations, copying the request's wording, or mentioning the request or its style instructions.
- The Usage page shows the monthly provider total and its unit inside the donut ring. A total too wide for the ring is shortened to one decimal with a k, m, or b suffix, such as $2.0k; the exact total stays available on hover, on keyboard focus, and to screen readers, and the legend keeps each provider's exact value.
- Primary built-in agents start every remaining task that does not depend on running background work instead of waiting for it, and name the dependency of each task they hold back; a queued typecheck, build, or test suite delays only other heavy checks, not code-writing or review work.

## Fixed

- A shell command that runs `git push` and later another command with `-f`, such as `rm -f` or `grep -f`, no longer asks for a force-push hard review. Destructive Git and force-push checks now read each command of a compound command separately.
- The web client opens and refreshes Sessions with fewer requests. Selecting a Session reads its transcript without waiting for the subscription to be confirmed; a Session-list change rereads the open transcript only when it missed events; list refreshes keep the visible rows instead of showing loading and run at most once per 750 ms; captured changes for a Session with many subagents are read once and shared; and Usage reads only when its page opens.
- The TUI no longer shows an `UnexpectedStatus` error while another YCoding process, such as `ycoding run` or a second TUI, writes to the same local database. Saving local telemetry samples now waits for the other writer to finish instead of failing at once.
