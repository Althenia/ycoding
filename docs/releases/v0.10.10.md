# YCoding v0.10.10

## Added

- The shell tool has a queue channel for expensive commands such as typechecks, builds, and package-wide test suites. Queued commands from every YCoding process on the machine share running limits (two at once and one per Session by default), wait for enough free memory and a low enough CPU load, and report completion like background commands. Set the limits under `shell_queue`; the TUI and the web Team view show queued commands and their position.
- `/sleep` lets the agent keep working while you are away: the root Session family answers its own questions and forms, settles guardrail reviews with the decision model, and keeps the machine awake. `/wake` or any message you send in the family ends sleep and restores your earlier review setting.
- `/guardrail-decision` toggles decision-model review for a root Session family. A review is approved once when the model approves with confidence 0.8 or higher and rejected otherwise; explicit denies still apply and YOLO levels are unchanged.
- Before a standard guardrail review reaches you, the decision model checks whether the action really matches the rule, and a confident false match is dismissed without a review.
- `/keep-awake` toggles keeping the machine awake, also from web Settings → Machine. On macOS it keeps the Mac awake with the lid closed where lid control is available. Sleep holds keep-awake on until the last sleeping Session family wakes.
- Unanswered questions, forms, and subagent questions time out after `question_timeout_seconds` (default 300; 0 disables). The agent then proceeds on its own judgment, and a late answer is rejected.
- Before history pruning first deletes anything, YCoding writes a one-time verified copy of the database beside it as `<database>.pre-prune-backup`, for example `ycoding.db.pre-prune-backup`. With less free space than the database size plus 1 GiB, it prunes nothing and shows a warning at most once an hour. To restore the copy, stop every YCoding process, replace the database file with it, and delete the database's `-wal` and `-shm` files; delete the copy with `rm` once you no longer need it.

## Changed

- Built-in agents commit only complete, self-contained changes: each commit includes its code, tests, docs, and release-note entries, is made after its checks pass, and has a summary that states its intent and a body that states why it exists, what behavior changed, and how it was verified.
- Built-in agents reply and write documentation, instruction files, code comments, and commit messages as directives and facts from verified evidence in the reader's own terms, without unrequested explanations, copying the request's wording, or mentioning the request or its style instructions.
- The Usage page shows the monthly provider total and its unit inside the donut ring. A total too wide for the ring is shortened to one decimal with a k, m, or b suffix, such as $2.0k; the exact total stays available on hover, on keyboard focus, and to screen readers, and the legend keeps each provider's exact value.
- Primary built-in agents start every remaining task that does not depend on running background work instead of waiting for it, and name the dependency of each task they hold back; a queued typecheck, build, or test suite delays only other heavy checks, not code-writing or review work.
- Settled Session history takes much less disk space. About a minute after a Session's work ends, and at startup and every hour, YCoding deletes the stored events that repeat what its saved messages and records already hold; resume, transcripts, forks, reverts, snapshots, and usage keep working from what remains.
- In Sessions idle for 24 hours, images in tool results are replaced with a short placeholder giving the image type and size, which the model also sees if the Session resumes. Base64 data longer than `tool_output.max_bytes` (50 KiB by default) is omitted from stored tool metadata.
- Tool progress is shown live but no longer stored: `session.tool.progress` is a live-only event and no longer appears in `session.log` or among the durable event types of the API and its clients.

## Fixed

- A shell command that runs `git push` and later another command with `-f`, such as `rm -f` or `grep -f`, no longer asks for a force-push hard review. Destructive Git and force-push checks now read each command of a compound command separately.
- The web client opens and refreshes Sessions with fewer requests. Selecting a Session reads its transcript without waiting for the subscription to be confirmed; a Session-list change rereads the open transcript only when it missed events; list refreshes keep the visible rows instead of showing loading and run at most once per 750 ms; captured changes for a Session with many subagents are read once and shared; and Usage reads only when its page opens.
- Usage reports no longer stall other requests. Each report reads through a separate read-only database connection in steps of at most 10,000 requests, so the TUI, web, and running Sessions keep responding while it runs; on a 9 GB database the summary report dropped from about 7.8 seconds to under half a second. Startup adds three usage indexes once.
- A subagent's "awaiting input" timer in the TUI header counts from when it asked its question and keeps counting while it waits, instead of showing the time since the subagent started.
- The TUI no longer shows an `UnexpectedStatus` error while another YCoding process, such as `ycoding run` or a second TUI, writes to the same local database. Saving local telemetry samples now waits for the other writer to finish instead of failing at once.
