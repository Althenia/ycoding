# YCoding v0.7.17

## Added

- **Keep machine awake** is available in the TUI command palette and web **Settings → Machine**. On macOS it prevents idle system sleep while enabled. It starts off, is not saved, and ends when the backend stops or restarts. Manual sleep and lid closure still apply; Linux and Windows report unsupported.
- The remote composer offers **`/compact`** to compact the selected Session's context without sending the command as an ordinary prompt.
- Idle Office agents can relax around the table-tennis table, with a moving ball and playing poses. New work interrupts play; reduced motion uses still poses without the ball animation.

## Changed

- Entering **Sessions** starts at the top; entering **Conversation** shows the latest message and resumes following. Scrolling up pauses following, and switching Sessions inside Conversation preserves their reading positions. Sessions also has a floating jump-to-top control.
- Session lists and **Running and recent** place running families first, then the latest reported activity. Pins and later metadata edits do not override activity order.
- Team cards use a compact hierarchy and stable slots for tokens, cost, context, and cache. Subagent navigation and the Conversation–Office switch pair icons with named controls.
- Subagent chats keep a compact status and navigation dock on phones. **Subagent details** opens the task, usage, and parent title in a sheet, while waiting questions stay directly answerable.
- Icon controls use neutral borders and focus indicators while keeping keyboard focus visible.
- Web cursors follow shared design-system roles for actions, selectable text, disabled and busy controls, sliders, image expansion, and Office panning.
- The web app uses self-hosted **Geist Sans** and **Geist Mono**. The Chrome extension embeds its Geist fonts without external font requests. Terminal font settings remain under the user's control.
- **New session** uses a named plus-icon control in the Session list and sidebar. Agent-name headings appear on text replies rather than tool- or reasoning-only blocks.
- Successful sends do not open a toast. A small ring marks a prompt while it is being sent; failed and uncertain sends retain their error feedback and retry controls. Routine notices remain in the notification center and configured system alerts.
- Push test alerts use the admin-authenticated **`POST /api/admin/push/test`** endpoint for one registered account/subscription pair. Settings keeps the push toggle without a test button.

## Fixed

- **Work finished** requires an explicit completion declaration and successful final settlement. Ordinary replies and idle status do not trigger it, and reconnects do not duplicate accepted completion notices.
- Live background shells count as running in Session lists and Team. Settled, canceled, and timed-out shells do not remain running.
- Pending family guardrail reviews can be inspected and answered from the current Session. Phone actions stay reachable, missing context prevents blind approval, and hard reviews remain human-only.
- The web client detects silent remote connections and checks connectivity when returning to the app or network. Recovery does not automatically replay actions with uncertain outcomes.
- The installed executable recognizes **`ycoding service`** commands, including `restart`, instead of interpreting `service` as a repository directory.
- Active skills can load their resources after an earlier compaction or agent switch, with the existing path and permission checks preserved.
- The TUI's **Enter answer** field answers the specific waiting subagent question rather than queuing an ordinary prompt. Answers remain literal text, the parent exposes waiting questions without requiring its sidebar, and guardrail, permission, and form review retain precedence.
- Office waits for its initial family state before placing known agents and keeps them in place through background reads and navigation, rather than replaying their entrance.
- Background transcript, todo, and Team refreshes retain already displayed content and reported usage instead of briefly clearing it.
- Streaming code blocks and refreshed file rows preserve focus, expanded diffs, and the visible reading position instead of remounting their controls.
- TUI captured-change summaries retain available files when a child transcript read fails, label incomplete totals, and offer targeted retry without requiring a reconnect.
- Model choices retain each model's valid effort when switching back and forth. Web and TUI ordinary sends follow confirmed Session selections instead of silently restoring a stale local choice; models without effort variants do not inherit the previous model's effort.

## Upgrade notes

- **Breaking Change:** save unsent drafts and reload every open remote tab or installed web app after deployment. The new notification protocol requires the updated client; v0.7.16 tabs can reject notification frames and reconnect until reloaded. There is no old-client compatibility path.
- **Push registration reset:** after deployment, reopen each browser or installed web app. An existing subscription re-registers automatically when notification permission is granted; otherwise check **Settings → Notifications → Push to this device** and restore it if needed. The one-time server migration resets Web Push registrations; Sessions, credentials, browser category preferences, and unread notices remain intact. Background push resumes after that browser registers again.
- Run `ycoding update` on each machine, then reload the remote workspace or reopen the installed web app.
- Let running work finish before restarting the background server. `ycoding service restart` interrupts executing Sessions.
- Update the backend and browser client together for explicit work-completion notifications, accurate background-shell activity, remote compaction, and Keep machine awake. Keep awake controls the selected backend machine, not the browser or phone displaying it.
