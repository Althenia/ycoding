# YCoding v0.10.8

## Added

- A `capabilities` configuration object turns capabilities off for a run: global or project `AGENTS.md` files (or individual files by path pattern), including nested files the `read` tool injects, built-in instruction blocks by name, skills, tools, MCP servers, and external plugins by allow and deny lists, managed project artifacts, the `~/.agents` and `~/.claude` roots, and it can pin the `websearch` provider. It works in any configuration layer, including `YCODING_CONFIG_CONTENT`.
- `ycoding run --config <file>` applies a JSON/JSONC configuration document as the highest-priority layer of a private server for that run.
- `ycoding run --isolated` runs on a private server with a temporary data directory and database that are removed afterwards, so the run never touches your Sessions or database. Stored credentials are unavailable in an isolated run; provide provider keys through environment variables or configuration.
- `ycoding run --format json` reports metrics for evaluation harnesses: `step_start` includes the agent and model, `step_finish` includes the context limit, context breakdown, and provider cache diagnostics when reported, and one final `run_finish` line gives the status, duration, steps, turns, tokens, cost, context size, and models, plus the usage, steps, and turns of the whole run including subagents and helper Sessions. Default text output is unchanged.

## Changed

- History that a finished local compaction removed from model context is deleted by the startup and hourly retention sweep, shrinking the database. Sessions compacted by Codex remote compaction keep their full history. Copy and export start at the compaction checkpoint summary. Forking or reverting to a message in removed history reports an error and changes nothing. Failure events from the removed range are kept for 7 days.

## Fixed

- Opening the shared database from another YCoding process, such as `ycoding run --standalone` or `serve --stdio`, no longer marks a running service's active child tasks as lost. Each active child task records its owning process, and only tasks whose owner process has exited are marked lost when a process starts.
- Built-in guidance for a tool the agent cannot use, such as workspace memory while memory is disabled or `decision` while it is denied, is no longer included in the instructions.
