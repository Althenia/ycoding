# YCoding v0.10.19

## Added

- Independent `/auto-permission`, `/auto-guardrail`, and `/auto-answer` controls alongside an on/off `/yolo` switch. Rule-based automation and agentic evaluation have separate settings in the TUI, remote workspace, and noninteractive CLI.
- Hidden permission, guardrail, and answer evaluators with inspectable decision provenance. Hidden evaluators stay out of normal agent selectors and have no execution tools.

## Changed

- Baseline permission and guardrail assessment uses structured `allow`, `deny`, and `escalate` choices with bounded evidence. `guardrails.decide_reviews` enables it when omitted; explicit `false` disables this baseline path independently of Session controls. Hard-rule false positives can be assessed, but genuine hard reviews and explicit denials retain their policy boundaries.
- **Breaking Change:** autonomy writes accept Boolean YOLO and separate Boolean automation flags, not numeric levels. Update API callers and regenerate clients with the backend upgrade. Stored numeric settings migrate to rule flags without enabling agentic YOLO; goals, sleep, and explicit answer settings remain intact.

## Fixed

- Required free text, prompted choices, and yes/no decisions retain their typed values and validation. Missing answers are distinct from `false`; failed or uncertain evaluations do not invent placeholder answers or default approvals.
- Unsupported structured-decision routes, refusal, invalid output, timeout, and uncertainty expose an actionable human review instead of a generic waiting message. Explicit denials remain enforced, and queued work does not replace a pending human decision.
- Keep automation indicators clear of phone composer actions. Goal progress stays inside the Goal control without moving the editor or action buttons.

Stable `0.10.19` artifacts and notes are separate from the `0.11.0-beta.2` migration line.
