# YCoding v0.7.14

## Added

- Install the remote workspace as an app from **Settings → App**. In Chrome and Edge, **Install App** opens the browser's install dialog when the browser offers one; on iPhone, iPad, and Safari on Mac, it shows the steps to add YCoding to your Home Screen or Dock. **App** also shows whether you are using the browser or the installed app.
- Keep your prompts across a reload or reconnect of the remote workspace. A steer that YCoding has accepted but not started shows **Processing**, and a queued prompt shows **Queued**, until YCoding picks it up. A send that failed or has an unknown outcome stays on its message with **Retry send**, and sent, failed, and unknown outcomes also appear as dismissible toasts.

## Changed

- YCoding is licensed under the GNU Affero General Public License, version 3 only (AGPL-3.0-only), starting with this release; the same license applies to its npm packages. Earlier releases keep the MIT License they were published under. The MIT notice of OpenCode, which YCoding is derived from, is kept in `NOTICE`. Release archives and the CLI, AI, and client npm packages include the `LICENSE` and `NOTICE` files; the installer requires them in each archive but does not install them.
- Notification settings have three categories, each with **In app** and **System** switches: **Work finished**, **Needs your attention**, and **Machine offline**. **Work finished** waits until the whole Session family is done, including subagents, background shells, and goals, and alerts read "YCoding — work finished". **Needs your attention** covers a decision you must make, a guardrail block, and a failed run, and alerts read "YCoding — needs your attention". **Machine offline** alerts appear only while YCoding is open. Settings describes each category in plain language, and **Desktop alerts** is now **System alerts**. Push to this device sends **Work finished** and **Needs your attention**. Your earlier choices for Guardrail block, Error or failure, and Device disconnected are not carried over; **Machine offline** starts enabled.
- Office is one open floor. On tablets and desktops, each visible agent works in its own block with a desk and monitor for editing, a shelf for reading and searching, a test terminal for tests and commands, and a whiteboard for subagent and todo coordination; the entrance and relax area are shared. When an agent's activity changes, it moves to the matching object within its own block right away. Office also fills the available height.
- Show the **Edited files** card in remote Conversation once the Session stops running (idle, interrupted, or failed), as the TUI does; it stays hidden while work continues.
- **Last active** in the **Running and recent** carousel shows when the Session last finished a step or run.
- Built-in agents never make atomic commits: they commit only when the task, one of its phases, or a complete piece of functionality is finished.
- On desktop, the Workspaces list fades at its bottom edge while more workspaces are below; the fade clears at the end of the list.
- Repeat visits to the website and the remote workspace load faster: browsers keep the app's fingerprinted scripts, styles, and images for a year instead of re-checking each one on every load, while pages still pick up a new release on the next visit.

## Fixed

- Let a goal you set from the remote composer finish being set up. The composer shows **Setting goal…** while the goal is prepared, and the request now waits up to five minutes instead of 30 seconds. After a timeout or an unknown outcome, the workspace checks the Session before saying whether the goal is active.
- Limit the composer's retry countdown and **Retrying** status to the assistant step that is retrying. Once that step produces text, reasoning, or tool progress, or finishes, the status shows the Session's current state.
- Keep your machine connected to the remote workspace during busy Sessions. The connector spaces what it sends to stay under the relay's rate limit, so a burst of activity no longer disconnects it with `Agent message rate exceeded`, and a Session's change to stopped is no longer lost when a send fails.
- Keep the running state and **Work finished** alerts current when the machine fails to read Session status: it retries on the same connection, starting after 1 second and backing off to 30 seconds, instead of leaving the last status in place.
- Closing any dialog or sheet in the website and the remote workspace, including docs search, navigation menus, the Sessions and Activity sheets, pickers, the Team sheet's confirmations, device removal confirmations, and the Install App instructions, returns keyboard focus to the button that opened it, even when clicking that button did not focus it.
- In light mode, the landing page no longer shows a green glow behind its opening statement, and composer buttons and pickers have clearer edges. On tall screens, the landing page fills the window without an empty band above the footer.
- On phones, the Team sheet shows one title and one close button, keeps its content away from the screen edges, and places **Load older** after the tasks instead of over them.
- On phones, Settings no longer shows Office options, because Office is available only on tablets and desktops. The notification settings table fits a phone screen without breaking its column headings mid-word.

## Upgrade notes

- Reload the remote workspace, or reopen the installed app, to load the updated browser client.
- Update YCoding on each machine, then open the TUI or run `ycoding service restart` so its background server runs the new version. These features need the updated machine:
  - Restored pending prompts: with an older machine, opening a Session shows "Update the connected device to restore pending prompts." and Processing and Queued rows are not restored after a reload or reconnect.
  - Goal setup: an older machine still stops waiting for goal setup after 30 seconds, so a goal that takes longer can still time out.
  - **Work finished** waiting for the whole Session family, and a failed run raising **Needs your attention** in push alerts: an older machine reports only whether a Session is executing, so **Work finished** can arrive while background shells, queued input, subagent notices, or a goal are still outstanding.
  - The status retry and the connection fix.
  - **Last active**: a machine without the update shows **Last active not reported**. The first start after updating fills in **Last active** for existing Sessions from their Session history.
- The retry status, dialog focus, notification settings, Install App, and Office changes come from the browser client alone.
