All bindings below are now either verified-existing or verified-free.

15 · Subagent economics — correcting myself

I earlier wrote that "a subagent has no independent session economics". That was wrong. Each subagent is its own session with its own model, variant, tokens and cache behavior — entriesFromTasks() carries a per-task model and cache diagnostics are per-session. Spend rolls up to the parent but is also measured on its own. A subagent on a cold prefix can be why the parent's blended hit ratio drops, and you could not see that.

WhereShowsWhy there
Subagent footer18.4K (9%) · 74% hit · $0.41Always visible while attached; matches the reference footer, plus hit ratio.
Economics stripcontext, hit, prefix, reads, writes, spend, roll-up targetFull detail without a rail.
Picker rowSonnet 5 · 68% hit · 4m02sSpot the expensive subagent before attaching.
Parent CONTEXT· subagents $1.24Background spend never invisible in the parent's economics.

The subagent screen still has no rail, per the reference. The economics strip is horizontal instead — a rail would imply the subagent manages its own independent context, when it always reports upward.

19 · Dialogs, state system & toast

Two corrections. First, I drew dialogs as small bordered boxes with uppercase titles — wrong. The real pattern is a full-bleed panel: sentence-case title left with esc right, search line with a block cursor, grouped sections, solid-fill selection across the full width, right-aligned trailing values, bottom hint line. Second, and worse: I rendered every trailing state in the same MUTED grey, so ✓ Connected and ○ Disabled were indistinguishable. §19.2 fixes that globally — it applies to every dialog-*, not just MCP.

19.1 · Panel anatomy

PartSpec
PanelSURFACE #1D2128, no border, dimmed backdrop. Sizes medium 60 / large 88 / xlarge 116 — large is used by 13 dialogs, so it is the default.
Title rowSentence case, bold TEXT, left. esc MUTED, right. Never uppercase.
SearchBlock cursor on the first cell, MUTED placeholder. Present whenever the list can exceed one screen.
Group headerINFO blue, bold, blank line above. From command.group; Suggested pinned first.
RowState gutter · label · MUTED description · right-aligned trailing state or value.
SelectionINFO blue fill, PAGE-colored bold text, full panel width. See §19.2 for why this changed from accent.
Hint lineMUTED, bottom left, only for non-obvious interactions (←/→ change, space toggle).

19.2 · State recognition — global

The old design leaned on one weak cue: a colored glyph inside otherwise-grey text. Three cues now carry state, so it reads at a glance from either edge of the row.

StateGutterColorRow treatmentUsed by
ok · connected · active✓ACCENTnormal label, medium-weight trailingMCP, skills, status, artifacts
off · disabled · inactive○MUTEDentire row dimmed — label recedes tooMCP, skills, models
pending · connecting⋯INFOnormalMCP, providers, subagents
attention · conflict · awaiting!WARNINGlabel also WARNINGskills, subagents, guardrail
error · failed✗DANGERlabel normal, trailing DANGERretry, delete-failed, status
destructive action—DANGERlabel DANGERconfirm, permission, retry

The conflict this resolves

I had selection and success both on ACCENT green — they would compete on every list. Your screenshots use blue selection for exactly this reason. Revised assignment, applied everywhere:

TokenWasNow
INFOnavigation, subagent identity+ cursor / selection fill in every list — selection is navigation
ACCENTidentity, focus, success, selectionagent identity, success state, active mode affordance (composer rule, active tab) — no longer selection

Redundancy also removed: rows previously read agentmemory connected … ✓ Connected — the same fact twice. The description slot now carries something useful (transport, scope, count) and the trailing slot carries state alone.

19.4 · Toast

Built to the real component: absolute, top 1 / right 2, maxWidth min(60, width−6), padding 2×1, overlay background, and left + right borders only via SplitBorder, colored by text.feedback[variant]. Variants are exactly info · success · warning · error; default duration 5000ms.

Same recognition problem as the dialogs: the variant colour appeared only on two 1-cell borders, which is almost invisible at a glance. Fix — a state glyph plus variant word as the title line, in the variant colour, so the toast is identifiable without reading the message.

Runtime concern worth raising

toast.tsx holds a single currentToast slot — a new toast replaces the current one and resets the timer. A burst (three MCP servers failing at once) shows only the last, and errors can be silently overwritten by an unrelated success. That is a runtime behavior, not a design one, so I have not designed a queue around it — but it is worth an implementation task: either queue toasts, or never let a lower-severity toast replace an unread error.
