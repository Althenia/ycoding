# Session Interaction

On macOS 14 or newer, the packaged `ycoding` or `ycoding-node` server mounts the signed native chooser and isolated Chrome approval when `YCoding Interaction.app/Contents/MacOS/ycoding-interaction` is executable beside the server binary. Starting with version 0.12.0, macOS release archives and the Desktop backend bundle ship this app beside the binary. For independent staging, run `bun packages/cli/script/build-interaction-macos.ts '/absolute/staging/path/YCoding Interaction.app'` with the YCoding release signing identity available to `codesign` and match the packaged server's architecture. The launcher verifies the app and its process against the pinned certificate and bundle ID `app.ycoding.interaction` before private native IPC. It accepts no runtime path or trust override.

Paired Chrome enrollment requires the signed macOS helper's local **Connect Chrome** menu and a server listener on `127.0.0.1`. The peer route is unavailable unless the helper starts the menu successfully. Selecting the menu item and completing macOS authentication for that origin authorizes one private enrollment offer. The server sends the one-time code directly to the signed helper; refusal, cancellation, closure, and expiry revoke the unused offer. Neither HTTP nor the browser relay can request a code.

A bound Session can request control of an exact Chrome tab or macOS window. The request is not a grant. Only an authenticated local platform adapter can attest to consent given in its own visible surface. Chrome owned and isolated requests include one credential-free HTTP or HTTPS URL; the adapter binds consent to the canonical URL before it opens a tab. Isolated control requires its own adapter registration and never uses a paired profile as a fallback.

Isolated Chrome's native confirmation authorizes launch only. Action confirmation and irreversible actions return `refused` with reason `unsupported`, without a pending offer or browser dispatch.

The backend verifies the Session, adapter, target, generation and observation revision before it dispatches typed input. Chrome reads, previews and actions apply browser policy to the verified top-level document. The adapter verifies the document origin and sends only the query-free pathname with the native observation. Explicit navigation must match the exact approved URL; it cannot widen a grant to another path. A successful navigation invalidates the previous action revision, and a redirect or an unverifiable document cannot expose content or accept input. One call identity can dispatch at most once in a grant. Actions with irreversible effects require a separate one-use native confirmation for the exact action and revision. Platform permission, policy, sensitive inputs and CAPTCHA refusals still apply. An action with an uncertain outcome is not replayed and the grant is revoked.

Stop revokes the matching generation before adapter cleanup and cancels pending native consent for that generation. Cleanup can remain pending or fail; neither condition reopens the grant. Session movement, archive or deletion, adapter disconnection, target loss and expiry also revoke control.

The local HTTP surface exposes status, a pending request, preview and exact-generation revocation. The relay exposes only Session- and device-owned status, preview and Stop. Active status identifies the target category without revealing native labels or document addresses. Preview is a private PNG or JPEG of at most 960 × 720 pixels and 160 KiB decoded. The image header must match the declared dimensions. Preview is non-cacheable and withheld if capture overlaps a stale target or document transition; there is no whole-screen fallback. Each status transition or applied action emits one live `session.interaction.changed` event with only the Session ID and generation in its data. Clients re-read status on connection and after invalidation, and refresh a preview only while it is visible. The event, grants, consent and previews are not persisted or restored after backend restart. Semantic tool results use normal transcript settlement.
