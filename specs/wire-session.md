# Revision 5 session and interaction operations

`protocol/ycoding/v5/session.proto` defines 84 typed binary WebSocket operations. Its 83 live Protocol endpoints are exactly the baseline endpoint manifest minus the 60 resource operations, 53 platform operations and two platform-owned EXTERNAL upgrades. The only inventory-added operation is `event.unsubscribe`. Together, the three endpoint slices and the two upgrades cover all 198 endpoint declarations without overlap. Connector-only operations, including `session.attachment.upload`, belong to the connector contract and have no operation ID in this file.

Service declarations describe operation descriptors, not gRPC servers. Generated messages and descriptors implement neither dispatch nor authorization. Selected shared operations additionally permit REMOTE_CLIENT and RELAY through the closed [connector allowlist](./wire-connector.md); other operations permit LOCAL_CLIENT only.

## Admission, paging and scope

`session.prompt` and `session.command` return the durable admitted `SessionPending.User` record with DURABLY_ADMITTED settlement. Success means admission, not completed execution or an assistant response. The request's optional message ID, delivery and resume fields retain their live semantics. Other results settle at COMPLETED, including explicit Empty successes. `session.wait` is a read even though its source uses POST. Subscription registration and release are mutations; the log read remains READ.

`session.usageReport` uses OFFSET for the client offset/limit query. `session.list`, `session.snapshot` and `session.subagent.list` use CURSOR for opaque server-issued tokens. All other operations are UNPAGED. In particular, the log's exclusive aggregate `after` sequence and the completion feed's exclusive Session-ID `after` anchor are neither numeric offsets nor opaque server cursors.

Session list, active, outstanding and completion reads use Machine scope. Session creation and Location-owned interaction and generation operations use Location scope. Session form operations use Form scope, retaining the source's form-placement boundary. Other Session operations use Session scope. Event registration and release use Global descriptor scope; the subscribe request carries foundation Scope and accepts only global or authorized Session targets. Scope authorization and backend-derived placement remain dispatcher obligations, not generated codec capabilities.

These are local default scopes. Generated `role_scopes` overrides remote event registration/release to Session scope and remote Session creation to an advertised workspace scope. Remote event request Scope and payload scope identify the same verified Session. Form scopes name verified real Sessions remotely, not the local global sentinel. Every shared descriptor's request/result and ID are canonical for both local and remote callers; remote admission restrictions remain role-specific.

## Event and asset delivery

`event.subscribe` carries foundation `Scope` and preserves any live endpoint params/query. Its Result returns the server-assigned `subscription_id`. It registers an EVENTS stream whose payloads arrive as foundation EventBatch frames, not in the Result. It is unbounded and does not emit StreamEnd. `event.unsubscribe` releases the accepted identity and returns explicit Empty success. Its source contract is the inventory's explicit subscription-release requirement rather than an HttpApi endpoint.

The subscribe descriptor's `event_types` contains only `ycoding.v5.PublicEvent`. `events.proto` defines a 101-member typed oneof matching exactly `EventManifest.ServerDefinitions`: 51 public durable Session events and 50 ephemerals, including the seven Session ephemerals. Durable branches reuse unchanged `SessionLogItemValue1` through `SessionLogItemValue51`; ephemeral envelopes have no durable field. TypeScript `publicEvents` and Rust `PUBLIC_EVENTS` expose diagnostic membership, durability, branch tag and envelope type from the Protobuf field annotations. Ready replaces the connection announcement; `server.connected`, `log.synced`, historical/internal Session facts and broader runtime-only event families are not PublicEvent branches.

`session.log` preserves params, optional `after` and optional `follow`. Its Result returns `subscription_id`; EVENTS frames carry typed `SessionLogItem` records containing `log.synced` and public durable events with sourceEpoch. Historical/internal durable definitions are not added to the public log item union. Release uses `event.unsubscribe` with that identity.

The log descriptor's `event_types` contains only `ycoding.v5.SessionLogItem`. Accepted subscription identities retain this descriptor-specific payload association in the TS and Rust connection machines. PublicEvent cannot carry log.synced; SessionLogItem cannot carry an ephemeral delta. A connection's explicit event payload allowlist is an additional admission bound, not permission to send a log payload on a public subscription.

A finite log stream (`follow=false`) sends foundation `StreamEnd { subscription_id }` after its last EventBatch. Frame body tag 19 carries StreamEnd on the EVENT ledger, server to client only. There is no mid-stream error branch. A close before StreamEnd is incomplete, not successful completion. Structural validators require a nonempty identity and reject duplicate bodies, wrong direction and wrong ledger. The current WireConnection validators track handshake and epoch, not active subscriptions or cross-frame stream lifetime; active-identity matching, exactly-once terminal delivery and rejection of events after termination belong to the subscription owner.

`session.messages` and `session.message` preserve typed projected-message results and use TYPED_BULK above the inline limit. Full copy/export reads retain their canonical full-history contract separately from snapshot paging and loaded-window navigation. `session.attachment.read` uses ASSET_BULK: typed metadata contains MIME and byte length, while raw file content travels through BulkStart/BulkPiece/BulkEnd. Params retain Session ID and attachment digest. Base64 content is not carried in the typed Result.

## Shapes, shared declarations and validation

Requests retain separate params, query and payload messages. Results retain named declaration associations and source envelopes. Optional scalar/message fields use presence; optional collections use wrapper messages so absence and present-empty remain distinct. Nullable clearing and other unions use required oneof selections. Optional Never fields have no valid wire value and are omitted. Nonempty homogeneous arrays retain their count minimum. Unrestricted strings and dynamic keys use LosslessString; deliberately open metadata and instruction values use Value, not JSON text in bytes.

Integers retain signed/nonnegative 64-bit representation and JavaScript safe-integer bounds. Finite numeric fields retain double representation, including the millisecond JSON representation of UTC admission and message timestamps. Structural codecs do not implement domain transformations. Every descriptor includes middleware UnauthorizedError and InvalidRequestError plus endpoint-declared typed errors.

`shared.proto` holds each declaration used across operation files exactly once, retaining package names and frozen tags. Shared platform declarations include Location.Ref, FileDiff.Info, SessionNotFoundError, ConflictError, ForbiddenError, Shell.Info and PTY state with their transitive messages and enums. Existing resource declarations retain their names and bytes. Result-wrapper overrides are explicit and must resolve a live codec-name collision; this contract requires none.

Field constraints enforce structural integer, text-unit and collection bounds. Source-bound domain obligations identify every checked pattern, filter and refinement. Obligations are metadata, not claimed enforcement. Wire-to-domain conversion must validate them before executing a handler and reject through the validation-error boundary.

## Coverage and generation

`packages/protocol/test/session-coverage.test.ts` compares the live endpoint schemas and baseline manifest, checks the exact partition and single inventory addition, and verifies every field/tag/type/presence/enum/error/descriptor association. It calls requireConstraintCoverage for source fields and encoded union branches, verifies live source identities and tests source-order invariance. The codec-name gate includes the complete canonical descriptor set.

The materializer scripts check exact projected source bytes and refuse initialization over an existing file. Protobuf declarations remain canonical; conformance projections must match them without rewriting tags or IDs on source drift. The owning `generate:v5` command reads those declarations and generates codecs, field metadata, descriptors and event membership. Authorized contract corrections must preserve every unaffected tag and operation ID. Canonical files end in exactly one newline.

Generate TypeScript bindings through `bun run --cwd packages/protocol generate:v5` and Rust through the protocol crate's Cargo build. The digest hashes canonical proto source bytes. Generate foundation vectors last with `python3 protocol/ycoding/v5/testdata/generate.py`. Repeated generations must be byte-identical.

`packages/remote/test/session-conformance.test.ts` and `rust/crates/protocol/tests/wire_session.rs` share independent corpora for optional-empty/false presence, lone UTF-16 metadata keys, admission sequences, goal and nullable branches, signed error fields, nonempty Forms and relocated file-diff bytes. The existing resources corpus retains required-undefined none/value cases; no live session-slice result has that shape. StreamEnd and digest-bearing negative rejection reasons are checked in both languages. Conformance excludes domain-obligation enforcement, active-subscription ownership and live execution.
