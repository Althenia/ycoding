# Revision 5 connector and relay notice operations

The revision-5 connector contract maps the closed 79-name source inventory to 75 canonical connector descriptors and four relay-owned notice descriptors. `protocol/ycoding/v5/connector.proto` owns derived operations, raw upload staging, catalog composition and notices in the explicit 5000–5099 range. Shared local operations retain their IDs and use the same typed request and result for remote peers. Service declarations are descriptor metadata, not gRPC servers or an implemented dispatcher.

TypeScript exports `operationIDsByRole`; Rust exports `OPERATION_IDS_BY_ROLE`. REMOTE_CLIENT may originate 79 canonical operations, including the four relay-owned notices. RELAY may forward exactly 75 connector operations. LOCAL_CLIENT may also originate the canonical captured-change, team-economics and family-activity reads specified below. AGENT and SERVER send responses and permitted controls but no operation requests. Every unaffected local operation remains LOCAL_CLIENT-only. The existing `session.prediction` and `session.promptGenerate` remote roles are retained.

Request direction follows `packages/remote/src/index.ts:478–480,645–673`, `infra/cloudflare/src/relay/core.ts:554–613,754–827` and `packages/cli/src/remote-bridge.ts:305–328`. Claimed role never substitutes for authenticated ownership. The local, client and agent routes use the foundation PeerRole vocabulary. Generated allowlists do not authenticate an upgrade or authorize a Session.

Application-protocol failures and timeouts close with 1008 before connection establishment, including a Ready producer waiting for receipt confirmation after Ready handoff. Established failures close with 1002. Bindings use the connection's lifecycle state for adapter-detected failures as well as wire failures. Authentication/authorization revocation retains 4401/4403; reconstruction retains 1012. A transmitted unresolved request settles unknown, without automatic replay.

On an authenticated agent socket, the relay registers a validated scoped canonical epoch advertisement in frame-arrival order before accepting a later successful EVENTS Result. Awaited authorization and forwarding must not delay this connection-local epoch metadata behind the dependent Result. Fresh agent and recipient authority is required before delivery; an absent epoch still reconstructs the affected client with 1012.

## Canonical local family reads

`LOCAL_CLIENT`, `REMOTE_CLIENT` and `RELAY` use the same three descriptors and messages. Only `LOCAL_CLIENT` gains admission; no new operation, PeerRole value, message, field tag, event or error branch is allocated. The descriptors have Session scope, READ mutation, COMPLETED settlement, TYPED_BULK streaming and PRIVATE sensitivity. AGENT and SERVER cannot originate them. The local server authenticates the connection before descriptor admission; a claimed local role alone grants nothing. Remote requests still require authenticated user/device ownership, connector authority and verified Session placement.

Every request carries the target Session ID in `Request.scope.session`, not in its typed payload. Resolve that Session's Location from backend state. Accept no caller-supplied directory or workspace selector. Reject deleted, moved or unavailable placement before reading family data. Captured changes support a root or child Session; economics and activity require a root. Economics accepts the root and its direct managed children (excluding side-chat children); activity accepts direct children, excluding the root in its explicit list, and prepends the root to the result. Reject duplicate or foreign members. Local structural member bounds are 128 IDs, each 1–128 UTF-16 units; remote admission remains at most 15 explicit IDs. Economics requires at least one explicit ID, including the root for a root-only read; activity permits a present-empty list for a root-only read. These are bounded selections, not claims that unrequested members were read. A client requiring complete family economics enumerates the durable subagent inventory, requests every eligible member in bounded batches and includes the root once; resident transcript or Session windows are not the family inventory.

All text below is `LosslessString`; collection messages wrap repeated `items` at tag 1. Request wrappers require `payload` at tag 1. Result wrappers require `data` at tag 1. Optional means absent is distinct from a present-empty wrapper.

## Remote admission obligations on shared descriptors

Apply the connector's closed field validation before dispatch. Resolve every scoped Session's Location from backend state; reject moved, deleted or unavailable placement. Accept workspace targets only from the advertised inventory and revalidate their project. Browser input cannot choose paths, URLs, HTTP methods, trusted ownership IDs or Location headers (`packages/remote/src/index.ts:702–724`; `packages/cli/src/remote-operations.ts:641–704,1655–1725`; `packages/cli/src/remote-local.ts:39–41,235–241,439–455`). Existing ScopeKind and field constraints describe the wire boundary; no descriptor field grants extra placement authority.

`OperationDescriptor.role_scopes` (field 14) overrides the default scope only for its named authenticated role. REMOTE_CLIENT and RELAY use Session scope for event subscribe/unsubscribe and shell output; Session or advertised workspace scope for filesystem search and catalog composition; workspace scope for Session creation; machine scope for provider quota reads; machine or Session scope for the usage forecast. Local default scopes stay unchanged. `event.subscribe` carries the same Session target in its request scope and typed payload; no remote global subscription is valid. Descriptor `event_types` (field 15) associates subscriptions with `PublicEvent` or `SessionLogItem` and the connection enforces that association.

Typed messages use bounded binary bulk delivery; attachments use raw asset bytes. Relay forwarding retains transfer ownership without reassembling content. HTTP body enqueue is not consumption: the connection-owned browser reader acknowledges consumed-through virtual 64 KiB pieces. Preserve exact content length, transfer identity, final-short-piece validation, shared bulk windows, no-consumption deadline, abort/revocation and object-URL release. These delivery contracts do not substitute for Session/content authorization.

`Credit.transfer_id` is optional field 3. With that field present, `ledger` must be BULK and `consumed_through` identifies the cumulative virtual 64 KiB-piece prefix consumed from that live connection's registered HTTP transfer, not a WebSocket delivery ordinal. Grants are bounded by pieces actually handed to HTTP; unknown identities, future prefixes and non-increasing grants fail closed. A transfer-scoped grant never releases a socket ledger or another transfer. Without the field, Credit retains its frame-ledger ordinal semantics. BulkStart declares the admitted request, transfer identity, exact bytes and piece count; Cancel retains its request/transfer selectors. Empty HTTP bodies have zero pieces and need no transfer Credit.

HTTP reads use the existing authenticated message/attachment GET routes with `connectionEpoch`, `requestID` and `transferID` query selectors. Each selector must identify the requesting browser session's live, established connection and its admitted typed read at the exact Session and content ID. The router reconstructs trusted owner/device/browser headers from authentication. The relay admits one HTTP reader for that transfer before releasing any raw body. Response headers carry exact Content-Length, Content-Type, `x-ycoding-connection-epoch` and `x-ycoding-transfer-id`; typed messages use `application/x-protobuf` and assets use their declared MIME.

HTTP bulk responses use identity content encoding and `Cache-Control: no-store, no-transform`. The Worker adapter uses a native FixedLengthStream so the declared Content-Length is retained by workerd. An authenticated HTTP owner may begin its bounded body handoff before the browser releases BulkStart; that permits native header delivery without treating either native handoff or header receipt as consumption. Socket-only delivery still waits for BulkStart consumption before forwarding its pieces.

Relay socket drains sample monotonic time for each prepared frame. Synchronous subscription registration and transport callbacks may advance the Connection before the next frame; the drain samples again instead of reusing the earlier timestamp. Genuine clock regressions remain rejected by the Connection.

The remote client selects HTTP before BulkStart admission and holds the normal BulkStart receipt until its response is bound. Nonempty HTTP bodies then share the connection's negotiated BULK window and relay peer reservation with socket delivery. Each positive piece is 64 KiB except the exact final-short piece. The reader copies native chunks into the already reserved connection assembly and emits transfer-scoped Credits; its final prefix is withheld until exact body length and EOF are verified. Empty reads hold the BulkStart receipt until EOF instead. The relay closes the HTTP body after the validated backend BulkEnd, retaining transfer ownership until those final receipts arrive; only the canonical socket BulkEnd settles the request. Abort, revocation, replacement and the 30-second no-consumption deadline release the read and never replay transmitted work or publish partial success.

ASSET_BULK retains one pending request across nonterminal `Result.asset_metadata` (tag 6) and the correlated raw body. Metadata's MIME, exact byte count and canonical Result type must match the body declaration; exact successful BulkEnd alone settles success. Empty bodies declare zero bytes and pieces. Relay metadata remains opaque, and raw pieces forward without endpoint reassembly. The [connection ownership contract](../packages/protocol/src/v5/connection/README.md) defines reservation and downstream-consumption lifetimes.

The AGENT connection accepts each authenticated client's complete `SubscriptionSnapshot` through `updateRelayInterests` and derives a bounded, reservation-charged Session union. Register a backend identity with `registerRelayInterest` only after local subscription acceptance. Stale registration reports `relayInterestRejected` without revoking other clients; dispose that local observer. `releaseRelayClient` releases an identity only when its last client leaves. Accepted subscription IDs, source epochs and snapshot ownership clear on reconstruction.

The RELAY connection forwards an accepted whole EventBatch with `forwardEventBatch`, preserving its scope, subscription, epoch, IDs, payloads and order. Retain the upstream EVENT receipt and aggregate owner through downstream enqueue and handoff. Release them only after every returned forwarding ticket reports `eventBatchReleased` for consumption or teardown. One client's cancellation releases its queued output without changing another client's interests, handed consumption fences or transfers. Each downstream connection retains independent fair scheduling, credit and no-consumption deadlines.
