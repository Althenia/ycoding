# Revision-5 sans-IO connection

Import `Connection`, `defaultBudgets`, and `ReservationBudget` from `@ycoding-ai/protocol/v5/connection`. Supply authenticated local and peer roles, the generated operation table, an explicit generated public-event payload type list, and monotonic caller time in milliseconds. Supply a fresh connection epoch and the process source epoch on the Ready-producing endpoint. The connection owns no sockets, timers, authentication cache, durable store, upload manager, HTTP streams, or shared relay manager.

## Binding and ownership

- Take the adapter's aggregate application reservation before decode, copy, asynchronous retention, or forwarding. Call `admitIncoming(byteLength)` before decoding the existing native buffer; refuse input when it returns no token and drain `takeDecisions()`. Run the strict generated Frame validator/decoder, then call `acceptIncoming(token, frame, now)`. Call `rejectIncoming(token)` when decoding fails. Tokens belong to one connection and are single-use.
- Call `start(now)` on the Hello producer. The Ready producer automatically queues Ready after a valid Hello. The initiator automatically queues its one receipt-confirming Ping after Ready. Deliver no application frames until this handshake permits them.
- Call `request(operationID, scope, encodedPayload, reserveBytes, now)` for an RPC. Encode the operation-specific payload with its generated codec. Pass a conservative complete-Frame byte reservation, including all headers and worst-case ordinal widths. Call `enqueue(body, reserveBytes, now)` for domain results, controls and bulk frames. Call `enqueueEvent(eventRecord, metadata, now)` for individual events; provide accepted subscription identity, matching scope, source epoch, optional message ID and background priority in metadata. The connection coalesces events and computes encoded batch sizes arithmetically from generated field tags and payload lengths. Transfer ownership of each body and its backing bytes; do not mutate them while queued, prepared, handed, or buffered. Tiny controls are generated only by their live-work and consumption entry points.
- Call `prepareHandoff(now)` to select one eligible record and obtain its final epoch, ledger ordinal and tiny receipt. Encode that Frame with the generated codec, then call `handoff(prepared, exactEncodedByteLength, now)` at the synchronous binding handoff boundary. Process a refused/closed decision before transmitting; transmit an accepted handoff without yielding between the state transition and native delivery. An exact size above the reservation or stale authority fence is terminal. Handoff never consumes delivery. Call `abortPrepared(prepared)` to return a prepared record to its queue; its ordinal is reused. Keep at most one prepared record outstanding.
- Call `consume(ledger, ordinal, now)` only after applying delivery or transferring it to a specifically bounded request, projection, persistence, asset, or downstream-consumption owner. Forwarding or native handoff alone is not consumption. Consumption may occur out of order, but Credit grants only the contiguous prefix and releases the sender's exact recorded byte charges. Credit coalesces at 64 KiB or 25 ms of pending progress. Advance caller time with `advance(now)` to generate warranted credits/heartbeats and enforce deadlines; no method reads a clock.
- Process returned decisions and drain `takeDecisions()` after methods whose return value is a reservation or prepared record. `closed` carries a generated failure category and native close code. Failures before establishment use 1008, including a Ready-producing peer waiting in receipt-confirmation state after Ready handoff; established failures use 1002. The initiator establishes on receiving Ready. Use the generated category name as the fixed ASCII close reason, never payload or exception text. Revocation uses 4401/4403 and reconstruction uses 1012. Construct a new connection after close; never restore an old epoch or replay transmitted work.

`retainedBytes`, `bulkRetainedBytes`, `hydrationBytes`, `ledger(class)`, and `counters` expose application ownership accounting. Queued/prepared charges are conservative reservations; handed charges are exact complete encoded Frame lengths. Input tokens, endpoint reassembly and bounded hydration owners remain charged until released. These counters do not measure native socket buffers, allocator overhead, decoded-object heap size, or whole-process memory. Browser/Cloudflare native receipt can precede application admission; application caps do not prevent that native allocation or prove that send drains it.

## Requests, cancellation, and authority

ASSET_BULK sends `Result.asset_metadata` (outcome tag 6) before BulkStart. Its metadata TypedPayload retains the operation's canonical Result type; its MIME and byte count equal that Result's fields. MIME is an ASCII media type with optional token or quoted parameters, at most 256 characters. Metadata is nonterminal and remains correlated with the pending request. Duplicate metadata, inline asset success, mismatched declarations and a body without metadata fail the protocol. Raw content uses exactly 64 KiB pieces except the last, contiguous zero-based indexes and offsets, and exactly the declared total. An empty asset declares zero bytes and zero pieces and still ends with successful BulkEnd. Typed-message bulk retains its separate codec rules.

`encodeAssetMetadata(schema, typedResult)` builds the validated declaration for `fs.read` or `session.attachment.read`. Metadata delivery emits `assetMetadata`; terminal asset success emits one `settled` success with the validated metadata TypedPayload and one `bulkComplete` with `start`, raw `data`, `metadata` and `result`. The `result` is that same TypedPayload, not a second encoding or a base64 body. Reserve the caller's asset owner before accepting these objects. `releaseBulk` frees both raw-body and retained metadata charges. `assetMetadataRetainedBytes` includes metadata waiting for BulkStart and metadata owned by a completed asset. Cancellation, expiry, authority loss and reconstruction release both owners and settle transmitted work as unknown; a declared BulkEnd error rejects without successful partial data. Relay metadata remains opaque and raw pieces forward without endpoint reassembly.

Outgoing request IDs are per-connection monotonic uint64 decimal strings, independent of durable input IDs. Success/error type, scope, sender role, mutation class and settlement derive from the supplied generated operation descriptor. A Result for a settled allocated ID is a counted late drop; an unparseable/future ID is a protocol failure. Incoming IDs remain arbitrary wire strings: concurrent reuse fails, while lifetime uniqueness after settlement is the peer's obligation. Pending metadata is bounded without tombstones.

Call `acceptIncoming` in binding arrival order and process its `dispatch` and `cancelled` decisions in that order before admitting later frames to the adapter. The machine synchronously preserves validated Request/Cancel order; it stores no admission queue or mutation-lane state. Pending-request or receive-window exhaustion closes with LIMIT rather than silently dropping, deferring or reordering a request. Transfer dispatched input only to a bounded adapter owner before returning consumption credit.

The relay/domain adapter owns ordered authorization and admission: keep mutations in arrival order per Session, or per connection when sessionless; give notice requests one lane per connection. Reads take no admission lane and never wait for another request's authorization. Deliver agent responses immediately, outside admission lanes. A failed admission must not poison later work in its lane. Recheck current authority and placement after awaited authorization/read work; cancellation may stop delivery but never proves mutation rollback.

`cancel(requestID, now)` and `expireRequest(requestID, now)` remove queued-unsent work as `unsent`; unresolved transmitted work settles `unknown` and never replays. A received Cancel emits a `cancelled` decision identifying read versus mutation. Abort reachable request-scoped reads and stop delivery where safe; never infer rollback or interrupt a Session implicitly. `cancelTransfer(transferID, now)` releases a transfer and its slot immediately. Orphan pieces/end are counted late drops, with ordinary ordinal/consumption accounting and no allocation or success. Typed/asset bulk succeeds only after contiguous indexes/offsets, exact chunk/byte totals and validated terminal outcome. Endpoint content stays bounded and charged until `releaseBulk(transferID)`; relay connections emit `bulkForward` without full-message reassembly.

Recheck operation authorization, server-derived Session placement, managed-child input restrictions, pending form/review ownership and sensitive fresh authority in the caller before executing a `dispatch` or applying delivery. `updateAuthority(version, authorized, now, code)` advances the caller's authority fence or revokes the connection. Input reserved under an older fence cannot dispatch. `restart(now)` clears connection ownership and settles transmitted pending work as unknown with code 1012. Authentication/authorization freshness is caller-owned, not derived from Hello's claimed role or scope.

Local Form create/list/get/state/reply/cancel accept the generated `Scope` oneof `target: { case: "globalForm", value: { directory: encodeLossless(directory), workspaceId: encodeLossless(workspaceID) } }`, omitting `workspaceId` when absent. Use `encodeLossless("global")` for params.sessionID. The runtime resolves this recorded Location through the existing Form owner helper without a Session row. Remote roles cannot select globalForm. Real Session forms keep their Form scope and backend-derived placement. See the [Session wire contract](../../../../../specs/wire-session.md) for the complete construction.

## EVENTS and snapshots

Decode a successful EVENTS Result with its generated codec and pass that Result's `subscription_id` and the decoded, authorized request target to `acceptSubscription(requestID, subscriptionID, scope, now, direction)`. Supply the target explicitly. Local `event.subscribe` has a Global outer RPC scope and carries its Session/global target inside the generated request; remote roles require Session outer scope and the same Session payload target. Accept only Session/global targets and match any Session outer scope, including session.log. Use `receive` for inbound event routing and `send` on the producing endpoint after successful Result handoff. The machine retains subscription identity, accepted scope and descriptor event_types; PublicEvent and SessionLogItem are distinct payload contracts. Accept no remote global subscription. Release accepted interest explicitly with `releaseSubscription`; the application owns its typed unsubscribe operation and forwarding-union updates.

RELAY registrations require `acceptSubscription(requestID, subscriptionID, scope, now, direction, canonicalSourceEpoch)` on both receive and send subscriptions. Obtain the epoch from an authenticated backend acceptance or canonical read before registration; never substitute the relay's Ready process epoch or infer it from a batch. Other roles retain their existing default; a remote endpoint can pass the same explicit epoch when its canonical owner already provides it.

An explicit canonical epoch also lets RELAY, or AGENT in the send direction, settle another successful subscription RPC against an already registered identical scope/identity/epoch/event-type owner. This clears that RPC's bounded awaiting metadata without replacing the shared observer or dropping its queued events. Calls without an explicit epoch retain duplicate-identity rejection. AGENT can register its union owner first with `registerRelayInterest`, hand the successful RPC Result, then complete its request association with this explicit registration.

Call `beginHydration(subscriptionID)` before the canonical snapshot read. Buffer batches without choosing a source epoch during the read. This bounded owner can return event credit while its byte/count reservations remain retained. After the canonical read returns, call `completeHydration(subscriptionID, canonicalSourceEpoch, now)` with its required source epoch. Install only that argument, never Ready or an EventBatch as a stand-in. Transfer matching buffered batches in order and emit `resync` for other epochs; later mismatched batches also resync. Reserve the caller's projection/hydration storage before accepting those decisions; returned objects remain caller-owned after this boundary. Overflow invalidates the hydration, clears buffered ownership, emits `resync` and requires a fresh hydration. Typed ResyncRequired carries scope/source/message identity and invalidates matching buffers. Completing an unknown subscription is a caller error.

The application owns subscribe-before-snapshot sequencing, newest-100/paging/compaction rules, aggregate and source-epoch validation, exact watermark discard, the task-update exception, gap reload, live-text merge and canonical reconciliation. Transport state never resumes provider work. Supply PublicEvent and SessionLogItem as the explicit connection-level payload allowlist; subscription-specific event_types narrows it further. The generated publicEvents catalog records exact membership and durability. Scheduling fixtures deliberately replace descriptor event_types with their named test-only codec list; contract-flow tests retain the canonical associations.

One event above the complete-batch cap produces a counted, bounded normal-ledger ResyncRequired from caller-supplied metadata, not a split or payload-derived marker. Earlier accepted events flush and must be consumed before their scoped invalidation is handed; this dependency uses subscription/Session identity and event-ledger consumption, not guessed cross-channel arrival order. Later events continue through ordinary coalescing. Failure to admit the bounded invalidation closes the recipient with LIMIT.

The generated StreamEnd Frame completes an active finite subscription on the event ledger and releases its resources. Flush earlier coalesced batches before producing StreamEnd; do not hand it ahead of a queued or unconsumed scoped ResyncRequired. Reject unknown, ended or wrong-direction StreamEnd frames as protocol failures. Hydration and unresolved resync block successful finite completion; only a successful canonical hydration resolves the resync fence. Absence of StreamEnd before close is incomplete, never success. Releasing a producing subscription removes both its queued batches and queued/prepared StreamEnd.

## Relay interest and forwarding ownership

On AGENT↔RELAY, transfer each authenticated client's complete immutable `SubscriptionSnapshot` to `updateRelayInterests(snapshot, now)`. It returns added and removed Session IDs from the union. Client and Session counts and snapshot bytes are bounded and reservation-charged. `releaseRelayClient(clientID, now)` removes only that client's membership. Subscribe at the local backend before calling `registerRelayInterest(sessionID, acceptedSubscriptionID, backendSourceEpoch, now)`; `relayInterestRejected` reports stale or duplicate registration without closing unrelated interests. `relaySubscriptionID(sessionID)` exposes the accepted forwarding identity. Release the backend observer when the last client leaves or registration fails. Repeated clients share one identity; losing one client does not revoke another. Reconstruction clears snapshots and accepted identities.

On RELAY→REMOTE_CLIENT, `forwardEventBatch(batch, now)` reserves and queues a complete accepted batch without rewriting identity, scope, source epoch, event IDs, order or payload bytes. Its returned ticket belongs to that connection. EVENT accounting remains held through handoff until downstream cumulative consumption. `eventBatchReleased { ticket, consumed }` reports consumption or queued/connection teardown; drain `takeDecisions()` for queued removal. Hold the upstream receipt and aggregate reservation until every downstream ticket has released, then consume upstream. Never acknowledge upstream on enqueue or native handoff alone. Forwarding accepts only registered subscription identity and source epoch, and obeys the same fair scheduling, per-peer/event budgets and 30-second no-consumption deadline as locally produced batches.

StreamEnd senders are exactly SERVER, AGENT and RELAY. RELAY reception releases the accepted identity but leaves its event-ledger receipt unconsumed; forward completion behind prior responsibility and consume only after downstream release. Endpoint roles retain applied-completion consumption.

## HTTP bulk ownership

`Credit.transfer_id` (field 3) selects a connection-owned HTTP transfer and requires BULK. Its consumed-through value is a cumulative virtual-piece prefix, bounded by actual HTTP handoff, not a frame ordinal. Unknown transfers, future prefixes and non-increasing grants close the connection without granting credit to socket delivery. Credits without transfer identity retain their frame-ledger meaning. Raw HTTP bytes share the negotiated BULK window, aggregate reservation and relay peer cap; each handed piece retains its exact byte charge until its transfer Credit or teardown. The oldest unconsumed HTTP piece enforces the same 30-second deadline as socket delivery.

Call `expectHttpBulk(requestID)` on a remote client before BulkStart arrives. It retains bounded assembly ownership and emits `httpBulkStart` instead of consuming that normal frame. Bind a verified same-connection HTTP response with `beginHttpBody(transferID, connectionEpoch, now)`. A nonempty body releases the BulkStart receipt only after binding; an empty body retains it until EOF. `receiveHttpPiece(transferID, bytes, now)` validates fixed 64 KiB virtual pieces and the exact final-short piece, copies into the reserved assembly, and generates intermediate transfer Credits. After verifying exact length and EOF, call `completeHttpBody`; it emits the final prefix, or releases the empty body's BulkStart receipt. Canonical BulkEnd remains the only success boundary. A socket BulkPiece for an HTTP-selected transfer is a protocol failure.

On the relay, call `attachHttpBulk` only for a handed, unconsumed BulkStart on the authenticated browser connection. `handoffHttpPiece` validates transfer index, byte offset and exact piece size before reserving its native handoff charge. A full shared window returns `accepted: false` without changing ownership; await real credit rather than replaying handed bytes. Perform the synchronous HTTP enqueue only after accepted handoff. `httpBulkReleased` reports the exact cumulative prefix released by receipt or teardown; retain upstream frame responsibility until it reports release. Close the HTTP body after the validated backend terminal so the reader can verify EOF, but queue socket BulkEnd only after `httpBulkConsumed` confirms the delivered prefix. Cancellation, authority loss and close refund only that connection's HTTP owners.

## Limits and scheduling

Frame caps, handshake message/reservation caps, and the handshake deadline are fixed generated revision-5 constants and cannot be overridden. Hello proposes receive windows; Ready fixes values no higher than either endpoint's configured proposal or the canonical maxima. An over-cap proposal fails instead of being clamped. Other enforced per-connection budgets use `defaultBudgets` and explicit configuration. No shared-DO, HTTP-stream or attachment budget is defined by this module; connector snapshot ownership enforces the generated relay client and subscription counts.

Schedule bounded tiny flow first, then normal RPC/control; rotate Sessions for events and transfers for bulk at two event batches per bulk piece when both wait. Preserve Session/transfer order, including BulkEnd after its queued pieces. Keep one open batch per Session/subscription. Merge within the 40 ms interactive / 750 ms background interval; later interactive work shortens an open background wait. Flush at expiry, count/byte limits, source change or finite subscription end. Reserve the maximum uint64 widths of delivery ordinal and tiny receipt before final fair handoff; the complete Frame remains within 256 KiB at every ordinal magnitude. Each ledger's oldest handed record has its own 30-second consumption deadline; unrelated Pong or another recipient cannot refund or extend that responsibility.
