# Desktop design

## Overview

The native Electrobun WebView opens the Session workspace immediately and connects in the background to the saved backend or the shared local `ycoding` background server. The workspace follows a flat Ledger layout: a 256px navigation rail with status-filtered Session rows grouped by workspace, a conversation thread, one unified composer card, a 400px Session companion with text-only tabs, a command palette with TUI parity, management dialogs and a Workspaces destination with a searchable workspace list and a `FILES` directory explorer, and an open single-column Ledger Settings page that owns `Machine & Backend` and `Updates`. The renderer uses the Review Home product tokens and Geist faces. The operating system owns the native titlebar and window controls.

Every control maps to a method the desktop bridge exposes: connection, Session and repository reads, captured file changes, activity, Projects, Usage, model selection, prompts, pending requests and listeners. A capability the bridge lacks is absent or stated as unavailable, never simulated. The desktop and web entries use the shared workspace, conversation, composer and companion compositions.

## Principles

- Open the workspace at launch and connect automatically; show skeletons while connecting and an inline alert with Retry and Open Settings only when the connection fails.
- State ownership in words: a private backend stops with the window; the shared background server keeps running.
- Keep one open tonal hierarchy: `--yc-surface` rail and companion planes flank the `--yc-bg` conversation canvas, separated by 1px hairlines without nested boxed slabs or heavy shadows on stationary panes.
- Inherit the web token roles and Geist faces. Use the approved Review Home semantic category colors for context breakdowns in light and dark themes; follow the root open-hierarchy rule (`../../DESIGN.md` R12).
- Never show unconfirmed work as done: a draft keeps its text and identity until the backend confirms it.
- Show unknown as unknown: unreported status or context is stated as unavailable, never as zero or idle.
- Use the whole window: the conversation column and every destination page grow with the window instead of leaving empty gutters.
- Keep one grid: every stream block shares one column edge and one 14px radius.
- Keep motion honest: running work shows an indeterminate bar and loading shows skeletons, never bare "Loading" text or a frozen state.
- Format every number with the shared count, compact, percent and duration rules; a provider quota is always shown inside its own card.

## Running work

The Session companion Running tab lists only subagents in the running state and attributed shells in the running state. Lifecycle events invalidate its activity read. Waiting, supervising, starting, cancelling and terminal tasks remain outside this view. Paged results disclose that more running work may exist and offer Load more subagents; unattributed shells are excluded. Shell selection opens its output in Activity.

## Accessibility

Keep browser magnification enabled in the native renderer; do not copy the installed-PWA zoom lock. The transcript is a labelled ordered list with a separate polite status for finished responses; the rail is a navigation landmark and the main column is the page's main landmark. The palette is a modal dialog that contains focus. Follow the system light/dark preference with the existing token themes by default; the command palette can pin the window to any of the seven explicit themes and restore following the system. Motion is limited to state feedback and overlay entry and exit; the prefers-reduced-motion media query and the app animation preference disable it. Forced colors retains system indicators/boundaries and marks the current row and active option with an outline. Verify keyboard operation, long endpoint/title wrapping, pending/failure, 200% zoom and narrow native content without horizontal overflow. A stylesheet/source pass does not replace a native-window render check.

## Bridge gaps

The bridge supplies captured changes, scoped subagent and shell activity, Projects and Usage reads, workspace directory browsing and creation, Session management, workspace file attachments, guardrail and Family Review decisions, provider connection, MCP management and VCS diffs. It has no bulk pending or persisted run-status read, agent catalog choice or decision grades. Plugins are listed only: the protocol exposes `plugin.list`, so activating, deactivating or adding a plugin requires editing the `plugin` entry in `ycoding.json`, and the Plugins dialog states that discovery is read-only and that changes are configured in `ycoding.json` followed by a backend restart, instead of offering those actions. A standalone question that is not part of a form has no reply method; the Session says the desktop app cannot answer it and points to the terminal or the web app. The desktop UI shows none of these gaps as working until the bridge provides them.

The transcript renders reported reasoning, tools, shell output, compaction and existing attachment names. Captured file changes are shown as a Session-level summary, not attributed to a turn. The Changes tab selects a file and renders its unified patch. Activity shows Session-attributed shells and subagent tasks with their reported details. Context identifies its transcript list as retained messages, not active provider context. Session status filters use live events and label unobserved status as unknown. The new-chat context row reports the repository's default model when available; the server selects the model and effort for standalone chats.
