# Decisions and risks

## Approved user requirements

Keep the Godot full desktop client and existing YCoding backend. Use normal prompts. Automatically depict real runtime work; fine-grained pixel-office fidelity matters. Retain speech bubbles and source-linked history. Local HTTP is acceptable. Repair the existing product, settings and actual providers; no production demo substitution. Preserve TUI behavior and good existing work.

## Proposed engineering targets — confirm through local evidence

264 logical-unit default sidebar, 56-unit compact rail, 840-unit max composer and 1000-unit compact breakpoint; see UI spec. These are an initial coherent sizing system, not immutable copied measurements. One shell-scale owner; independent office camera. Use existing layout/rendering seams before introducing SubViewport restructuring.

## Reconsider only with evidence

A large refactor: document why the existing boundaries cause the verified defect. A new settings category: show the actual runtime capability. A provider-specific control: show the supported parameter contract. Asset replacement: demonstrate that retained assets cannot meet quality. A feature deferral: show source/requirement, workaround and actual user approval. A service auth redesign: concrete failure/need, not theoretical scope expansion.

## Main risks

Unverified local drift; duplicated scale ownership; GUI versus shell configuration; selection state not reaching requests; streaming admission/settlement confusion; demo fallbacks hiding failures; unsafe approval shortcuts; event/snapshot race and duplicate prompts; role versus session actor identity; visual review skipped after build passes. Each is a hypothesis until reproduced.

## Expanded desktop decisions

One visible office per resolved project/folder location; other YCoding sessions keep running. User avatar is local presentation with central input-focus gating, not an AI agent. Sessions/Statistics/Settings are rich routes while Office stays primary. All settings are classified from live sources and verified through their owner; initial catalog has 236 entries/patterns, not 236 proven working controls. Provider quota/usage/estimates/advisory budgets remain separate. A new hard-budget enforcement system is not required unless separately approved. Extend the existing release/website pipeline with guarded source-aware changes; no competing publisher.
