# Implementation workplan

Audit -> reproduce -> smallest coherent repair -> targeted tests -> native operation -> visual comparison -> evidence -> reconcile tracking. Do not stop after auditing. Preserve unrelated edits; no stage/commit/reset/branch switch without explicit authorization.

Read the original REQUEST and latest ADDENDUM first. Current code, Schema/Protocol and tests determine how to implement; latest user requirements determine what acceptable behavior means. Update old tests/docs that enshrine the rejected floating layout or production demo boot. Do not rewrite working subsystems to satisfy a plan.

R0 establishes the baseline. R1 proves real coding. R2 fixes the shell. R3 covers all settings. R4 delivers fidelity and player movement. R5 isolates multi-project work. R6 closes conversation/TUI parity. R7 adds statistics/quotas and honest budgets. R8 verifies recovery and quality. R9 prepares builds/installers. R10 extends the existing GitHub Release/Pages chain. Exact objectives, dependencies and acceptance are in MILESTONES.md and tracking/tasks.json.

Work on UI or packaging independently when real-provider credentials block one test; do not use that blockage to invent success. Hard-budget enforcement, asset licenses, platform smoke and signatures are explicit gaps until completed. Required settings cannot be silently deferred behind “advanced”.

End each local session by updating tasks/evidence and HANDOFF. Record source revision, dirty state, command/cwd/exit, screenshots/video, real vs fixture source and unresolved defects. Regenerate TRACKING/TODO, run pack validation. Read the code again when the checkout changes, rather than blindly applying this snapshot's patches.
