# Completion checklist

All items start unchecked. They are gates, not claims.

- [ ] R0 — Reproduce the current app, TUI baseline and reported failures before trusting old completions.
- [ ] R1 — An ordinary desktop prompt completes through the actual configured provider, or fails honestly.
- [ ] R2 — Sidebar, office, composer and rich pages resize as one coherent app.
- [ ] R3 — Every live setting/action has an explicit treatment and required controls work end-to-end.
- [ ] R4 — A polished, truthful office with a user-controlled avatar.
- [ ] R5 — Independent locations, drafts and active work coexist safely.
- [ ] R6 — Inspect and control real work in rich desktop views.
- [ ] R7 — Useful rich analytics without inventing balances or miscounting usage.
- [ ] R8 — The repaired flows survive real failures and ongoing work.
- [ ] R9 — Repeatable verified CLI + Office candidates on supported hosts.
- [ ] R10 — Existing release pipeline publishes real artifacts and the existing website links them.

- [ ] Every current runtime/TUI setting and action has a reviewed disposition; required controls are actually wired.
- [ ] No production startup, reconnect or provider-error path enters synthetic replay.
- [ ] Multiple project requests/drafts/history/models/attention remain correctly scoped.
- [ ] User can walk, interact and type without movement conflicts.
- [ ] Statistics distinguish observed usage, estimates, quotas and local budgets; unknown is not zero.
- [ ] Native visual review, real-provider evidence, and release/install evidence are separate and present.
- [ ] No copied reference assets, font binaries, keys or raw private logs ship in production artifacts or Pages.
- [ ] Existing TUI and CLI release behavior is preserved; GitHub credentials never reach pull-request jobs.
- [ ] All unresolved required gaps remain open in tracking; no fabricated completion.
