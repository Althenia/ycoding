# Desktop information architecture

Use a persistent app sidebar and a route owner in the current Godot composition root. **Office** remains the default spatial work surface. **Sessions** provides full-width rich transcripts and history when the user asks for detail; **Statistics** has room for charts and tables; **Settings** uses a large dialog/page with its own grouped navigation. Navigating to these pages does not stop the service, cancel work or change the prompt target. Returning to Office restores camera, player and selection, without replaying old bubbles.

Global sidebar: New session; Office; Sessions; Statistics; project/folder list with activity/attention; bottom Settings, Help/About, service state. Use clean native-style type and spacing in shell/screens; pixel art belongs to the world. No permanent opaque right inspector. Contextual drawers keep the Office visible; full detail opens explicitly as Sessions. Critical approval banners remain accessible on every route, with project/family identity.

Settings grouping mirrors the supplied OpenCode references: Application (General, Appearance, Keybindings, Notifications, Office); Workspace (Projects/Folders); Connections (Providers, Models, MCP, Browser/Computer); Runtime (Agents, Skills, Commands, Permissions/Guardrails, Context/Efficiency, Tools, Integrations); Administration (Usage/Budgets, Updates, Data/Diagnostics, Advanced configuration). Groups can collapse; a search box finds every registered setting. Do not show every advanced child in the left nav. Category names are YCoding's, not copied external product branding.

Route state must not leak secrets into logs or deep links. Preserve unsent draft when navigating. Settings dirty state prompts Save/Discard/Cancel; Escape must not discard silently. Model/provider sheets support search, keyboard selection, connected/available/error states and capability-driven controls; a successful save requires effective readback. See ALL_SETTINGS.md and SETTINGS_CATALOG.md.
