# Agent guide — repair kit scope

This guide applies to this handoff folder. It does not replace the target repository's root or package guides. Read those first when working in `/Users/viadz/Workspace/Project/ycoding`.

## Product contract

Keep the actual Godot client and existing YCoding service. The user types ordinary prompts, as in the TUI. The service decides work; deterministic office presentation depicts actual events. No office LLM, second provider executor, Electron migration, mandatory IPC proxy, or new infrastructure without a verified need.

The explicit latest request is **repair and complete the existing desktop**, including visual fidelity, settings and real configured-provider operation. It is not permission to delete working TUI features or reset the repository to an older plan.

## Required workflow

Inspect → run → compare → document evidence → smallest coherent repair → run → verify → visually compare → regressions → update handoff. Do not stop at inventory or a design document. Do not perform a large rewrite without demonstrated architectural need.

Distinguish facts from hypotheses: `observed_in_supplied_image`, `reported_by_user`, `verified_in_checkout`, `verified_at_runtime`, `proposed_target`, `unknown`. Source appearance is not runtime proof.

## Preserve existing work

Read `git status` before editing. Preserve staged, unstaged and untracked work. Never reset, clean, stash, discard, stage, commit, push, or replace root instructions unless explicitly authorized. An obsolete TUI-only policy needs a narrow documented reconciliation with the user's explicit desktop request; do not bypass unrelated guardrails. See [templates/ROOT_AGENTS_MERGE.md](templates/ROOT_AGENTS_MERGE.md).

Read before modifying a file. When Secure files is used, pass the latest returned whole-file hash to each update. Do not repeatedly retry a permission restriction or use another connector to evade it.

## Truthful runtime

No synthetic response, fake conversation, fake worker or fake success in production. Legitimate fixtures stay isolated to tests/dev tooling. An unavailable service/provider must show an honest actionable error while preserving input. Never translate disconnection into successful completion or idle certainty.

Bubbles use actual delegation/message/report text or clearly labelled state, not invented acknowledgments. History comes from the existing canonical session and orchestration records; UI animation is never a durable work authority. Do not expose hidden model reasoning as conversation content.

## Security without scope inflation

Local HTTP remains acceptable. Reuse existing authentication, permission ceilings and guardrails. Provider keys stay with the established service credential/config path. Do not log environment dumps, headers, tokens, request bodies, transcript secrets or raw provider errors. Do not weaken permissions to make the test pass. A screenshot of an access toggle is not authority to invent a new full-access mode.

## Verification and completion

Tests must exercise production implementation, not a copy of it. Run package-owning checks discovered in the checkout; never assume a root test command is valid. Record exact command, cwd, exit code, time, source revision/dirty state and output location. Redact before sharing evidence. Headless import is not GUI validation; fixture replay is not real-provider proof; successful prompt admission is not successful generation.

A task may become `done` only with passing, non-synthetic evidence of its required kinds. Gate `done` additionally requires all milestone tasks and dependency gates complete. Record user visual approval at the visual/final gates. Missing credentials or unavailable native rendering are **blocked verification**, never a pass.

At every handoff update task JSON, evidence, parity/gap matrices, provider and mock audits, known issues and next exact action. Do not hand-edit generated progress files. Finish with Current state / Decision / Next milestone / Main risk / Verification and a brief TL;DR.

## Latest scope additions

Read references/ADDENDUM.md. Include all current settings via ALL_SETTINGS and the source-coverage gate; independent projects/folders; the user-controlled avatar with central focus gating; multipage Sessions/Statistics; truthful quota/limits; and existing build/install/Release/Pages evolution. A UI focus handler alone does not block polled movement keys. Do not add multi-user infrastructure, an unrelated cross-client history scanner, or unrequested hard-budget enforcement. Retain unknown/not-reported values and capability-driven settings. Native and release evidence remain distinct from these utility tests.
